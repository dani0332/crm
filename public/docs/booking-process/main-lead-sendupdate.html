📋 Main Lead & Send Update Processing

Comprehensive guide to initial policy booking and endorsement processing in Sage 300

🎯 Overview

The Main Lead and Send Update processing system handles two distinct but related workflows in the Sage 300 integration: Main Lead represents the initial policy booking, while Send Update handles policy modifications, endorsements, and changes after the initial booking. Both processes follow similar Sage integration patterns but with different entry types and handling logic.

💡 Core Concepts

Main Lead: The original policy booking - creates customer, prepayment receipts, AR/AP invoices, and applies payments.
Send Update: Policy modifications after booking - handles endorsements with STRAIGHT, REVERSAL, or CORRECTION entry types.
Both processes integrate with the complete Sage 300 financial workflow including receipts, invoices, and payment applications.

🔧 Key Differences

  • Main Lead: Always uses STRAIGHT entry type
  • Send Update: Can use STRAIGHT, REVERSAL, or CORRECTION
  • Main Lead: Creates new customer if not exists
  • Send Update: Uses existing customer
  • Main Lead: Uses quote code for payment tracking
  • Send Update: Uses send_update_log_id for tracking

🗄️ Database Tracking

  • Main Lead: Tracked via quotes table and quote_status_id
  • Send Update: Tracked via send_update_logs table
  • Payments: Both use payments and payment_splits tables
  • Sage Processes: Both use sage_processes for queue management
  • API Logs: Both logged in sage_api_logs table

📋 Process Types

📝

Main Lead Booking

Initial policy creation and booking on Sage 300. Creates customer, prepayment receipts, invoices (AR/AP), and applies payments. Entry type is always STRAIGHT. Quote status transitions from draft through to PolicyActive.

🔄

Send Update - STRAIGHT

Simple policy modifications that increase premium or add coverage. Creates additional invoices and payments. Used for upgrades, coverage additions, or premium increases without reversing existing transactions.

↩️

Send Update - REVERSAL

Reverses the original booking entries and creates new correction entries. Used for significant policy changes that require complete reversal of original financial transactions before creating corrected entries.

✏️

Send Update - CORRECTION

Corrects specific errors or makes adjustments without full reversal. Creates adjustment entries to fix discrepancies. Used for minor corrections that don't require complete transaction reversal.

📝 postBookPolicyToSage() - Main Lead Booking

Main orchestrator function for initial policy booking on Sage 300.

public function postBookPolicyToSage($sageRequestDataArray)
{
    [$sageRequest, $quote, $payment, $paymentSplits] = $sageRequestDataArray;

    LoggerService::startQuoteLogging($quote, LoggerFeatureEnum::SAGE_POLICY_BOOKING);
    LoggerService::info(self::class.' fn: '.__FUNCTION__.' - Sage Booking - Quote Code: '.$quote->code.' - Policy Booking started');

    // Step 1: Verify or create customer
    $sageRequest->customerId = $this->verifySageCustomer($quote->customer_id, $data, $quote, 15);

    // Step 2: Create AR prepayment receipts for paid splits
    $createARPrepaymentPremiumReceiptsResponse = $this->createARPrepaymentPremiumReceipts($sageRequestDataArray);
    if (!$createARPrepaymentPremiumReceiptsResponse['status']) {
        return $createARPrepaymentPremiumReceiptsResponse;
    }

    // Step 3: Create AP prepayment receipts (currently commented out)
    // $createAPPrepaymentPremiumReceiptsResponse = $this->createAPPrepaymentPremiumReceipts($sageRequestDataArray);

    // Step 4: Create AR invoices (premium and commission)
    $createARInvoicePremAndCommResponse = $this->createARInvoicePremAndComm($sageRequestDataArray);
    if (!$createARInvoicePremAndCommResponse['status']) {
        return $createARInvoicePremAndCommResponse;
    }

    // Step 5: Create AP premium invoice
    $createAPInvoicePremResponse = $this->createAPInvoicePrem($sageRequestDataArray);
    if (!$createAPInvoicePremAndCommResponse['status']) {
        return $createAPInvoicePremResponse;
    }

    // Step 6: Apply AR payments to invoices
    $applyPaymentARInvoicesResponse = $this->applyPaymentARInvoices($sageRequestDataArray);
    if (!$applyPaymentARInvoicesResponse['status']) {
        return $applyPaymentARInvoicesResponse;
    }

    // Step 7: Handle embedded products if eligible
    if ($isLobAllowedForEmbeddedProductBooking && $sukoonEPTransaction && $isTapPaymentGateway) {
        $embeddedProductSageBookingResponse = (new SageApiEmbeddedProductService)->bookEmbeddedProductOnSage([
            $quote, $sageRequest, $sukoonEPTransaction
        ]);
    }

    LoggerService::info(self::class.' fn: '.__FUNCTION__.' - Sage Booking - Policy Booked for: '.$quote->code);
    return ['status' => true, 'message' => 'Policy booked successfully'];
}

🔄 bookEndorsementOnSage() - Send Update Processing

Handles endorsements and policy modifications with different entry types.

public function bookEndorsementOnSage($sageRequestDataArray)
{
    [$sageRequest, $sendUpdateLog, $payment, $paymentSplits] = $sageRequestDataArray;

    LoggerService::startQuoteLogging($sendUpdateLog, LoggerFeatureEnum::SAGE_ENDORSEMENT_BOOKING);
    LoggerService::info(self::class.' fn: '.__FUNCTION__.' - Endorsement Booking - Send Update ID: '.$sendUpdateLog->id);

    // Determine entry type based on send update type
    $entryType = $this->getEndorsementEntryType($sendUpdateLog);
    $sageRequest->entry_type = $entryType;

    // Get existing customer (no customer creation for endorsements)
    $quote = $sendUpdateLog->quote;
    $sageRequest->customerId = $this->getSageCustomerNumber($quote);

    if ($entryType == SageEnum::SCT_STRAIGHT) {
        // Straight endorsement - additional premium

        // Create AR prepayment receipt
        $createARPrepaymentResponse = $this->createARPrepaymentPremiumReceipts($sageRequestDataArray);
        if (!$createARPrepaymentResponse['status']) {
            return $createARPrepaymentResponse;
        }

        // Create AR/AP invoices with STRAIGHT entry type
        $createARInvoiceResponse = $this->createARInvoicePremAndComm($sageRequestDataArray);
        if (!$createARInvoiceResponse['status']) {
            return $createARInvoiceResponse;
        }

        $createAPInvoiceResponse = $this->createAPInvoicePrem($sageRequestDataArray);
        if (!$createAPInvoiceResponse['status']) {
            return $createAPInvoiceResponse;
        }

        // Apply payment to new invoices
        $applyPaymentResponse = $this->applyPaymentARInvoices($sageRequestDataArray);
        if (!$applyPaymentResponse['status']) {
            return $applyPaymentResponse;
        }

    } elseif ($entryType == SageEnum::SCT_REVERSAL) {
        // Reversal endorsement - reverse original and create correction

        // Step 1: Create reversal invoices
        $sageRequest->entry_type = SageEnum::SCT_REVERSAL;
        $createReversalARResponse = $this->createARInvoicePremAndComm($sageRequestDataArray);
        $createReversalAPResponse = $this->createAPInvoicePrem($sageRequestDataArray);

        // Step 2: Create correction invoices
        $sageRequest->entry_type = SageEnum::SCT_CORRECTION;
        $createCorrectionARResponse = $this->createARInvoicePremAndComm($sageRequestDataArray);
        $createCorrectionAPResponse = $this->createAPInvoicePrem($sageRequestDataArray);

        // Step 3: Handle payments for corrections
        $applyPaymentResponse = $this->applyPaymentARInvoices($sageRequestDataArray);
    }

    LoggerService::info(self::class.' fn: '.__FUNCTION__.' - Endorsement Booked for Send Update ID: '.$sendUpdateLog->id);
    return ['status' => true, 'message' => 'Endorsement booked successfully'];
}

🔑 Key Differentiator: send_update_log_id

Main Lead Payments: send_update_log_id is NULL
Send Update Payments: send_update_log_id is NOT NULL and links to send_update_logs table
This distinction is critical for payment routing, status tracking, and Sage process management.

🔧 Integration Points & Job Queue

📞 Main Lead Job Processing

BookPolicyOnSageJob

  • Trigger: Scheduled via scheduleSageProcesses()
  • Model: Quote models (CarQuote, HealthQuote, etc.)
  • Middleware: WithoutOverlapping with quote code lock
  • Timeout: 80 seconds
  • Retries: 1 attempt only
  • Entry Type: Always STRAIGHT

Main Lead Sage Process

  • Request Type: SAGE_PROCESS_BOOK_POLICY_REQUEST
  • Model Type: Quote class name
  • Model ID: Quote ID
  • Status Flow: PENDING → PROCESSING → COMPLETED/FAILED
  • Conflict Handling: Reverts to PENDING on Sage conflict

🔄 Send Update Job Processing

BookEndorsementOnSageJob

  • Trigger: Scheduled via scheduleSageProcesses()
  • Model: SendUpdateLog
  • Middleware: WithoutOverlapping with send update ID lock
  • Timeout: 80 seconds
  • Retries: 1 attempt only
  • Entry Type: STRAIGHT, REVERSAL, or CORRECTION

Send Update Sage Process

  • Request Type: SAGE_PROCESS_BOOK_ENDORSEMENT_REQUEST
  • Model Type: SendUpdateLog
  • Model ID: Send Update Log ID
  • Status Flow: PENDING → PROCESSING → COMPLETED/FAILED
  • Conflict Handling: Reverts to PENDING on Sage conflict

⚠️ Important Considerations

🔒 Concurrency Control

  • WithoutOverlapping: Prevents duplicate processing
  • Time-Based Locks: Format YmdHi (e.g., 2024102113)
  • Lock Key: quote code or send update ID + time suffix
  • dontRelease(): Prevents accidental concurrent jobs

🚨 Error Handling

  • Sage Conflict: Returns to PENDING for retry
  • Timeout: Marks as TIMEOUT_STATUS
  • General Failure: Marks as FAILED_STATUS
  • Logging: All errors logged as INFO not ERROR

💰 Payment Handling

  • Main Lead: Uses quote code for payment tracking
  • Send Update: Uses main lead code + counter
  • Credit Approval: Skips prepayment receipt creation
  • NRA Case: Creates receipts during split approval

📋 Entry Type Selection

  • STRAIGHT: Premium increase, coverage addition
  • REVERSAL: Major changes requiring full reversal
  • CORRECTION: Error fixes, minor adjustments
  • Determined By: Send update type or endorsement type
