🔗 Embedded Product Booking

Comprehensive guide for MDX (Driver Cover), RDX (Rider Medical Cover), and ECB (Excess Cashback) - Sage 300 booking process

🎯 Overview

The Embedded Product Booking system manages the integration and booking of three specific embedded products: MDX (Driver Cover - MEDEX), RDX (Rider Medical Cover), and ECB (Excess Cashback) alongside main insurance policies. This process handles the complete lifecycle from product selection through Sage 300 integration including receipts, invoices, and payment applications.

💡 Core Embedded Product Operations

Product eligibility validation, automatic booking triggers during policy booking, separate financial processing in Sage 300, status synchronization, and comprehensive audit logging. All three embedded products (MDX, RDX, ECB) follow the same booking workflow but with product-specific API response retrieval and validation rules.

🔧 Function Types in This Documentation

  • Sage API Service Methods: Handle actual API calls to Sage 300
  • Payload Factory Methods: Generate API request structures
  • Location: SageApiEmbeddedProductService.php & SagePayloadFactory.php

🗄️ Database Storage

  • Embedded Transactions: embedded_transactions table
  • Product Options: embedded_product_options table
  • Sage Status: sage_embedded_product_statuses table
  • Quote Tags: quote_tags for booking status tracking

📋 Embedded Product Types

The system currently supports booking for three specific embedded products, each with unique characteristics and API integration requirements:

🚗

MDX - Driver Cover (MEDEX)

Driver medical cover provided by MEDEX for comprehensive driver protection. Requires TAP payment gateway, uses viewQuotePolicy API method with EmbeddedProduct call type, and requires specific status validations before Sage booking.

🏍️

RDX - Rider Medical Cover

Rider medical cover for motorcycle riders providing medical protection during rides. Integrated with bike/motorcycle insurance policies, uses viewQuotePolicy API method with EmbeddedProduct call type, and follows the same booking workflow as MDX.

💰

ECB - Excess Cashback

Excess cashback benefit offering financial reimbursement for policy excess amounts. Uses issuePolicy API method (not viewQuotePolicy), requires insurance_provider_id filtering, and has distinct API response retrieval logic compared to MDX/RDX products.

🔑 Key Product Differentiation

MDX & RDX: Use viewQuotePolicy API method with call_type = 'EmbeddedProduct'
ECB: Uses issuePolicy API method with insurance_provider_id filtering
All three products follow the same 4-step Sage booking workflow but differ in their API response retrieval.

🔄 Embedded Product Booking Workflow

1

AR Receipt Creation

Generate AR prepayment receipts for embedded product payments (Step 1)

2

AR Invoice Generation

Create AR premium and commission invoices (Step 2)

3

AP Invoice Generation

Create AP premium invoices for vendor payments (Step 3)

4

AR Payment Application

Apply AR prepayments to generated AR invoices and mark complete (Step 4)

📝 Note on Workflow Steps

The embedded product booking workflow consists of 4 core steps. AP prepayment receipt creation and AP payment application steps are not performed for embedded products as they are handled entirely through AR processing. The actual implementation in SageApiEmbeddedProductService.php has these steps commented out (lines 216-222 and 249-254).

🔗 bookEmbeddedProductOnSage() - API Service Method

Main function in SageApiEmbeddedProductService for booking embedded products with complete Sage integration. Supports three specific product types: MDX (Driver Cover - MEDEX), RDX (Rider Medical Cover), and ECB (Excess Cashback).

public function bookEmbeddedProductOnSage($sageRequestDataArray, $epShortCode = null)
{
    [$quote, $sageRequest, $embeddedProductTransaction] = $sageRequestDataArray;

    // Update status to queued
    $this->updateAndLogEPBookingStatus($embeddedProductTransaction, SageEmbeddedProductEnum::BOOKING_QUEUED->id(), self::CLASSNAME.' fn: '.__FUNCTION__);

    // Start logging for embedded product booking
    LoggerService::startQuoteLogging($embeddedProductTransaction, LoggerFeatureEnum::SAGE_EP_BOOKING);
    LoggerService::info(self::CLASSNAME.' fn: '.__FUNCTION__.' - Sage Booking - Quote Code: '.$quote->code.' - Embedded Product Booking started for: '.$embeddedProductTransaction->code);

    // Get API response data using product-specific retrieval method
    $insuranceProviderId = $embeddedProductTransaction?->product?->embeddedProduct?->insurance_provider_id;
    $insurerRequestResponse = $this->getInsurerRequestResponse($quote, $epShortCode, $insuranceProviderId);

    // Create embedded product specific payload with product type support
    $sageRequestEmbeddedProduct = self::createEmbeddedProductPayload($embeddedProductTransaction, $insurerRequestResponse, $epShortCode);
    $sageLogArray = $embeddedProductTransaction->sageApiLogs->keyBy('step')->toArray();

    // Check if already booked
    $isEmbeddedProductBookedOnSage = QuoteTag::where([
        'quote_type_id' => $sageRequest->quoteTypeId,
        'quote_uuid' => $quote->uuid,
        'name' => QuoteTagEnums::EMBEDDED_PRODUCT_BOOKED_ON_SAGE,
        'value' => 1,
    ])->first();

    if (!$isEmbeddedProductBookedOnSage) {
        // Step 1: Create AR Prepayment Receipt
        $arReceiptCreationResponse = $this->createARPrepaymentReceipt([
            $quote, $sukoonMedXTransaction, $sageRequest, $sageRequestEmbeddedProduct, $sageLogArray
        ]);

        if (!$arReceiptCreationResponse['status']) {
            $this->updateAndLogEPBookingStatus($sukoonMedXTransaction, SageEmbeddedProductEnum::BOOKING_FAILED->id(), self::CLASSNAME.' fn: '.__FUNCTION__);
            return $arReceiptCreationResponse;
        }

        $sageRequestEmbeddedProduct->epSageReceiptId = $arReceiptCreationResponse['documentNumber'];

        // Step 2: Create AR Commission and Premium Invoice
        $createARInvoicePremAndComm = $this->createARInvoicePremAndComm([
            $quote, $embeddedProductTransaction, $sageRequest, $sageRequestEmbeddedProduct, $sageLogArray
        ]);

        if (!$createARInvoicePremAndComm['status']) {
            $this->updateAndLogEPBookingStatus($embeddedProductTransaction, SageEmbeddedProductEnum::BOOKING_FAILED->id(), self::CLASSNAME.' fn: '.__FUNCTION__);
            return $createARInvoicePremAndComm;
        }

        // Step 3: Create AP Premium Invoice
        $createAPInvoicePrem = $this->createAPPremInvoice([
            $quote, $embeddedProductTransaction, $sageRequest, $sageRequestEmbeddedProduct, $sageLogArray
        ]);

        if (!$createAPInvoicePrem['status']) {
            $this->updateAndLogEPBookingStatus($embeddedProductTransaction, SageEmbeddedProductEnum::BOOKING_FAILED->id(), self::CLASSNAME.' fn: '.__FUNCTION__);
            return $createAPInvoicePrem;
        }

        // Step 4: Apply Prepayments to AR Invoice
        $applyPaymentARInvoices = $this->applyPaymentARInvoices([
            $quote, $embeddedProductTransaction, $sageRequest, $sageRequestEmbeddedProduct, $sageLogArray
        ]);

        if (!$applyPaymentARInvoices['status']) {
            $this->updateAndLogEPBookingStatus($embeddedProductTransaction, SageEmbeddedProductEnum::BOOKING_FAILED->id(), self::CLASSNAME.' fn: '.__FUNCTION__);
            return $applyPaymentARInvoices;
        }

        // NOTE: AP Prepayment Receipt and AP Payment Application steps are currently
        // commented out in the implementation (lines 216-222 and 249-254 in service)
        // This is intentional as EP transactions do not require AP receipt processing

        // Mark as completed and create quote tag
        $this->updateAndLogEPBookingStatus($embeddedProductTransaction, SageEmbeddedProductEnum::BOOKING_COMPLETED->id(), self::CLASSNAME.' fn: '.__FUNCTION__);

        QuoteTag::create([
            'quote_type_id' => $sageRequest->quoteTypeId,
            'quote_uuid' => $quote->uuid,
            'name' => QuoteTagEnums::EMBEDDED_PRODUCT_BOOKED_ON_SAGE,
            'value' => 1,
        ]);

        LoggerService::info(self::CLASSNAME.' fn: '.__FUNCTION__.' - Sage Booking - Embedded Product Booked for: '.$quote->code);
    } else {
        $this->updateAndLogEPBookingStatus($embeddedProductTransaction, SageEmbeddedProductEnum::BOOKING_COMPLETED->id(), self::CLASSNAME.' fn: '.__FUNCTION__);
        LoggerService::info(self::CLASSNAME.' fn: '.__FUNCTION__.' - Sage Booking - Embedded Product Booked Already for: '.$quote->code);
    }

    return ['status' => true, 'message' => 'Embedded Product is Booked for EP Code : '.$embeddedProductTransaction->code];
}

⚠️ Important Implementation Note

AP Prepayment Receipt Steps Currently Disabled: The implementation has AP prepayment receipt creation and AP payment application steps commented out. This is intentional as embedded product transactions are handled entirely through AR (Accounts Receivable) processing. The workflow consists of only 4 active steps: AR Receipt → AR Invoice → AP Invoice → AR Payment Application.

🔄 getInsurerRequestResponse() - Product-Specific API Response Retrieval

Abstraction method that retrieves insurer API responses based on embedded product type. Supports different products with specialized data handling.

public function getInsurerRequestResponse($quote, $epShortCode, $insuranceProviderId = null)
{
    return match ($epShortCode) {
        EmbeddedProductEnum::ECB => self::getInsurerRequestResponseForECB($quote, $insuranceProviderId),
        default => self::getInsurerRequestResponseForSukoonMedXRedx($quote, $insuranceProviderId),
    };
}

public function getInsurerRequestResponseForECB($quote, $insuranceProviderId = null)
{
    // ECB-specific API response retrieval with insurance provider filtering
    return InsurerRequestResponse::where([
        'quote_uuid' => $quote->uuid,
        'status' => 'passed',
        'execution_method' => 'issuePolicy',
        'insurance_provider_id' => $insuranceProviderId,
    ])->latest()->first();
}

public function getInsurerRequestResponseForSukoonMedXRedx($quote, $insuranceProviderId = null)
{
    // MDX and RDX API response retrieval
    // Note: Function name kept as "SukoonMedXRedx" for backward compatibility
    // MDX = Driver Cover (MEDEX), RDX = Rider Medical Cover
    return InsurerRequestResponse::where([
        'quote_uuid' => $quote->uuid,
        'status' => 'passed',
        'execution_method' => 'viewQuotePolicy',
        'call_type' => 'EmbeddedProduct',
    ])->latest()->first();
}

📅 scheduleBookingOfEmbeddedProduct() - API Service Method

Function for scheduling embedded product booking through queue system with validation.

public function scheduleBookingOfEmbeddedProduct($request)
{
    $user = auth()->user();
    $quoteTypeId = QuoteTypes::getIdFromValue($request['modelType']);
    $quote = $this->getQuoteObjectBy($request['modelType'], $request['quoteId']);

    // Get payment information
    $payment = Payment::where('code', $quote->code)->mainLeadPayment()->with('paymentSplits')->first();
    $paymentSplits = $payment->paymentSplits;

    // Validate insurance provider
    $epTransaction = EmbeddedTransaction::where('id', $request['epTransactionId'])->first();
    $insuranceProvider = InsuranceProvider::find($request['insuranceProviderId']);
    $isSukoonInsuranceProvider = in_array($insuranceProvider?->code, $this->sageApiService->allowedProviderForSageEPBooking());

    if (!$isSukoonInsuranceProvider) {
        return ['status' => false, 'message' => 'Sage booking cannot be scheduled because current insurer is '.$insuranceProvider?->text];
    }

    // Create sage request payload
    $sageRequest = app(SagePayloadFactory::class)->sagePayLoad($request['modelType'], $payment, $quote, $paymentSplits);
    $sageRequest->userId = $user?->id;
    $sageRequest->insurerID = $request['insuranceProviderId'];
    $sageRequest->sageProcessRequestType = SageEnum::SAGE_PROCESS_BOOK_EMBEDDED_PRODUCT_REQUEST;
    $sageRequest->epTransactionId = $request['epTransactionId'];
    $sageRequest->epInsuranceProviderId = $request['insuranceProviderId'];
    $sageRequest->quoteType = $request['modelType'];
    $sageRequest->quoteId = $request['quoteId'];
    $sageRequest->quoteTypeId = $quoteTypeId;
    $sageRequest->quoteCode = $quote->code;

    // Verify customer in Sage
    $data = ['id' => $quote->id, 'quoteTypeId' => $quoteTypeId];
    $sageRequest->customerId = $this->sageApiService->verifySageCustomer($quote->customer_id, $data, $quote, 15);

    // Create or update sage process record
    $sageProcessData = [
        'user_id' => $sageRequest->userId,
        'insurance_provider_id' => $sageRequest->insurerID,
        'request' => json_encode([
            'sagePayload' => $sageRequest,
            'requestPayload' => $request,
        ]),
        'status' => SageEnum::SAGE_PROCESS_PENDING_STATUS,
    ];

    $sageProcess = SageProcess::where([
        'model_type' => $epTransaction::class,
        'model_id' => $epTransaction->id,
    ])->first();

    if ($sageProcess) {
        $sageProcess->update($sageProcessData);
    } else {
        $sageProcessData['model_type'] = $epTransaction::class;
        $sageProcessData['model_id'] = $epTransaction->id;
        $sageProcess = SageProcess::create($sageProcessData);
    }

    return ['status' => true, 'message' => 'Embedded Product booking scheduled successfully'];
}

🔧 createEmbeddedProductPayload() - Payload Factory Method

Static method that creates embedded product specific payload from API response data.

public static function createEmbeddedProductPayload($sukoonMedXTransaction, $viewQuotePolicyApiLog)
{
    $sageRequestEmbeddedProduct = new stdClass();

    // Get API response data
    $viewQuotePolicyApiResponse = json_decode($viewQuotePolicyApiLog->response);
    $originalInsurerTaxInvoiceNumber = $viewQuotePolicyApiResponse->additional_data->tax_invoice_document_number;

    // Format invoice number for Sage (max 18 characters)
    $insurerTaxInvoiceNumber = self::formatDocNumber($originalInsurerTaxInvoiceNumber);

    // Basic embedded product information
    $sageRequestEmbeddedProduct->epTransactionId = $sukoonMedXTransaction->id;
    $sageRequestEmbeddedProduct->epTransactionCode = $sukoonMedXTransaction->code;
    $sageRequestEmbeddedProduct->epProductName = $sukoonMedXTransaction->product->embeddedProduct->name;
    $sageRequestEmbeddedProduct->epProductCode = $sukoonMedXTransaction->product->embeddedProduct->short_code;

    // Financial information
    $sageRequestEmbeddedProduct->epPremium = $sukoonMedXTransaction->premium;
    $sageRequestEmbeddedProduct->epCommission = $sukoonMedXTransaction->commission;
    $sageRequestEmbeddedProduct->epVatOnCommission = $sukoonMedXTransaction->vat_on_commission;
    $sageRequestEmbeddedProduct->epTotalAmount = $sukoonMedXTransaction->total_amount;

    // Invoice information
    $sageRequestEmbeddedProduct->insurerTaxInvoiceNumber = (string) mb_substr($insurerTaxInvoiceNumber, -18);
    $sageRequestEmbeddedProduct->originalInsurerTaxInvoiceNumber = $originalInsurerTaxInvoiceNumber;

    // Policy information from API response
    $sageRequestEmbeddedProduct->policyNumber = $viewQuotePolicyApiResponse->policy_number ?? '';
    $sageRequestEmbeddedProduct->policyStartDate = $viewQuotePolicyApiResponse->policy_start_date ?? '';
    $sageRequestEmbeddedProduct->policyEndDate = $viewQuotePolicyApiResponse->policy_end_date ?? '';

    // Customer information
    $sageRequestEmbeddedProduct->customerName = $viewQuotePolicyApiResponse->customer_name ?? '';
    $sageRequestEmbeddedProduct->customerEmail = $viewQuotePolicyApiResponse->customer_email ?? '';

    return $sageRequestEmbeddedProduct;
}

⚙️ BookEmbeddedProductOnSageJob Implementation Details

Dedicated queue job that handles asynchronous embedded product booking with comprehensive error handling and status management.

class BookEmbeddedProductOnSageJob implements ShouldQueue
{
    public $tries = 1;  // Single attempt to prevent duplicate bookings
    public $timeout = 80;  // 80-second timeout for Sage API operations

    public function __construct($sageRequest, $epTransaction, $request, $sageProcess)
    {
        $this->sageRequest = $sageRequest;
        $this->epTransaction = $epTransaction;
        $this->request = $request;
        $this->sageProcess = $sageProcess;
        // Time-based lock to prevent concurrent processing
        $this->lockPostfix = Carbon::now()->format('YmdHi'); // e.g., 2024102113
    }

    public function handle()
    {
        // Start logging with feature flag
        LoggerService::startQuoteLogging($this->epTransaction, LoggerFeatureEnum::SAGE_EP_BOOKING_REVERSAL);

        // Re-fetch sage process for latest status
        $this->sageProcess = SageProcess::find($this->sageProcess->id);
        $quote = $this->getQuoteObjectBy($this->request->modelType, $this->request->quoteId);

        // Validate EP transaction exists
        $quoteTypeId = QuoteTypes::getIdFromValue($this->request->modelType);
        $ePTransaction = (new SageApiService)->getEPTransactions($quote, $quoteTypeId);

        if (!$ePTransaction || count($ePTransaction) === 0) {
            $message = 'Cannot proceed as transaction is not found';
            (new SageApiService)->updateSageProcessStatus($this->sageProcess, SageEnum::SAGE_PROCESS_FAILED_STATUS, $message, $this->logFor);
            return;
        }

        // Only process if status is PENDING
        if ($this->sageProcess->status === SageEnum::SAGE_PROCESS_PENDING_STATUS) {
            // Update to PROCESSING
            (new SageApiService)->updateSageProcessStatus($this->sageProcess, SageEnum::SAGE_PROCESS_PROCESSING_STATUS, null, $this->logFor);

            // Execute booking with epShortCode parameter
            $response = (new SageApiEmbeddedProductService)->bookEmbeddedProductOnSage(
                [$quote, $this->sageRequest, $this->epTransaction],
                $this->sageRequest->epShortCode
            );

            // Handle response based on status
            if (!$response['status']) {
                if ($response['message'] == SageEnum::SAGE_PROCESSING_CONFLICT_MESSAGE) {
                    // Sage conflict - revert to PENDING for retry
                    (new SageApiService)->updateSageProcessStatus($this->sageProcess, SageEnum::SAGE_PROCESS_PENDING_STATUS, $response['message'], $this->logFor);
                } else {
                    // Booking failed - mark as FAILED
                    (new SageApiService)->updateSageProcessStatus($this->sageProcess, SageEnum::SAGE_PROCESS_FAILED_STATUS, $response['message'], $this->logFor);
                }
            } else {
                // Success - mark as COMPLETED
                (new SageApiService)->updateSageProcessStatus($this->sageProcess, SageEnum::SAGE_PROCESS_COMPLETED_STATUS, null, $this->logFor);
            }
        }

        // Trigger next process in queue
        (new SageApiService)->scheduleSageProcesses($this->sageRequest->insurerID);
    }

    public function failed(Throwable $exception)
    {
        // Handle timeout vs general failure
        if (str_contains($exception->getMessage(), SageEnum::SAGE_TIMEOUT_REQUEST_MESSAGE)) {
            (new SageApiService)->updateSageProcessStatus($this->sageProcess, SageEnum::SAGE_PROCESS_TIMEOUT_STATUS, $exception->getMessage());
        } else {
            (new SageApiService)->updateSageProcessStatus($this->sageProcess, SageEnum::SAGE_PROCESS_FAILED_STATUS, $exception->getMessage());
        }

        // Update EP booking status
        (new SageApiEmbeddedProductService)->updateAndLogEPBookingStatus($this->epTransaction, SageEmbeddedProductEnum::BOOKING_FAILED->id(), $this->logFor);

        // Reschedule next process
        (new SageApiService)->scheduleSageProcesses($this->sageRequest->insurerID);
    }

    public function middleware()
    {
        // Prevent overlapping jobs with time-based unique key
        return [(new WithoutOverlapping($this->epTransaction->code.'-'.$this->lockPostfix))->dontRelease()];
    }
}

🔐 Concurrency Control

  • Middleware: WithoutOverlapping with time-based suffix
  • Lock Key: {epTransactionCode}-{YmdHi} format
  • Purpose: Prevents duplicate EP booking attempts
  • Release: dontRelease() - manual cleanup required

⚡ Error Handling Strategy

  • Sage Conflict: Reverts to PENDING for automatic retry
  • Timeout: Marks as TIMEOUT_STATUS for investigation
  • General Failure: Marks as FAILED_STATUS
  • Attempts/Timeout Errors: Logged as INFO not ERROR

🔍 Key Implementation Details

Important Parameters:

  • $sageRequest->epShortCode - Critical parameter for product type differentiation (ECB vs MDX/RDX)
  • $this->lockPostfix - Time-based suffix (YmdHi format) ensures unique lock keys
  • $this->tries = 1 - Single attempt prevents accidental duplicate bookings in Sage
  • $this->timeout = 80 - Matches Sage API response time expectations
