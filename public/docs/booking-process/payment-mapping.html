🔗 Payment Mapping & Apply Prepayment

Comprehensive guide to payment receipt-to-invoice mapping and prepayment application in Sage 300

🎯 Overview

The Payment Mapping & Apply Prepayment process manages the critical third step of Sage integration: linking previously created payment receipts to newly generated invoices. This process ensures proper financial reconciliation by applying prepayments to outstanding invoice balances in both AR and AP modules.

💡 Core Payment Mapping Operations

Automatic Receipt-to-Invoice Mapping for upfront payments, Split Payment Application for installment-based policies, AR/AP Prepayment Processing for customer and vendor payments, and systematic balance reconciliation through Sage 300 payment application workflow with comprehensive error handling and recovery mechanisms.

🔧 Function Types in This Documentation

  • Sage API Service Methods: Handle actual API calls to Sage 300
  • Payload Factory Methods: Generate API request structures
  • Location: SageApiService.php & SagePayloadFactory.php

🗄️ Database Dependencies

  • Receipt References: payment_splits.sage_reciept_id
  • Invoice Numbers: payments.tax_invoice_number
  • Mapping Logs: sage_api_logs table for all operations

📋 Payment Mapping Types

🔗

Upfront Payment Mapping

Direct one-to-one mapping between single prepayment receipt and invoice for upfront payment policies. Complete balance settlement.

📊

Split Payment Mapping

Partial payment application for installment-based policies. Maps individual installment receipts to corresponding invoice portions.

🔄

AR/AP Cross-Mapping

Coordinated mapping for both customer receipts (AR) and vendor payments (AP) to ensure complete financial reconciliation.

⚖️

Balance Reconciliation

Automatic balance adjustment and validation to ensure invoice balances match applied payment amounts in Sage 300.

📦 Payment Mapping Scenarios

The system handles payment-to-invoice mapping across three main scenarios, each with specific workflows:

🏠 Main Lead Payment Mapping

  • AR Mapping: Customer receipts to customer invoices
  • AP Mapping: Vendor payments to vendor invoices (if insurer direct payment)
  • Modes: Upfront, Split Payments, Non-Split/Non-Upfront
  • Special Cases: Zero price policies (credit approval), historic data skip logic

🔗 Embedded Product Payment Mapping

  • AR Only: EP customer receipts to EP invoices
  • AP Mapping: Currently disabled (commented out in implementation)
  • Simplicity: Always upfront payments, no split schedules
  • Method: applyPaymentARInvoices() in SageApiEmbeddedProductService

📝 Send Update Payment Mapping

  • Context: Endorsement-related payment adjustments
  • Scenarios: Additional payments for increased premium
  • Mapping: New prepayment receipts to adjustment invoices
  • Complexity: May involve reversals and corrections

⚠️ Important: skipApplyPrepaymentsForSpecificLeads()

Historic Data Compatibility: The system includes logic to skip prepayment application for specific leads to maintain compatibility with data created before M2 launch. This is temporary code that checks specific criteria and returns early if the quote falls under skippable conditions. See line 666 in applyPaymentARInvoices() implementation.

💰 Zero Price Policy Handling

  • Condition: payment.total_price == 0
  • Action: Skip prepayment application entirely
  • Reason: No actual payment to map
  • Requirement: Must use CreditApproval payment method

📊 Payment Frequency Logic

  • UPFRONT: Single payment mapping (applyUpfrontPaymentARInvoices)
  • SPLIT_PAYMENTS: Multiple installment mappings (applySplitPaymentARInvoices)
  • Other: Non-split/non-upfront handling (applyNonSplitNonUpfrontPaymentARInvoices)
  • Status Check: Payment must be PAID or CAPTURED

💰 Upfront Payment Application

Payment Frequency: PaymentFrequency::UPFRONT | Context: Single payment to single invoice mapping

📋 Characteristics

💳 Payment Structure

  • Single prepayment receipt already created
  • Full invoice amount paid at once
  • Payment status: PAID or CAPTURED
  • Immediate full settlement

📄 Application Process

  • Create AR receipt batch with invoice reference
  • Apply full receipt amount to invoice
  • Mark invoice as paid/settled
  • No partial payments or schedules

🔄 Workflow Steps

  • Step 13: Create payment receipt application batch
  • Step 14: Ready to post receipt batch
  • Step 15: Post receipt batch to GL
  • Invoice fully reconciled after posting

✅ Validation

  • Payment status must be PAID
  • Total price cannot be zero (unless CreditApproval)
  • Receipt ID must exist in payment_splits
  • Invoice must be posted before application

💡 Key Points for Upfront Payment Application

One-to-One Mapping: Single prepayment receipt applied to single invoice
Full Settlement: Invoice balance becomes zero after application
Simple Process: No complex split tracking or partial applications
Immediate Reconciliation: Payment and invoice reconciled in one step

📅 Split Payment Application

Payment Frequency: PaymentFrequency::SPLIT_PAYMENTS | Context: Multiple installment payments to invoice with schedules

📋 Characteristics

💳 Payment Structure

  • Multiple installment receipts
  • First payment typically paid upfront
  • Future payments matched to invoice schedules
  • Each payment tracked separately

📄 Application Process

  • Apply only PAID/CAPTURED split receipts
  • Match payments to PaymentSchedules in invoice
  • Partial invoice settlement
  • Track remaining balance per schedule

🔄 Workflow Complexity

  • Iterate through paid payment splits
  • Create receipt application for each
  • Update payment schedule status
  • Track remaining installments

⚖️ Balance Tracking

  • Invoice total vs paid amounts
  • Schedule-by-schedule reconciliation
  • Outstanding balance per installment
  • Future payment obligations

💡 Key Points for Split Payment Application

Partial Applications: Apply only paid installments, leave future ones pending
Schedule Matching: Each payment maps to specific PaymentSchedule entry
Incremental Settlement: Invoice balance reduces with each installment payment
Status Tracking: Each split status tracked individually in payment_splits table

🔄 Non-Split/Non-Upfront Payment Application

Payment Frequency: Other (Not UPFRONT, Not SPLIT_PAYMENTS) | Context: Custom payment arrangements

📋 Characteristics

💳 Payment Structure

  • Neither standard upfront nor split
  • First payment must be PAID/CAPTURED
  • Flexible payment arrangement
  • Edge case handling

📄 Application Logic

  • Similar to split payment processing
  • Apply first payment if available
  • Custom payment schedule handling
  • Flexible reconciliation rules

⚠️ Use Cases

  • Custom financing arrangements
  • Deferred payment scenarios
  • Migration data compatibility
  • Special payment terms

✅ Validation

  • First payment PAID or CAPTURED check
  • Custom payment validation rules
  • Receipt existence verification
  • Invoice posting status check

💡 Key Points for Non-Split/Non-Upfront Application

Flexibility Required: Handles payment scenarios not covered by standard types
First Payment Focus: Must have at least first payment paid before processing
Custom Logic: May use custom rules based on specific payment arrangement
Migration Support: Ensures compatibility with historic/imported data

🛠️ Core Payment Mapping Functions

📍 Function Type: These are Sage API Service Methods that orchestrate payment mapping processes.

🔗 applyPaymentARInvoices() - API Service Method

Main orchestrator function in SageApiService that applies AR prepayment receipts to AR invoices based on payment frequency.

public function applyPaymentARInvoices($sageRequestDataArray)
{
    $returnMessage = ['status' => false, 'message' => null, 'error' => null];
    [$sageRequest, $quote, $payment, $paymentSplits, $sageLogArray] = $sageRequestDataArray;
    $isTotalPriceZero = $payment->total_price == 0;

    /* Start: Temporary code for historic data to allow book policy after m2 launch */
    $isQuoteFallUnderSkippableCriteria = $this->skipApplyPrepaymentsForSpecificLeads($quote, $payment, $paymentSplits);
    if ($isQuoteFallUnderSkippableCriteria['status']) {
        return $isQuoteFallUnderSkippableCriteria;
    }

    /* applyPaymentARInvoices */
    $isTransactionPaidAndFrequencyUpfront = $sageRequest->invoicePaymentStatus == PaymentStatusEnum::PAID && $payment->frequency == PaymentFrequency::UPFRONT;

    if ($isTransactionPaidAndFrequencyUpfront && !$isTotalPriceZero) {
        return $this->applyUpfrontPaymentARInvoices([$sageRequest, $quote, $payment, $paymentSplits, $sageLogArray]);
    } elseif ($isTotalPriceZero) {
        LoggerService::info('########## applyUpfrontPaymentARInvoices skipped for : '.$quote->code.' due to zero price ##########');
    }

    $isFrequencySplitAndFirstChildPaymentPaid = $sageRequest->invoicePaymentStatus == PaymentStatusEnum::PAID && $payment->frequency == PaymentFrequency::SPLIT_PAYMENTS;

    if ($isFrequencySplitAndFirstChildPaymentPaid) {
        return $this->applySplitPaymentARInvoices([$sageRequest, $quote, $payment, $paymentSplits, $sageLogArray]);
    }

    $isFrequencyUpfrontOrSplit = in_array($payment->frequency, [PaymentFrequency::UPFRONT, PaymentFrequency::SPLIT_PAYMENTS]);
    $isFirstPaymentPaidOrCaptured = in_array($paymentSplits[0]['payment_status_id'], [PaymentStatusEnum::PAID, PaymentStatusEnum::CAPTURED]);

    if (!$isFrequencyUpfrontOrSplit && $isFirstPaymentPaidOrCaptured) {
        return $this->applyNonSplitNonUpfrontPaymentARInvoices([$sageRequest, $quote, $payment, $paymentSplits, $sageLogArray]);
    }

    $returnMessage['status'] = true;
    $returnMessage['message'] = 'Apply Prepayment completed';

    return $returnMessage;
}

🔧 Individual Payment Mapping Methods

📍 Function Type: These are Sage API Service Methods that handle specific payment mapping scenarios.

🔗 applyUpfrontPaymentARInvoices() - API Service Method

Applies upfront prepayment receipts to AR invoices in SageApiService for complete balance settlement.

private function applyUpfrontPaymentARInvoices($sageRequestDataArray)
{
    [$sageRequest, $quote, $payment, $paymentSplits, $sageLogArray] = $sageRequestDataArray;
    $returnMessage = ['status' => false, 'message' => null, 'error' => null];
    LoggerService::info('########## Start applyPaymentARInvoices for : '.$quote->code.' ##########');

    $totalSteps = 15;
    $currentStep = 13;
    $isLiveApiCallStep13 = true;

    // Check if payment application already completed
    if (isset($sageLogArray[$currentStep]) && $sageLogArray[$currentStep]['status'] == SageEnum::STATUS_SUCCESS) {
        LoggerService::info('SAGE API : createPaymentReceiptOneInvoice Sent Already for '.$quote->code);
        $isLiveApiCallStep13 = false;
        $postedResponse = json_decode($sageLogArray[$currentStep]['response'], true);
    } else {
        LoggerService::info('SAGE API : Send createPaymentReceiptOneInvoice for '.$quote->code);

        // Create payment receipt mapping payload
        $payLoadOptions = SagePayloadFactory::createPaymentReceiptOneInvoice(
            $quote,
            $sageRequest->customerId,
            $payment,
            $paymentSplits
        );

        $resp = $this->postToSage300($payLoadOptions['endPoint'], $payLoadOptions['payload']);
        $postedResponse = json_decode($resp, true);

        // Log the API call
        if ($isLiveApiCallStep13) {
            $this->logSageApiCall($payLoadOptions, $postedResponse, $quote, $quote, $currentStep, $totalSteps, SageEnum::STATUS_SUCCESS);
        }
    }

    // Process Ready to Post and Post operations
    if (!empty($postedResponse['BatchNumber'])) {
        // Ready to Post step
        $currentStep = 14;
        $readyToPostPayload = SagePayloadFactory::readyToPostReceiptAr($postedResponse['BatchNumber']);
        $readyToPostResponse = $this->postToSage300($readyToPostPayload['endPoint'], $readyToPostPayload['payload'], 'PATCH');

        // Post to GL step
        $currentStep = 15;
        $postPayload = SagePayloadFactory::aRPostReceiptsPayment($postedResponse['BatchNumber']);
        $finalResponse = $this->postToSage300($postPayload['endPoint'], $postPayload['payload']);

        LoggerService::info('########## End applyPaymentARInvoices for : '.$quote->code.' ##########');
        $returnMessage['status'] = true;
        $returnMessage['message'] = 'Prepayments applied on sage';
    }

    return $returnMessage;
}

📊 applySplitPaymentARInvoices() - API Service Method

Applies split payment receipts to AR invoices in SageApiService for installment-based payment mapping.

private function applySplitPaymentARInvoices($sageRequestDataArray)
{
    [$sageRequest, $quote, $payment, $paymentSplits, $sageLogArray] = $sageRequestDataArray;
    $returnMessage = ['status' => false, 'message' => null, 'error' => null];

    LoggerService::info('########## Start arSplitPrepaymentPayload for : '.$quote->code.' ##########');
    $totalSteps = 15;
    $currentStep = 13;

    // Get paid payment splits only
    $paidPaymentSplits = $paymentSplits->whereIn('payment_status_id', [
        PaymentStatusEnum::PAID,
        PaymentStatusEnum::CAPTURED
    ]);

    // Check if split payment receipts already applied
    if (isset($sageLogArray[$currentStep]) && $sageLogArray[$currentStep]['status'] == SageEnum::STATUS_SUCCESS) {
        LoggerService::info('SAGE API : arSplitPrepaymentPayload Sent Already for '.$quote->code);
        $postedResponse = json_decode($sageLogArray[$currentStep]['response'], true);
    } else {
        LoggerService::info('SAGE API : Send arSplitPrepaymentPayload for '.$quote->code);

        // Create split payment receipt mapping payload
        $payLoadOptions = SagePayloadFactory::arSplitPrepaymentPayload(
            $quote,
            $sageRequest->customerId,
            $payment,
            $paidPaymentSplits
        );

        $resp = $this->postToSage300($payLoadOptions['endPoint'], $payLoadOptions['payload']);
        $postedResponse = json_decode($resp, true);

        $this->logSageApiCall($payLoadOptions, $postedResponse, $quote, $quote, $currentStep, $totalSteps, SageEnum::STATUS_SUCCESS);
    }

    // Process Ready to Post and Post operations for split payments
    if (!empty($postedResponse['BatchNumber'])) {
        // Ready to Post step
        $readyToPostPayload = SagePayloadFactory::readyToPostReceiptAr($postedResponse['BatchNumber']);
        $readyToPostResponse = $this->postToSage300($readyToPostPayload['endPoint'], $readyToPostPayload['payload'], 'PATCH');

        // Post to GL step
        $postPayload = SagePayloadFactory::aRPostReceiptsPayment($postedResponse['BatchNumber']);
        $finalResponse = $this->postToSage300($postPayload['endPoint'], $postPayload['payload']);

        $returnMessage['status'] = true;
        $returnMessage['message'] = 'Split Payment Prepayments applied on sage';
    }

    return $returnMessage;
}

🏭 Payload Factory Methods

📍 Function Type: These are Payload Factory Methods that generate Sage 300 API request structures for payment mapping.

🔗 createPaymentReceiptOneInvoice() - Payload Factory Method

Static method in SagePayloadFactory that creates the payment receipt mapping payload for upfront payments.

public static function createPaymentReceiptOneInvoice($quote, $sage_customer_number, $payment, $splitPayments, $isPosAllSplitPayment = false)
{
    $entryType = SageEnum::SCT_STRAIGHT;

    $payLoad = [
        'BatchRecordType' => 'CA',  // AR Receipt Batch
        'BankCode' => SageEnum::BANK_CODE_INS,
        'ReceiptsAdjustments' => [
            [
                'BatchType' => 'CA',
                'CustomerNumber' => $sage_customer_number,
                'BankCode' => SageEnum::BANK_CODE_INS,
                'ReceiptTransactionType' => 'Receipt',  // Payment application type
                'AppliedReceiptsAdjustments' => self::createAppliedReceiptsAdjustmentsForAR(
                    $quote,
                    $sage_customer_number,
                    $payment,
                    $splitPayments,
                    $isPosAllSplitPayment
                ),
            ],
        ],
    ];

    return [
        'endPoint' => 'AR/ARReceiptAndAdjustmentBatches',
        'payload' => $payLoad,
        'sage_request_type' => SageEnum::SRT_CREATE_PAY_REC_ONE_INV,
        'entry_type' => $entryType,
    ];
}

🔗 createAppliedReceiptsAdjustmentsForAR() - Payload Factory Method

Helper method that creates the applied receipts adjustments array for AR payment mapping.

private static function createAppliedReceiptsAdjustmentsForAR($quote, $sage_customer_number, $payment, $splitPayments, $isPosAllSplitPayment = false)
{
    $appliedReceiptsAdjustments = [];

    foreach ($splitPayments as $index => $item) {
        // Skip if payment split doesn't have sage receipt ID
        if (empty($item->sage_reciept_id)) {
            continue;
        }

        // Create receipt application entry
        $receiptData = self::createReceiptDataForAR($item, $sage_customer_number, $payment, $index + 1);
        $appliedReceiptsAdjustments[] = $receiptData;

        // Create prepayment application entry
        $prePaymentData = self::createPrePaymentDataForAR($item, $sage_customer_number, $payment);
        $appliedReceiptsAdjustments[] = $prePaymentData;
    }

    return $appliedReceiptsAdjustments;
}

🗄️ Database Tables & Columns

📊 Primary Tables for Payment Mapping

1. payment_splits Table

Individual payment installments with receipt references for mapping.

Column Type Purpose Usage in Payment Mapping
sage_reciept_id VARCHAR(100) NULLABLE AR receipt document number Required for payment mapping - links receipt to invoice
sage_ap_payment_receipt_id VARCHAR(100) NULLABLE AP payment document number Used for AP payment mapping processes
payment_status_id INT Split payment status Must be PAID/CAPTURED for mapping eligibility
payment_amount DECIMAL(15,2) Amount for this installment Used in CustomerReceiptAmount for mapping
collection_amount DECIMAL(15,2) Actually collected amount Used when different from payment_amount

2. payments Table

Main payment information for mapping coordination.

Column Type Purpose Usage in Payment Mapping
tax_invoice_number VARCHAR(255) Invoice document number Target invoice for payment application
frequency ENUM Payment frequency type Determines mapping strategy (UPFRONT vs SPLIT_PAYMENTS)
total_price DECIMAL(15,2) Total payment amount Validation for complete payment mapping
discount_value DECIMAL(15,2) Applied discount amount Included in first installment mapping
