🔄 Non-Motor CQF Renewal

Queue-based processing of CQF renewal leads for Bike, Home, Pet, Travel, Life, Savings, Yacht, Jetski, Cycle

Active Documentation

❓ What is This?

The Non-Motor CQF Renewal feature finds eligible non-motor quotes (PersonalQuote and, for Bike, CarQuote) whose policies expire on a given date, runs them through a validation and storage pipeline, and creates RenewalsUploadLeads and RenewalQuoteProcess records so renewal leads can be worked by the business. Processing runs entirely in queue jobs and Laravel Batches, so the scheduler command exits quickly and workers do the work.

💡 Why queue-based?

✓ Command returns immediately; no long-running process
✓ Work is distributed across queue workers (e.g. Supervisor)
✓ One quote per job: better parallelism and failure isolation
✓ Batch progress and completion are visible (e.g. Horizon)
✓ Failed policies are reported via SendFailedNonCQFRenewal (Mail) from FinalizeNonMotorCQFLOBJob

📋 End-to-End Flow

Triggered by the scheduler (or manually). The command dispatches a single orchestrator job; everything else runs in batches and jobs.

1. Command
leads:process-non-motor-cqf-renewals
2. Orchestrator Job
Per LOB: eligible? → create lead → dispatch LOB job
3. LOB Batch
One batch per LOB: many Quote jobs
4. Quote Jobs
One job per quote: pipeline → good/cannot_upload
5. Finalize Job
Update lead; send failed report if any

🔑 Key terms

CQF Central Quotation Framework – renewal lead creation from existing quotes.
LOB Line of Business (Bike, Home, Pet, Travel, Life, Savings, Yacht, Jetski, Cycle).
RenewalsUploadLeads One record per LOB run: total_records, good, cannot_upload, status.
RenewalQuoteProcess One per quote processed; status PROCESSED or BAD_DATA, used for failed list.

⚙️ Trigger & Configuration

  • Command: php artisan leads:process-non-motor-cqf-renewals (or via scheduler).
  • Feature switch: ApplicationStorageEnums::NON_MOTOR_CQF_RENEWALS_SWITCH – when off, command only logs and exits.
  • Start date: Carbon::now()->addDays($renewalDaysThreshold) – only quotes with policy_expiry_date on this date are considered.
  • Threshold: ApplicationStorageEnums::NON_MOTOR_CQF_RENEWALS_DAYS_THRESHOLD – number of days from today to the expiry date (e.g. 30 = process quotes expiring in 30 days).

🏗️ Job Architecture

1. ProcessNonMotorCQFOrchestratorJob

Runs once per run. Reads threshold and start date; for each LOB in NonMotorCQFRegistry::supportedLOBs(), checks hasEligibleQuotesForLOB(). If eligible: gets getEligibleQuoteCountForLOB(), creates RenewalsUploadLeads with total_records set, dispatches ProcessNonMotorCQFLOBJob. Dispatches all LOB jobs as a single batch named Non Motor CQF Renewal Batch.

Files: app/Jobs/CQF/ProcessNonMotorCQFOrchestratorJob.php

2. ProcessNonMotorCQFLOBJob

One per LOB that had eligible quotes. Builds the list of eligible quote IDs (PersonalQuote for that LOB; for Bike only, also CarQuote with bike vehicle types). Creates one ProcessNonMotorCQFQuoteJob per quote ID, then dispatches them as a batch with ->then(FinalizeNonMotorCQFLOBJob::dispatch($renewalsUploadLeadsId)). Batch name: Non Motor CQF Renewal - {LOB} (e.g. "Non Motor CQF Renewal - Bike").

Files: app/Jobs/CQF/ProcessNonMotorCQFLOBJob.php

3. ProcessNonMotorCQFQuoteJob

One per quote. Receives quoteId, source (Personal / Car for Bike), quoteType, renewalsUploadLeadsId, renewalDaysThreshold. Calls NonMotorCQFRenewalExecutionService::processQuoteForJob(), which loads the quote and runs the pipeline (validation → duplicate check → storage). On success: markQuoteAsCompleted (increments good, creates RenewalQuoteProcess PROCESSED). On failure: markQuoteAsFailed (increments cannot_upload, creates RenewalQuoteProcess BAD_DATA).

Files: app/Jobs/CQF/ProcessNonMotorCQFQuoteJob.php

4. FinalizeNonMotorCQFLOBJob

Runs when the LOB’s quote batch completes. Loads the lead; sets total_records = good + cannot_upload and status = COMPLETED (or is_deleted = 1 if none processed). If cannot_upload > 0, sends the failed notification via SendFailedNonCQFRenewal (Mailable) which builds the Bird payload (with LOB in validationErrors and fileName) and triggers the Bird workflow.

Files: app/Jobs/CQF/FinalizeNonMotorCQFLOBJob.php

🔀 Quote Processing Pipeline

Each quote is passed through three pipes in order. Context is CQFRenewalContext (quote, lead, quoteType, threshold, validator, mapper, storage).

LOBValidationPipe
LOB-specific validation
DuplicateCheckPipe
Duplicate / already processed check
StoragePipe
Create renewal quote / storage
  • Pipes: app/Services/CQF/NonMotor/Pipes/LOBValidationPipe.php, DuplicateCheckPipe.php, StoragePipe.php
  • Context: app/Services/CQF/NonMotor/CQFRenewalContext.php
  • If any pipe fails (adds errors to context), the quote is marked failed (cannot_upload, RenewalQuoteProcess BAD_DATA).

📁 Registry & LOB Implementations

NonMotorCQFRegistry defines which LOBs are supported and their validator, mapper, and storage classes. Supported LOBs: Bike, Yacht, Jetski, Cycle, Pet, Home, Life, Savings.

✅ Eligibility Rules

Quotes are eligible if they match the following (same for PersonalQuote and, for Bike, CarQuote):

  • policy_expiry_date = start date (today + threshold days).
  • quote_status_id NOT IN (PolicyCancelled, PolicyCancelledReissued, CancellationPending).
  • payment_status_id IN (PAID, PARTIALLY_PAID, CAPTURED, PARTIAL_CAPTURED, CREDIT_APPROVED).
  • Personal: quote_type_id = LOB’s quote type id.
  • Bike from Car: vehicle_type_id IN VehicleTypeEnum::ids() (bike-related vehicle types).

🗄️ Database & Models

renewals_upload_leads total_records (set at creation + at finalize), good, cannot_upload, status, quote_type, renewal_import_code, etc.
renewal_quote_process renewals_upload_lead_id, quote_id, policy_number, status (NEW → PROCESSED or BAD_DATA), validation_errors, data.
Models RenewalsUploadLeads, RenewalQuoteProcess. Failed policies are read from RenewalQuoteProcess (status BAD_DATA) for the lead.
