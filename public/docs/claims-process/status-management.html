⚙️ Status Management

Comprehensive guide to claim status workflows and transition logic

📊 Status Hierarchy Overview

The Claims Management System uses a two-tier status system: Main Status for high-level claim state and Sub-Status for detailed workflow tracking.

🎯 Main Status (Team Lead Management)

Open

Active claims being processed

Closed

Completed or terminated claims

Managed by: Team Leads with CLAIMS_STATUS_UPDATE permission

Database Key: status_type = 'statuses'

🔄 Sub-Status (Detailed Workflow)

New Claim

Initial registration state

Claim Registered

Claim number assigned

Under Review

Assessment in progress

Claim Settled

Payment completed

Managed by: Claims Managers with CLAIMS_SUB_STATUS_UPDATE permission

Database Key: status_type = 'sub-statuses'

🔄 Observer Pattern - Automatic Transitions

The ClaimRequestObserver automatically triggers status updates based on field changes, implementing sophisticated business logic for each Line of Business.

🎯 Monitored Field Changes

The observer monitors specific field changes and triggers appropriate business logic:

claim_number When claim number is entered, automatically updates sub-status to "Claim Registered" (or "Awaiting Inspection" for Car claims)
claim_sub_status_id Evaluates closure logic based on LOB-specific closure states and automatically closes claims when appropriate
approved_repair_amount Car/Bike LOB: Updates sub-status to "Repair approved & work in progress" when amount is entered
approved_total_loss_amount Car/Bike LOB: Updates sub-status to "Total Loss Offer Letter shared" when amount is entered
approved_cash_loss_amount Car/Bike LOB: Updates sub-status to "Cash loss approved" when amount is entered
claim_status_id Prepared for Google review email dispatch when claim is closed (currently commented out)
// ClaimRequestObserver::updating() method public function updating(ClaimRequest $claimRequest): void { $claimService = new ClaimsService; // Monitor claim number changes if ($claimRequest->isDirty('claim_number')) { $originalClaimNumber = $claimRequest->getOriginal('claim_number'); $newClaimNumber = $claimRequest->claim_number; if (empty($originalClaimNumber) && !empty($newClaimNumber)) { $claimService->updateClaimSubStatusToClaimRegistered($claimRequest); } } // Monitor sub-status changes for closure logic if ($claimRequest->isDirty('claim_sub_status_id')) { $newClaimSubStatusId = $claimRequest->claim_sub_status_id; $shouldCloseTheClaim = $claimService->checkSubStatusForClaimClosure( $claimRequest, $newClaimSubStatusId ); if ($shouldCloseTheClaim) { $claimService->markClaimAsClosed($claimRequest); } } }

🏢 LOB-Specific Closure Logic

Each Line of Business has unique closure criteria implemented in the checkSubStatusForClaimClosure() method.

🚗 Motor/Car & Bike Claims Closure States

Closure Triggers:
  • Repair completed and claim settled
  • Total loss paid and claim settled
  • Cash loss paid and claim settled
  • Claim withdrawn
  • Claim denied
// Car and Bike LOBs share identical closure logic if ($isCarQuoteType || $isBikeQuoteType) { $subStatusListForClaimClosed = [ ClaimsEnum::CLAIM_SUB_STATUS_REPAIR_COMPLETED_AND_CLAIM_SETTLED->value, ClaimsEnum::CLAIM_SUB_STATUS_TOTAL_LOSS_PAID_AND_CLAIM_SETTLED->value, ClaimsEnum::CLAIM_SUB_STATUS_CASH_LOSS_PAID_AND_CLAIM_SETTLED->value, ClaimsEnum::CLAIM_SUB_STATUS_CLAIM_WITHDRAWN->value, ClaimsEnum::CLAIM_SUB_STATUS_CLAIM_DENIED->value, ]; }

🏥 Health & Group Medical Claims Closure States

Base Closure Triggers:
  • Claim paid
  • Claim withdrawn
  • Claim denied
Additional for Health & Group Medical:
  • Request approved
  • Answered and closed
if ($isHealthQuoteType || $isGroupMedicalQuoteType) { $subStatusListForClaimClosed = array_merge($subStatusListForClaimClosed, [ ClaimsEnum::CLAIM_SUB_STATUS_REQUEST_APPROVED->value, ClaimsEnum::CLAIM_SUB_STATUS_ANSWERED_AND_CLOSED->value, ]); }

💼 Life Claims Closure States

Simplified Closure Logic:
  • Claim paid
  • Claim denied
if ($isLifeQuoteType) { $subStatusListForClaimClosed = [ ClaimsEnum::CLAIM_SUB_STATUS_CLAIM_PAID->value, ClaimsEnum::CLAIM_SUB_STATUS_CLAIM_DENIED->value, ]; }

🏠 Other LOBs (Home, Travel, Pet, etc.) Closure States

Standard Closure Logic:
  • Claim paid
  • Claim withdrawn
  • Claim denied
Supported LOBs: Home, Travel, Yacht, Pet, Cycle, Jetski, Business, CorpLine, Savings
// Default closure logic for all other LOBs $subStatusListForClaimClosed = [ ClaimsEnum::CLAIM_SUB_STATUS_CLAIM_PAID->value, ClaimsEnum::CLAIM_SUB_STATUS_CLAIM_WITHDRAWN->value, ClaimsEnum::CLAIM_SUB_STATUS_CLAIM_DENIED->value, ];

🤖 AI-Powered Customer Notifications

🧠 InstantWriter AI Integration

The Claims Management System integrates with InstantWriter AI to optimize customer communication messages before sending notifications.

1. Draft Message
Claims manager writes initial message
2. AI Optimization
InstantWriter AI enhances message
3. Review & Send
Manager reviews and sends notification
4. Status Update
Sub-status updated automatically
// ClaimsService::optimizeMessageWithAI() method public function optimizeMessageWithAI(string $message, string $claimUuid) { $apiData = [ 'original_message' => $message, 'claim_reference' => $claimUuid, ]; try { return InstantWriterAIFacade::request('/message-optimizer/optimize', 'post', $apiData); } catch (\Exception $e) { LoggerService::error(self::class.'::'.__FUNCTION__.' - Error optimizing message', [ 'error' => $e->getMessage(), 'message' => $message, ]); throw $e; } }

📧 Notification Workflow

  1. Message Creation: Claims manager drafts customer message
  2. AI Optimization: Optional AI enhancement via InstantWriter API
  3. Validation: ClaimSendNotificationRequest validates both messages and sub-status
  4. Status Update: Sub-status updated and closure logic evaluated
  5. Activity Logging: ClaimActivity record created with both messages
  6. Customer Notification: Message sent to customer via preferred channel
