🏗️ Claims System Architecture & Structure

Comprehensive technical documentation of the claims management system architecture

📊 System Architecture Overview

The Claims Management System follows a layered architecture pattern with clear separation of concerns, implementing Laravel best practices and modern Vue.js frontend integration.

🏛️ Layered Architecture

Frontend Layer (Vue.js 3 + Inertia.js)

Modern reactive frontend with Composition API, component-based architecture, and real-time updates

  • Vue 3 with Composition API and <script setup> syntax
  • Inertia.js for seamless Laravel-Vue integration
  • TailwindCSS for responsive styling
  • Component-based architecture with 12+ specialized components
  • Permission-based UI rendering with useCan() composables

Controller Layer (Laravel Controllers)

HTTP request handling, middleware integration, and response formatting

  • ClaimsController with 25+ methods for comprehensive CRUD operations
  • Permission-based middleware with 11 specific claim permissions
  • Request validation with Form Request classes
  • Error handling with comprehensive logging
  • Inertia responses for web routes, JSON for AJAX endpoints

Service Layer (Business Logic)

Core business logic, external integrations, and data processing

  • ClaimsService with 30+ methods for business operations
  • CPAPI integration for claim creation only
  • InstantWriter AI integration for message optimization
  • Azure S3 integration for document management
  • Complex filtering and pagination logic

Model Layer (Eloquent ORM)

Data models with relationships, business logic, and database interactions

  • ClaimRequest - Main model with 25+ relationships
  • ClaimRequestDetail - LOB-specific details
  • ClaimActivity - Status change tracking
  • Comprehensive audit logging with OwenIt/Auditing
  • Soft deletes and UUID-based routing

Database Layer (MySQL)

Data persistence with optimized queries and relationships

  • Primary tables: claim_requests, claim_request_details, claim_activities
  • Lookup tables: lookups, claim_statuses, quote_types
  • Audit tables for comprehensive change tracking
  • Optimized indexes for performance
  • Foreign key constraints for data integrity

ClaimRequest Model

  • Location: app/Models/ClaimRequest.php
  • Table: claim_requests with 30+ fillable fields
  • Relationships: 10+ relationships (customer, manager, quoteType, claimStatus, etc.)
  • Traits: Auditable, FilterCriteria, HasFactory
  • Business Methods: assignManager(), updateStatus(), setWhatsAppConsent(), updateComplaintStatus(), updateNextFollowUp()
  • Scopes: scopeAssignedTo(), scopeUnassigned(), scopeByQuoteType(), scopeByStatus(), scopeBySource(), scopeWithWhatsAppConsent()
  • Accessors: getFullNameAttribute(), getIsAssignedAttribute(), getDisplayCreatedAtAttribute()
  • Filterables: 18 filterable fields with FilterTypes (EXACT, IN, DATE_BETWEEN)
  • Boot Logic: Auto-sets source='IMCRM', whatsapp_consent=false

ClaimRequestDetail Model

  • Location: app/Models/ClaimRequestDetail.php
  • Table: claim_request_details (1:1 with ClaimRequest)
  • Car Fields: plate_number, car_make, car_model, model_year
  • Health Fields: service_type_id, request_reference_number
  • Tracking: user_ip for audit purposes
  • Relationships: belongsTo ClaimRequest, belongsTo Lookup (serviceType)
  • Methods: updateVehicleInfo(), updateServiceType()
  • Accessors: getVehicleInfoAttribute(), getHasVehicleInfoAttribute()

Activities Model

  • Location: app/Models/Activities.php
  • Table: activities (1:* with ClaimRequest)
  • Fields: claim_request_id, claim_status_id, created_by_id, comment, comment_ai
  • AI Support: comment_ai field for AI-optimized messages
  • Relationships: belongsTo ClaimRequest, ClaimStatus, User
  • Scopes: scopeForClaimRequest(), scopeForClaimUuid(), scopeByStatus(), scopeCreatedBy()
  • Factory: Static createForClaim() method for easy creation

QuoteDocument Model

  • Purpose: Polymorphic document management
  • Features: S3 integration, temporary URLs
  • Types: Claim documents, policy documents
  • Security: Access control, audit logging
  • Operations: Upload, download, delete, bulk operations
  • Storage: Azure S3 with CDN integration

🗄️ Database Schema

claim_requests Table

  • Primary Key: id (auto-increment)
  • UUID: uuid (for secure routing)
  • Code: code (human-readable reference)
  • Customer Info: first_name, last_name, email, mobile_no, customer_id
  • Claim Details: incident, incident_date, claim_number, claim_decline_reason
  • Status Fields: claim_status_id, claim_sub_status_id, complaint_status_id
  • LOB Fields: quote_type_id, claim_type_id, claim_request_type_id
  • Financial: approved_repair_amount, approved_total_loss_amount, approved_cash_loss_amount
  • Management: manager_id, manager_assigned_date
  • Quote Integration: quote_uuid, personal_quote_id, insurance_provider_id, policy_number
  • Complaint Fields: complaint_datetime, complaint_notes
  • Follow-up: next_followup_datetime, next_followup_notes
  • Tracking: source (default: 'IMCRM'), whatsapp_consent (default: false)
  • Timestamps: created_at, updated_at

claim_request_details Table

  • Primary Key: id (auto-increment)
  • Foreign Key: claim_request_id (1:1 relationship)
  • Car Details: car_make, car_model, model_year, plate_number
  • Health Details: service_type_id, request_reference_number
  • Tracking: user_ip (for audit purposes)
  • Timestamps: created_at, updated_at

activities Table

  • Primary Key: id (auto-increment)
  • Foreign Keys: claim_request_id, claim_status_id, created_by_id
  • Content: comment, comment_ai (AI-optimized messages)
  • Tracking: claim_uuid (for easy lookup)
  • Timestamps: created_at, updated_at

lookups Table

  • Purpose: Centralized configuration storage
  • Types: claim-statuses, claim-types, claim-request-types, service-types
  • Fields: id, code, text, description, parent_id
  • Hierarchy: Parent-child relationships for sub-categories
  • Usage: Dropdown options, validation rules, LOB-specific configurations
  • Examples: Car sub-statuses, Health service types, Life claim types

quote_documents Table

  • Purpose: Polymorphic document storage
  • Polymorphic: quote_documentable_type, quote_documentable_id
  • Document Info: original_name, file_path, file_size, mime_type
  • Type Classification: document_type_id, document_type_code
  • Storage: Azure S3 integration with temporary URLs
  • Security: Access control, audit logging
  • Timestamps: created_at, updated_at

audits Table

  • Purpose: Comprehensive audit logging via OwenIt/Auditing
  • Polymorphic: auditable_type, auditable_id
  • Change Tracking: old_values, new_values, event
  • User Tracking: user_id, user_type
  • Metadata: url, ip_address, user_agent
  • Timestamps: created_at
  • Coverage: All model changes, status updates, document operations

🔧 Service Layer Architecture

ClaimsService

  • Location: app/Services/ClaimsService.php
  • Inheritance: Extends BaseService, uses CentralTrait
  • Properties: $searchPrefix='claims.', $query (ClaimRequest with eager loading), $perPage=15
  • Constructor: Builds optimized query with 25+ selected fields and 8+ eager loaded relationships
  • Methods: 30+ business logic methods for CRUD, filtering, integrations
  • Integrations: CustomerPortalApiFacade (creation only), InstantWriterAIFacade, Azure S3
  • Performance: Specific field selection, eager loading, simplePaginate()

Key Service Methods

  • getClaimsData(): Main listing with 18+ filterable fields, pagination
  • getClaimsDataForExport(): Export data with same filtering logic
  • createClaim(): CPAPI integration for initial creation only (15+ data fields)
  • updateClaimStatus(): Status updates with Activity logging
  • sendNotification(): AI-optimized messaging via InstantWriterAIFacade
  • uploadClaimDocuments(): Azure S3 document management
  • getDropdownData(): Form options (statuses, types, providers)
  • searchPolicies(): Internal policy search logic (not CPAPI)

External Integrations

  • CustomerPortalApiFacade: Claim creation only (/api/claims/save-claim)
  • InstantWriterAIFacade: Message optimization for customer communications
  • Azure S3: Document storage with temporary URLs, CDN integration
  • Policy Search: Handled internally within current system (not via CPAPI)
  • Error Handling: Try-catch blocks with LoggerService for all integrations
  • Data Filtering: array_filter() to remove null values before API calls
  • Response Handling: Success/failure checking with proper error propagation

Business Logic Patterns

  • LOB Validation: Car, Health, Life specific rules
  • Status Transitions: Automatic workflow management
  • Closure Logic: LOB-specific closure detection
  • Permission Checks: Role-based access control
  • Audit Logging: Comprehensive change tracking
  • Data Integrity: Validation and constraints

🎨 Frontend Architecture

Vue.js 3 Architecture

  • Framework: Vue 3.5.x with Composition API
  • Integration: Inertia.js for Laravel-Vue bridge
  • Styling: TailwindCSS with responsive design
  • Components: Auto-import via unplugin-vue-components
  • State: Reactive data with VueUse composables
  • Build: Vite with HMR and optimization

Component Structure

  • Show.vue: Main claim details page with 12+ imported components
  • Index.vue: Claims listing with 15+ table columns, filters, export functionality
  • Create.vue: Claim creation form with policy search integration
  • Edit.vue: Claim editing interface with validation
  • Form.vue: Reusable form component with LOB-specific fields
  • Components/: 12+ specialized components in dedicated folder

Key Components

  • ClaimDetails.vue: Main claim information display
  • ClaimStatus.vue: Status management with permission checks
  • ClaimSubStatusAndCustomerUpdate.vue: Sub-status and customer updates
  • ClaimDocuments.vue: Document management with S3 integration
  • CustomerDetails.vue: Customer information display
  • NextFollowUpUpdate.vue: Follow-up scheduling with datetime picker
  • ComplaintStatus.vue: Complaint status management
  • History Components: ClaimLeadHistory, ClaimSubStatusLogs, NextFollowUpLogs, ComplaintStatusLogs

Frontend Patterns

  • Permission-Based UI: useCan(), useCanAny(), useHasAnyRole() composables
  • Event-Driven: @documentUploaded, @documentDeleted, @update events
  • Form Validation: Client-side validation with reactive forms
  • Error Handling: useToast() notifications, NProgress loading
  • Real-time Updates: Inertia.js partial reloads, preserve-scroll
  • State Management: Reactive refs, computed properties, reactive() objects
  • Utilities: useClipboard(), formattedDateDmyWithTime(), calculateDaysDifference()
  • Table Management: EasyDataTable with 15+ columns, sorting, filtering

🔐 Security & Permissions

Permission System

  • CLAIM_LIST: View claims listing (Index.vue)
  • CLAIM_CREATE: Create new claims (Create.vue)
  • CLAIM_EDIT: Edit existing claims (Edit.vue)
  • CLAIM_SHOW: View individual claims (Show.vue)
  • CLAIMS_EXPORT_DATA: Export claim data (Index.vue export functionality)
  • CLAIMS_STATUS_UPDATE: Update claim status (ClaimStatus.vue)
  • CLAIMS_SUB_STATUS_UPDATE: Update sub-status (ClaimSubStatusAndCustomerUpdate.vue)
  • CLAIM_DOCUMENT_UPLOAD: Upload documents (ClaimDocuments.vue)
  • CLAIM_DOCUMENT_DELETE: Delete documents (ClaimDocuments.vue)
  • CLAIM_DOCUMENT_S3_URL: Get S3 URLs (ClaimDocuments.vue)
  • CLAIM_DOWNLOAD_ALL_DOCUMENTS: Bulk download (ClaimDocuments.vue)

Security Features

  • UUID Routing: Secure route model binding with claim.uuid
  • CSRF Protection: Laravel CSRF tokens in all forms
  • Input Validation: Form Request validation with prepareForValidation()
  • SQL Injection Prevention: Eloquent ORM with parameterized queries
  • XSS Protection: Output escaping in Vue templates
  • Audit Logging: OwenIt/Auditing package with comprehensive tracking
  • Soft Deletes: Data recovery capability with deleted_at
  • IP Tracking: user_ip field in ClaimRequestDetail for audit

Data Protection

  • Soft Deletes: Data recovery capability with deleted_at timestamps
  • Audit Trail: Complete change history via OwenIt/Auditing
  • Access Control: Role-based permissions with Spatie Permission
  • Document Security: Azure S3 access controls with temporary URLs
  • API Security: Rate limiting and throttling on external APIs
  • Data Validation: Form Request classes with comprehensive validation rules
  • LoggerService: Structured logging for all operations

Middleware Stack

  • Authentication: Laravel auth middleware on all routes
  • Permission: Spatie Permission package with specific claim permissions
  • CSRF: Cross-site request forgery protection on forms
  • Throttling: Rate limiting for API endpoints
  • Logging: LoggerService for request/response logging
  • Error Handling: Try-catch blocks with graceful error responses
  • Route Model Binding: UUID-based secure routing
