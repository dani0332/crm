🆕 Claim Creation Process

Comprehensive guide to creating new insurance claims with CAPI integration

📋 Overview

The claim creation process is the entry point for all new insurance claims in the system. It involves policy search and verification through CAPI integration, customer information validation, LOB-specific field collection, and initial claim registration with automatic status assignment.

📝 LOB-Specific Validation Rules

Each Line of Business has unique validation requirements enforced through the ClaimStoreRequest validation class.

🚗 Motor/Car & Bike Claims

  • Plate Number: Required, regex pattern /^[A-Za-z0-9\-\s]+$/
  • Car Make: Required string, max 100 characters
  • Car Model: Required string, max 100 characters
  • Model Year: Required integer, range 1900 to current year + 1
  • Interdependency: If any vehicle field is provided, all must be provided
  • Auto-formatting: Plate number converted to uppercase
  • Shared Logic: Car and Bike use identical validation (isCarOrBikeLOB method)

🏥 Health & Group Medical Claims

  • Claim Request Type: Required (reimbursement, pending-approvals, ask-a-question)
  • Service Type: Required for pending-approvals type
  • Service Types: In-patient or Out-patient requests
  • Reference Number: Optional for tracking purposes
  • Conditional Logic: Service type validation based on request type
  • Lookup Validation: All IDs validated against lookups table
  • Group Medical: Corporate health insurance with additional validation

💼 Life Claims

  • Standard Fields: Basic claim information only
  • Simplified Validation: No LOB-specific required fields
  • Policy Information: Policy number and incident details
  • Incident Date: Required, must be before today
  • Claim Type: Selected from available life claim types
  • Processing: Direct path to claim processing

🏠 Other LOBs (Home, Travel, Pet, etc.)

  • Standard Processing: Basic claim workflow without complex validation
  • Supported LOBs: Home, Travel, Yacht, Pet, Cycle, Jetski, Business, CorpLine, Savings
  • Common Fields: Policy number, incident date, incident story
  • Document Types: LOB-specific document requirements from lookups
  • Status Flow: Standard Open → Closed workflow
  • Validation: Basic field validation without LOB-specific business rules

⚠️ Data Preparation & Normalization

The prepareForValidation() method automatically:

  • Converts plate number to uppercase

🔄 Claim Creation Workflow

⚙️ ClaimsService::createClaim() Implementation

public function createClaim(array $data): array { try { // Prepare API data for CAPI integration $apiData = [ 'firstName' => $data['first_name'] ?? null, 'lastName' => $data['last_name'] ?? null, 'email' => $data['email'] ?? null, 'mobileNo' => $data['mobile_no'] ?? null, 'incident' => $data['incident_story'] ?? null, 'incidentDate' => $data['incident_date'] ?? null, 'customerId' => $data['customer_id'] ?? null, 'policyNumber' => $data['policy_number'] ?? null, 'insuranceProviderId' => $data['insurance_provider_id'] ?? null, 'quoteTypeId' => $data['quote_type_id'] ?? null, 'source' => $data['source'] ?? config('constants.SOURCE_NAME', 'IMCRM'), // LOB-specific fields added based on quote type ]; // Remove null values and make CAPI request $apiData = array_filter($apiData, fn($value) => !is_null($value)); $response = CustomerPortalApiFacade::request('/api/claims/save-claim', 'post', $apiData); return $response->data; } catch (\Exception $e) { // Comprehensive error logging LoggerService::error(self::class.'::'.__FUNCTION__.' - Error creating claim request', [ 'error' => $e->getMessage(), 'data' => $data, 'api_data' => $apiData ?? null, ]); throw $e; } }
Data Filtering Null values removed before API call
Source Assignment Default source set to 'IMCRM' if not provided
LOB Field Addition Car and Health specific fields added conditionally
Error Logging Comprehensive logging with context data

🎯 Observer Pattern Integration

🔄 Automatic Status Assignment

Upon claim creation, the ClaimRequestObserver automatically sets the initial sub-status based on LOB:

// ClaimRequestObserver::creating() method public function creating(ClaimRequest $claimRequest): void { $claimsService = new ClaimsService; // If claim number is provided during creation, set status to "Claim registered" if (!empty($claimRequest->claim_number)) { $claimsService->updateClaimSubStatusToClaimRegistered($claimRequest); } }

🚗 Motor Claims Initial Status

  • Default: "New claim"
  • With Claim Number: "Claim registered and awaiting inspection"
  • Auto-Assignment: Based on QuoteTypeId::Car detection

🏥 Health Claims Initial Status

  • Default: "New claim" or "New request" based on type
  • With Claim Number: "Claims registered"
  • Request-Specific: Different flows for reimbursement vs approvals

💼 Life Claims Initial Status

  • Default: "New claim"
  • With Claim Number: "Claims registered"
  • Simplified Flow: Direct path to processing
