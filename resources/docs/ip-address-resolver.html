🌐 IP Address Resolver

Custom IP address resolution from request headers for accurate audit logging behind proxies

❓ What is the IP Address Resolver?

The application runs behind Nginx (and other proxies) in Docker and production environments. Without custom handling, audit logs would record the proxy/server IP instead of the real client IP. The IpAddressResolver resolves the client IP from forwarded headers and is used by OwenIt\Auditing (Laravel Audit) so that audit records store the correct user IP.

💡 Why This Matters

Audit trail accuracy: Compliance and security reviews require knowing which IP addresses performed actions. With a single proxy (e.g. Nginx), X-Real-IP or X-Forwarded-For carry the real client IP; the resolver reads these headers in a defined order and validates IPs to avoid spoofing before returning a value. Laravel's Request::ip() is used as fallback and respects the TrustProxies middleware.

🔄 IP Resolution Order

The resolver checks sources in the following order. The first valid public IP is returned.

1

X-Real-IP

Single header, most reliable when one proxy (e.g. Nginx) sits in front of the app.

2

X-Forwarded-For

May contain multiple IPs (client, proxy1, proxy2). First valid public IP in the chain is used.

3

Request::ip()

Laravel's default, which respects TrustProxies middleware and REMOTE_ADDR.

Security: IP Validation

🔒 Public IPs Only

For X-Real-IP and X-Forwarded-For, the resolver uses filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE) so that only valid, non-private, non-reserved addresses are accepted from headers. This reduces the risk of clients spoofing private IPs. If no valid public IP is found in headers, the code falls back to $request->ip(), which is already trusted by the framework after TrustProxies runs.

🛠️ Components

1. IpAddressResolver (app/Resolvers/IpAddressResolver.php)

📌 Purpose

  • Implements OwenIt\Auditing\Contracts\Resolver
  • Used by Laravel Audit as the ip_address resolver
  • Returns a string IP for the current request

🔑 Logic

  • Reads X-Real-IP first; returns if valid public IP
  • Else parses X-Forwarded-For (comma-separated), returns first valid public IP
  • Else returns Request::instance()->ip()
// Simplified resolution logic $request = Request::instance(); if ($realIp = $request->header('X-Real-IP')) { if (filter_var($realIp, FILTER_VALIDATE_IP, FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE)) { return $realIp; } } if ($forwardedFor = $request->header('X-Forwarded-For')) { $ips = array_map('trim', explode(',', $forwardedFor)); foreach ($ips as $ip) { if (filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE)) { return $ip; } } } return $request->ip();

2. Audit Configuration (config/audit.php)

The audit package is configured to use the custom resolver for the ip_address field:

'resolver' => [ 'user' => OwenIt\Auditing\Resolvers\UserResolver::class, 'ip_address' => App\Resolvers\IpAddressResolver::class, 'user_agent' => OwenIt\Auditing\Resolvers\UserAgentResolver::class, 'url' => OwenIt\Auditing\Resolvers\UrlResolver::class, ],

3. TrustProxies Middleware (app/Http/Middleware/TrustProxies.php)

Laravel must trust the proxy IPs so that Request::ip() and header handling work correctly. The following proxies/CIDRs are configured:

Proxy / CIDR Environment
127.0.0.1 Localhost
172.16.0.0/12 Docker default bridge network
10.0.0.0/8 Private network range
192.168.0.0/16 Private network range
172.19.0.0/16 UAT Server
172.27.0.0/16 Test Server
172.20.0.0/16 Staging Server 1
172.22.0.0/16 Staging Server 2
172.18.0.0/16 PROD Server

4. Nginx Configuration

Nginx must pass the client IP and scheme to PHP-FPM so the application and resolver see the correct values. The following FastCGI params are set in docker/nginx.conf, docker/stg_nginx.conf, and docker/uat_nginx.conf:

# Set real IP headers for proper IP forwarding fastcgi_param HTTP_X_REAL_IP $remote_addr; fastcgi_param HTTP_X_FORWARDED_FOR $proxy_add_x_forwarded_for; fastcgi_param HTTP_X_FORWARDED_PROTO $scheme; fastcgi_param REMOTE_ADDR $remote_addr;

📌 Headers Passed

  • X-Real-IP: Nginx $remote_addr (client IP as seen by Nginx)
  • X-Forwarded-For: Nginx $proxy_add_x_forwarded_for (append to existing chain if any)
  • X-Forwarded-Proto: $scheme (http/https)
  • REMOTE_ADDR: $remote_addr (for Laravel request)

✅ Summary

  • Audit: Custom App\Resolvers\IpAddressResolver prioritises X-Real-IP, then X-Forwarded-For (first valid public IP), then Request::ip().
  • Config: config/audit.php uses the custom resolver for the ip_address resolver key.
  • Proxies: TrustProxies middleware defines trusted proxies/CIDRs for local, Docker, UAT, Test, Staging, and Prod.
  • Nginx: Docker Nginx configs pass X-Real-IP, X-Forwarded-For, X-Forwarded-Proto, and REMOTE_ADDR to PHP-FPM.
