❓ What is Policy Issuance Automation?

The Policy Issuance Automation system is a comprehensive, modular architecture designed to automate the complete policy issuance workflow with insurance providers. It provides a standardized interface for integrating multiple insurers across different Lines of Business (LOB) - Health, Car, and Travel.

💳 Pre-Automation Payment Capture

Auto-capture is a critical prerequisite step that happens BEFORE the automation workflow begins:

✓ Payment Flow: Customer pays online → Payment authorized → Background job processes split payment approval
✓ Auto-Capture Executes: System captures authorized payment via Marshall/Tap API before automation starts
✓ Success Path: If capture succeeds → Automation workflow is scheduled (createPolicyIssuanceAutomation())
✓ Failure Path: If capture fails → Quote marked with AUTO_CAPTURE_FAILED status and allocated to team for manual handling
✓ Implementation: Located in SplitPaymentService->processSplitPaymentApprove() (lines 770-792, 1475-1487)
✓ Retry Logic: Up to 3 attempts with 1-second delay between retries
✓ Provider Support: Currently implemented for GIG (AXA) and potentially other providers

Note: This explains why documentation refers to "pre-captured" payments - the payment is already captured before any automation steps execute.

💡 Why This System?

Policy Issuance Automation eliminates manual processing and reduces errors. The system:

✓ Automates the entire lifecycle from quote to booked policy
✓ Provides consistent error handling with retry mechanisms for transient failures
✓ Enables seamless integration with multiple insurance providers through a common interface
✓ Maintains data integrity with comprehensive audit trails throughout automation
✓ Handles documents automatically with upload/download and Azure storage integration
✓ Tracks status in real-time with detailed logging at each step
✓ Processes asynchronously using queue-based jobs for scalability

🏢 Lines of Business (LOB) & Insurance Providers

Automated policy issuance across multiple insurance providers and product lines

🏥 Health Insurance

Comprehensive health insurance policy automation with individual and group coverage

  • 📋 ADNIC Health - 3-step automation (STP only)
Automation Steps (3 steps):
  • Upload Documents (per-member)
  • Issue Policy (with payment reference)
  • Upload Policy Documents to IMCRM

Note: STP cases only. Payment pre-captured. Booking handled separately.

🚗 Car Insurance

Motor insurance policy automation for comprehensive and third-party coverage

  • 📋 GIG (AXA) Car - 5-step automation with OCR processing
  • 📋 Liva (RSA) Car - 4-step automation with timeout handling
Automation Steps:
  • GIG: 5 steps (Upload → Issue → Get Docs → OCR → Book)
  • Liva: 4 steps (Upload → Issue → Get Docs → Book)

Key Differences: GIG uses OAuth2 + OCR batch processing. Liva uses double base64 decode + timeout detection.

✈️ Travel Insurance

Travel insurance policy automation for individual and family coverage

  • 📋 Alliance Travel - 5-step automation workflow
Automation Steps:
  • Issue Policy (Inbound/Outbound)
  • Purchase Policy
  • Upload Policy Documents
  • Fill Policy Booking Details
  • Book Policy to Sage

🛠️ System Architecture Overview

Modular, provider-agnostic architecture with standardized interface and comprehensive logging

Interface Layer PolicyIssuanceInterface defines contract for all providers
Service Layer 10+ specialized services per provider (orchestrator, executor, API, validation)
HTTP Layer Dedicated HTTP client with timeout and retry configuration
Validation Layer Pre-validation before API calls to prevent unnecessary failures
Document Layer Automated document fetch from Azure, upload to insurer and IMCRM
Response Layer Normalized response parsing with standardized error handling
Logging Layer Comprehensive audit trails with LoggerService integration
Queue Layer Asynchronous job processing with retry mechanisms
