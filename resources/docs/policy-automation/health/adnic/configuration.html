⚙️ Configuration Management

Complete guide to configuring ADNIC Health Policy Issuance Automation

Production Ready

1. Environment Configuration

All ADNIC API credentials and base URLs are configured through environment variables and accessed via config/constants.php.

1.1 Environment Variables (.env)

Add the following variables to your .env file:

# ADNIC API Configuration ADNIC_API_BASE_URL=https://api.adnic.ae ADNIC_PARTNER_ID=your_partner_id ADNIC_PARTNER_REFERENCE_NO=your_reference_number ADNIC_AUTHORIZATION_TOKEN=Bearer your_token_here ADNIC_SUBSCRIPTION_KEY=your_subscription_key # Azure Storage (for document management) AZURE_IM_STORAGE_URL=https://yourstorage.blob.core.windows.net AZURE_IM_STORAGE_CONTAINER=your_container_name

1.2 Constants Configuration (config/constants.php)

The following ADNIC constants are defined in config/constants.php:

Constant Key Environment Variable Purpose Required
ADNIC_API_BASE_URL ADNIC_API_BASE_URL Base URL for ADNIC API endpoints ✅ Yes
ADNIC_PARTNER_ID ADNIC_PARTNER_ID Partner identification for API authentication ✅ Yes
ADNIC_PARTNER_REFERENCE_NO ADNIC_PARTNER_REFERENCE_NO Partner reference number for API requests ✅ Yes
ADNIC_AUTHORIZATION_TOKEN ADNIC_AUTHORIZATION_TOKEN Bearer token for API authentication ✅ Yes
ADNIC_SUBSCRIPTION_KEY ADNIC_SUBSCRIPTION_KEY Azure API Management subscription key ✅ Yes
// config/constants.php return [ // ... other constants // Adnic Policy Issuance API Credentials 'ADNIC_API_BASE_URL' => env('ADNIC_API_BASE_URL'), 'ADNIC_PARTNER_ID' => env('ADNIC_PARTNER_ID'), 'ADNIC_PARTNER_REFERENCE_NO' => env('ADNIC_PARTNER_REFERENCE_NO'), 'ADNIC_AUTHORIZATION_TOKEN' => env('ADNIC_AUTHORIZATION_TOKEN'), 'ADNIC_SUBSCRIPTION_KEY' => env('ADNIC_SUBSCRIPTION_KEY'), ];

Use Laravel's config() helper to access these values:

$baseUrl = config('constants.ADNIC_API_BASE_URL'); $token = config('constants.ADNIC_AUTHORIZATION_TOKEN');

2. Runtime Configuration via ApplicationStorage

Runtime configuration allows you to enable/disable features and adjust settings without code deployment. All runtime settings are stored in the application_storage table and accessed via ApplicationStorageService.

2.1 Feature Toggles

Storage Key Enum Constant Purpose Type Default
ENABLE_ADNIC_HEALTH_POLICY_ISSUANCE ApplicationStorageEnums::ENABLE_ADNIC_HEALTH_POLICY_ISSUANCE Master switch to enable/disable automation boolean false
ENABLE_RETRY_TIMEOUT_ADNIC_HEALTH_POLICY_ISSUANCE ApplicationStorageEnums::ENABLE_RETRY_TIMEOUT_ADNIC_HEALTH_POLICY_ISSUANCE Enable retry mechanism for timeout failures boolean false
ADNIC_HEALTH_AUTOMATION_API_TIMEOUT ApplicationStorageEnums::ADNIC_HEALTH_AUTOMATION_API_TIMEOUT API timeout in seconds for HTTP requests integer 30

2.2 Accessing Runtime Configuration

use App\Services\ApplicationStorageService; use App\Enums\ApplicationStorageEnums; // Check if automation is enabled public function isPolicyIssuanceAutomationEnabled(): bool { return app(ApplicationStorageService::class) ->getValueByKey(ApplicationStorageEnums::ENABLE_ADNIC_HEALTH_POLICY_ISSUANCE); } // Get API timeout private int $apiTimeout = (int) app(ApplicationStorageService::class) ->getValueByKey(ApplicationStorageEnums::ADNIC_HEALTH_AUTOMATION_API_TIMEOUT); // Check retry enabled public function isPolicyIssuanceAutomationRetryEnabledForTimeout(): bool { return (bool) app(ApplicationStorageService::class) ->getValueByKey(ApplicationStorageEnums::ENABLE_RETRY_TIMEOUT_ADNIC_HEALTH_POLICY_ISSUANCE); }

💡 Runtime Configuration Benefits

  • Enable/disable automation without code deployment
  • Adjust API timeouts based on network conditions
  • Control retry mechanisms for troubleshooting
  • A/B testing capabilities
  • Emergency shutdown capability

4. Feature Toggle Management

Feature toggles provide runtime control over automation functionality without requiring code deployment.

4.1 Enabling/Disabling Automation

To enable or disable the automation, update the application_storage table:

-- Enable automation UPDATE application_storage SET value = '1' WHERE key = 'ENABLE_ADNIC_HEALTH_POLICY_ISSUANCE'; -- Disable automation UPDATE application_storage SET value = '0' WHERE key = 'ENABLE_ADNIC_HEALTH_POLICY_ISSUANCE';

4.2 Checking Feature Toggle Status

use App\Services\ApplicationStorageService; use App\Enums\ApplicationStorageEnums; // In AdnicInsuranceService public function isPolicyIssuanceAutomationEnabled(): bool { return app(ApplicationStorageService::class) ->getValueByKey(ApplicationStorageEnums::ENABLE_ADNIC_HEALTH_POLICY_ISSUANCE); } // Usage in automation flow if (!$this->isPolicyIssuanceAutomationEnabled()) { LoggerService::warning('Automation is disabled', extra: [ 'toggle' => ApplicationStorageEnums::ENABLE_ADNIC_HEALTH_POLICY_ISSUANCE, ]); return false; }

💡 Feature Toggle Best Practices

  • Always check feature toggle before executing automation
  • Log when automation is disabled for monitoring
  • Use feature toggles for gradual rollout
  • Monitor toggle status in application logs
  • Document toggle changes in deployment notes

5. Retry Mechanism Configuration

The retry mechanism handles timeout failures and transient errors by automatically retrying failed operations.

5.1 Enabling Retry for Timeouts

-- Enable retry mechanism UPDATE application_storage SET value = '1' WHERE key = 'ENABLE_RETRY_TIMEOUT_ADNIC_HEALTH_POLICY_ISSUANCE';

5.2 Checking Retry Status

public function isPolicyIssuanceAutomationRetryEnabledForTimeout(): bool { return (bool) app(ApplicationStorageService::class) ->getValueByKey(ApplicationStorageEnums::ENABLE_RETRY_TIMEOUT_ADNIC_HEALTH_POLICY_ISSUANCE); } // Usage in error handling if ($this->isPolicyIssuanceAutomationRetryEnabledForTimeout() && $isTimeout) { // Mark process for retry $process->update(['status' => PolicyIssuanceEnum::TIMEOUT_STATUS]); LoggerService::info('Process marked for retry due to timeout'); }

⚠️ Retry Considerations

When enabling retry mechanisms:

  • Monitor retry attempts to prevent infinite loops
  • Set maximum retry limits
  • Log all retry attempts for debugging
  • Consider exponential backoff for retries
  • Review failed retries regularly

6. API Timeout Settings

API timeout configuration controls how long the system waits for API responses before timing out.

6.1 Configuring API Timeout

-- Set API timeout to 60 seconds UPDATE application_storage SET value = '60' WHERE key = 'ADNIC_HEALTH_AUTOMATION_API_TIMEOUT';

6.2 Using Timeout in HTTP Client

// In AdnicHttpClient constructor public function __construct() { $this->apiTimeout = (int) app(ApplicationStorageService::class) ->getValueByKey(ApplicationStorageEnums::ADNIC_HEALTH_AUTOMATION_API_TIMEOUT); // ... other initialization } // Applying timeout to HTTP requests public function post(string $endPoint, array $payload = [], array $headers = []): Response { return Http::timeout($this->apiTimeout) ->withHeaders($this->baseHeaders) ->post($url, $payload); }

6.3 Recommended Timeout Values

API Endpoint Recommended Timeout Reason
Generate Policy 60 seconds Policy generation may take longer
Upload Document 45 seconds Document upload depends on file size
Download Document 45 seconds Document download depends on file size

💡 Timeout Best Practices

  • Set timeouts based on API response time expectations
  • Consider network latency and document sizes
  • Monitor timeout occurrences in logs
  • Adjust timeouts based on production metrics
  • Use retry mechanism for timeout failures

8. Service Provider Registration

Service providers register ADNIC services with Laravel's service container for dependency injection.

8.1 AdnicServiceProvider Implementation

// app/Providers/AdnicServiceProvider.php namespace App\Providers; use App\Services\PolicyIssuanceAutomation\Health\Adnic\AdnicBookPolicyService; use App\Services\PolicyIssuanceAutomation\Health\Adnic\AdnicHttpClient; use App\Services\PolicyIssuanceAutomation\Health\Adnic\AdnicInsuranceService; use App\Services\PolicyIssuanceAutomation\Health\Adnic\AdnicResponseHandler; use App\Services\PolicyIssuanceAutomation\Health\Adnic\AdnicStepExecutor; use App\Services\PolicyIssuanceAutomation\Health\Adnic\AdnicValidationService; use Illuminate\Support\Facades\App; use Illuminate\Support\ServiceProvider; class AdnicServiceProvider extends ServiceProvider { /** * Register services. */ public function register(): void { App::bind('AdnicHttpClient', function () { return new AdnicHttpClient; }); } /** * Bootstrap services. */ public function boot(): void { App::bind(AdnicInsuranceService::class, function ($app) { return new AdnicInsuranceService( $app->make(AdnicStepExecutor::class), $app->make(AdnicValidationService::class), $app->make(AdnicBookPolicyService::class), $app->make(AdnicResponseHandler::class), ); }); } }

8.2 Registering in config/app.php

💡 Service Provider Benefits

9. Facade Registration

Facades provide a static interface to HTTP client services, simplifying API calls throughout the application.

9.1 AdnicHttpFacade Implementation

// app/Facades/AdnicHttpFacade.php namespace App\Facades; use App\Services\PolicyIssuanceAutomation\Health\Adnic\AdnicHttpClient; use Illuminate\Support\Facades\Facade; class AdnicHttpFacade extends Facade { protected static function getFacadeAccessor() { return AdnicHttpClient::class; } }

9.2 Using the Facade

use App\Facades\AdnicHttpFacade; // Make API call using facade $response = AdnicHttpFacade::post($endPoint, $payload, $headers); // Get base URL $baseUrl = AdnicHttpFacade::getBaseUrl();

9.3 Facade Methods

Method Parameters Return Type Purpose
post() string $endPoint, array $payload, array $headers Response Make POST request to ADNIC API
getBaseUrl() None string Get configured API base URL

💡 Facade Benefits

  • Simplified API calls without dependency injection
  • Static interface for HTTP operations
  • Easy to mock in tests
  • Consistent API across the application
  • Reduced boilerplate code

10. Configuration Management Best Practices

Follow these best practices to ensure secure, maintainable, and scalable configuration management.

10.1 Security Best Practices

  • Never commit secrets: Store all sensitive credentials in environment variables
  • Use .env.example: Document required environment variables without exposing values
  • Rotate credentials: Regularly update API tokens and keys
  • Restrict access: Limit who can modify application_storage configuration
  • Audit changes: Log all configuration changes for security auditing

10.2 Environment-Specific Configuration

// Use different values per environment // .env.local (Development) ADNIC_API_BASE_URL=https://api-dev.adnic.ae // .env.staging (Staging) ADNIC_API_BASE_URL=https://api-staging.adnic.ae // .env.production (Production) ADNIC_API_BASE_URL=https://api.adnic.ae

10.3 Configuration Validation

// Validate configuration on service initialization public function __construct() { $this->baseUrl = config('constants.ADNIC_API_BASE_URL'); if (empty($this->baseUrl)) { throw new \RuntimeException('ADNIC_API_BASE_URL is not configured'); } // ... validate other required configs }

10.4 Configuration Documentation

  • Document all configuration variables in README or architecture docs
  • Include default values and acceptable ranges
  • Document environment-specific requirements
  • Provide examples for common configurations
  • Update documentation when adding new configuration

10.5 Monitoring Configuration

  • Monitor feature toggle changes in application logs
  • Alert on configuration errors or missing values
  • Track timeout occurrences and adjust accordingly
  • Review retry success rates
  • Monitor API response times vs timeout settings

Properly test configuration to ensure the automation system works correctly with different settings.
