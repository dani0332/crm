1. AdnicInsuranceService Main Orchestrator

Purpose & Responsibilities:
  • Implements PolicyIssuanceInterface - Core contract for all insurance providers
  • Manages the overall automation flow and coordinates between different services
  • Tracks step progression and maintains automation state
  • Handles automation enablement checks via feature toggles
  • Determines next step based on completed steps
  • Manages UI step locking status for manual intervention

Key Methods:

createPolicyIssuanceSchedule($quote, $insurer): void

Initiates automation schedule. Checks if automation is enabled and creates PolicyIssuance record.

executeSteps($process): array

Main entry point for step execution. Validates required data and initiates step sequence.

executeStepSequence($quote, $process, string $nextStepToBeExecuted): array

Sequential step execution with state management. Executes steps in order until completion or failure.

getNextStep(?string $completedStep): ?string

Determines next step based on completed steps. Returns null if all steps completed.

isPolicyIssuanceAutomationEnabled(): bool

Feature toggle check. Retrieves runtime configuration from ApplicationStorageService.

getStepsLockingStatus($quote, bool $throughAutomation = false): array

UI locking status for manual intervention. Delegates to AdnicBookPolicyService.

Dependencies:
  • AdnicStepExecutor - Step execution logic
  • AdnicValidationService - Data validation
  • AdnicBookPolicyService - Booking process
  • AdnicResponseHandler - Response formatting
  • ApplicationStorageService - Feature toggles
  • PolicyIssuanceService - Core orchestration
  • LoggerService - Logging

Usage Example:

// Create automation schedule $adnicService = app(AdnicInsuranceService::class); $adnicService->createPolicyIssuanceSchedule($quote, $insurer); // Execute automation steps $process = PolicyIssuance::where('quote_id', $quote->id)->first(); $response = $adnicService->executeSteps($process); // Check automation status $isEnabled = $adnicService->isPolicyIssuanceAutomationEnabled(); $nextStep = $adnicService->getNextStep($process->completed_step);
Integration Points:
  • PolicyIssuanceInterface: Implements core interface contract
  • PolicyIssuanceService: Factory method creates instance via init()
  • PolicyIssuanceJob: Queue job calls executeSteps()
  • AdnicServiceProvider: Service container binding
  • ApplicationStorageService: Runtime feature toggle configuration

2. AdnicStepExecutor Step Execution Layer

Purpose & Responsibilities:
  • Executes individual automation steps using Command Pattern
  • Delegates to appropriate service methods based on step type
  • Updates automation status after each step completion
  • Handles step-specific error scenarios and logging
  • Maps step constants to handler methods

Step Handlers:

private array $stepHandlers = [ AdnicEnum::STEP_UPLOAD_DOCUMENTS => 'executeUploadDocumentsStep', AdnicEnum::STEP_ISSUE_POLICY => 'executeIssuePolicyStep', AdnicEnum::STEP_UPLOAD_POLICY_DOCS => 'executeUploadPolicyDocumentsStep', ];

Note: STEP_BOOK_POLICY constant exists but is not used in automation flow. Booking is handled separately outside automation.

Key Methods:

executeIssuePolicyStep($quote, $process): array

Executes policy issuance step. Calls AdnicApiService::issuePolicy() and handles response.

executeUploadDocumentsStep($quote, $process): array

Executes document upload step. Calls AdnicApiService::uploadDocuments() for all required documents.

executeUploadPolicyDocumentsStep($quote, $process): array

Executes policy document download and upload to IMCRM. Calls AdnicApiService::uploadPolicyDocumentsToIMCRM().

Dependencies:
  • AdnicApiService - API communication layer
  • PolicyIssuanceService - Status updates
  • LoggerService - Logging

Usage Example:

// Step executor is called internally by AdnicInsuranceService $stepExecutor = app(AdnicStepExecutor::class); // Execute specific step $response = $stepExecutor->executeIssuePolicyStep($quote, $process); if ($response['status']) { // Step completed successfully $process->update(['completed_step' => $response['completed_step']]); }
Integration Points:
  • AdnicInsuranceService: Calls step handlers via dynamic method invocation
  • AdnicApiService: Delegates API calls to appropriate methods
  • PolicyIssuanceService: Updates API issuance and insurer status on failures

3. AdnicApiService API Communication Layer

Purpose & Responsibilities:
  • Direct interaction with insurance provider APIs
  • Orchestrates API calls with proper payloads and headers
  • Stores API logs for audit trails via PolicyIssuanceService
  • Updates quote and payment data after successful API calls
  • Handles API response parsing and error handling
  • Coordinates document operations and quote updates

Key Methods:

issuePolicy($quote, $process, $healthInsurerRequestResponse): array

Creates policy with insurer. Builds payload, calls /GeneratePolicy endpoint, updates quote with policy details.

uploadDocuments($quote, $process, $healthInsurerRequestResponse): array

Uploads customer documents to insurer. Validates documents, fetches from Azure, converts to base64, uploads via /UploadDocument endpoint.

uploadPolicyDocumentsToIMCRM($quote, $process): array

Downloads policy documents from insurer and uploads to IMCRM. Calls /GeneratePolicyDocument endpoint, downloads base64 content, uploads to IMCRM.

Dependencies:
  • AdnicRequestBuilder - Payload construction
  • AdnicResponseHandler - Response parsing
  • AdnicDocumentHandler - Document operations
  • AdnicQuoteUpdaterService - Quote/payment updates
  • AdnicValidationService - Pre-validation
  • AdnicHttpFacade - HTTP client facade
  • PolicyIssuanceService - Log storage
  • LoggerService - Logging

Usage Example:

// Issue policy $apiService = app(AdnicApiService::class); $response = $apiService->issuePolicy($quote, $process, $quote->insurerGenerateQuoteRequestResponse); if ($response['status']) { $policyNumber = $response['data']->PolicyInfo->PolicyNo; // Policy issued successfully } // Upload documents $uploadResponse = $apiService->uploadDocuments($quote, $process, $quote->insurerGenerateQuoteRequestResponse); // Download and upload policy documents $docResponse = $apiService->uploadPolicyDocumentsToIMCRM($quote, $process);
Integration Points:
  • AdnicHttpFacade: Makes HTTP POST requests to ADNIC API endpoints
  • AdnicRequestBuilder: Builds API-specific payloads
  • AdnicResponseHandler: Parses and normalizes API responses
  • AdnicDocumentHandler: Fetches documents from Azure and uploads to IMCRM
  • AdnicQuoteUpdaterService: Updates quote and payment data after successful API calls
  • PolicyIssuanceService: Stores API logs for audit trails

4. AdnicHttpClient HTTP Layer

Purpose & Responsibilities:
  • Manages HTTP communication with insurance provider
  • Configures authentication, headers, and timeouts
  • Provides consistent error handling for HTTP errors
  • Centralizes API configuration (base URL, credentials)
  • Implements retry mechanism for connection/timeout errors
  • Logs all HTTP requests and responses

Configuration Properties:

private string $baseUrl; // From config('constants.ADNIC_API_BASE_URL') private array $authParam; // Authorization token and subscription key private array $baseHeaders; // Standard headers (Content-Type, Accept, Auth) private int $apiTimeout; // From ApplicationStorageService private string $partnerId; // From config('constants.ADNIC_PARTNER_ID') private string $partnerReferenceNo; // From config('constants.ADNIC_PARTNER_REFERENCE_NO')

Key Methods:

post(string $endPoint, array $payload = [], array $headers = []): Response

Makes HTTP POST request. Configures timeout, retry logic, headers, and logs request/response.

buildClient(array $headers = []): PendingRequest

Builds HTTP client with timeout, retry configuration, and merged headers.

getBaseUrl(): string

Returns configured base URL for API endpoint construction.

getPartnerId(): string

Returns partner ID for payload construction.

getPartnerReferenceNo(): string

Returns partner reference number for payload construction.

Retry Configuration:

// Retry configuration in buildClient() ->retry( times: 5, sleepMilliseconds: 10000, when: function ($exception) { // Retry on connection and timeout exceptions return $exception instanceof ConnectionException; }, throw: false )
Dependencies:
  • ApplicationStorageService - Runtime timeout configuration
  • Illuminate\Support\Facades\Http - Laravel HTTP client
  • LoggerService - Request/response logging
  • config() - Environment configuration

Usage Example:

// Accessed via AdnicHttpFacade use App\Facades\AdnicHttpFacade; $payload = ['PartnerInfo' => ['PartnerId' => '123']]; $response = AdnicHttpFacade::post('/GeneratePolicy', $payload); if ($response->successful()) { $data = $response->json(); // Process response } // Direct usage $httpClient = app(AdnicHttpClient::class); $response = $httpClient->post('/UploadDocument', $payload, $customHeaders);
Integration Points:
  • AdnicHttpFacade: Provides facade access to HTTP client
  • AdnicApiService: Uses facade for all API calls
  • ApplicationStorageService: Retrieves timeout configuration at runtime
  • config/constants.php: Base URL, credentials, partner information

5. AdnicRequestBuilder Payload Builder

Purpose & Responsibilities:
  • Constructs API request payloads from domain models
  • Formats dates, addresses, and other data as per API requirements
  • Builds headers for specific API calls
  • Encapsulates payload structure knowledge
  • Maps domain values to API-specific codes (nationality, gender, marital status, etc.)
  • Handles complex nested payload structures

Key Methods:

buildIssuePolicyPayload($quote, $process, $healthInsurerRequestResponse, $splitPayment): array

Policy creation payload. Builds PartnerInfo, SponsorInfo, QuoteInfo, InsuredInfo, and PolicyInfo sections.

buildUploadDocumentsPayload(string $base64Content, $healthInsurerResponse, $insuredMember, $insurerDocCode, $quoteDocument): array

Document upload payload. Includes PartnerInfo and DocumentInfo with base64 content, quotation number, member sequence.

buildDownloadDocumentPayload($generatePolicyResponse, $docId): array

Document download payload. Includes PartnerInfo and PolicyDocumentInfo with document ID, policy number, quotation number.

Mapping Methods (Private):

  • mappingSalaryBand($salaryBand) - Maps salary band IDs to API codes
  • mappingGender($gender) - Maps gender values to 'M'/'F'
  • mappingMaritalStatus($maritalStatus) - Maps marital status IDs to API codes
  • uploadedDocumentsInfo($uploadDocumentsResponse) - Builds document info array from upload responses
Dependencies:
  • AdnicHttpClient - Partner ID and reference number

Usage Example:

// Build issue policy payload $requestBuilder = app(AdnicRequestBuilder::class); $payload = $requestBuilder->buildIssuePolicyPayload( $quote, $process, $quote->insurerGenerateQuoteRequestResponse, $splitPayment ); // Build upload document payload $base64Content = base64_encode($documentContent); $uploadPayload = $requestBuilder->buildUploadDocumentsPayload( $base64Content, $healthInsurerResponse, $insuredMember, '3', // Emirates ID code $quoteDocument ); // Build download document payload $downloadPayload = $requestBuilder->buildDownloadDocumentPayload( $generatePolicyResponse, $documentId );
Integration Points:
  • AdnicApiService: Uses builder for all API payload construction
  • AdnicHttpClient: Retrieves partner information for payloads
  • Domain Models: Extracts data from Quote, Payment, Customer models

6. AdnicResponseHandler Response Parser

Purpose & Responsibilities:
  • Normalizes API responses into consistent structure
  • Parses success/error responses from ADNIC API
  • Builds standardized step response arrays
  • Handles HTTP status codes and API-specific error formats
  • Extracts error messages from various response structures
  • Provides consistent response format across all steps

Standard Response Structure:

[ 'status' => bool, // true = success, false = failure 'completed_step' => string, // Step identifier (set by caller) 'message' => string, // User-friendly message 'error' => mixed, // Error details (null on success) 'data' => mixed, // Response data (null on failure) ]

Key Methods:

buildStepResponse(string $step, bool $status = false, ?string $message = null, $error = null, $data = null): array

Builds consistent step response array with standardized structure.

parseHttpResponse(Response $response, string $apiKey): array

Normalizes HTTP response from ADNIC into consistent structure. Checks for API errors, handles 404 responses.

hasApiErrors($responseObject): bool

Checks if response contains API-level errors in ErrorInfo or DocumentInfo.ErrorInfo.

extractErrorMessage($responseObject, string $apiKey): string

Extracts error message from response object. Checks DocumentInfo.ErrorInfo first, then ErrorInfo, falls back to default message.

Dependencies:
  • Illuminate\Http\Client\Response - HTTP response object

Usage Example:

// Parse HTTP response $responseHandler = app(AdnicResponseHandler::class); $httpResponse = AdnicHttpFacade::post('/GeneratePolicy', $payload); $parsedResponse = $responseHandler->parseHttpResponse( $httpResponse, AdnicEnum::RESPONSE_POLICY ); if ($parsedResponse['status']) { $policyData = $parsedResponse['data']; // Process successful response } else { $error = $parsedResponse['error']; $message = $parsedResponse['message']; // Handle error } // Build step response $stepResponse = $responseHandler->buildStepResponse( AdnicEnum::STEP_ISSUE_POLICY, true, 'Policy issued successfully', null, $policyData );
Integration Points:
  • AdnicApiService: Uses handler to parse all API responses
  • AdnicInsuranceService: Uses handler to build error responses
  • AdnicHttpClient: Provides Response objects for parsing

7. AdnicValidationService Validation Layer

Purpose & Responsibilities:
  • Pre-validates data before API calls to prevent unnecessary requests
  • Validates quote data completeness (customer, payment, plan details)
  • Validates document availability and types
  • Validates booking prerequisites
  • Provides clear error messages for missing/invalid data
  • Prevents API costs and improves user experience

Key Methods:

validateRequiredData($quote): array

Validates required data for policy issuance. Checks health UMAF response, payments, insurer quote number, customer existence.

validateUploadDocuments($quote, $quoteDocuments, $insuredInfoDetails): array

Validates document availability. Checks for mandatory documents (EID, Passport, Visa, Birth Certificate, Medical Form, CDD). Also checks if EID front/back are uploaded.

validateDownloadDocuments($quote, $docTypeCodeForIMCRM): array

Validates document IDs availability before downloading. Checks that all required document IDs exist in quote.

Mandatory Documents:

// Required documents for ADNIC policy issuance $mandatoryDocuments = [ DocumentTypeCode::HEA_MEDICAL_APPLICATION_FORM, // Medical application form DocumentTypeCode::HEA_CUSTOMER_DUE_DILIGENCE, // Customer Due Diligence DocumentTypeCode::HEA_EID, // Emirates ID DocumentTypeCode::HEA_PAS, // Passport DocumentTypeCode::HEA_VISA, // Visa DocumentTypeCode::HEA_BIRTH_CERTIFICATE, // Birth Certificate ];
Dependencies:
  • LoggerService - Error logging
  • DocumentTypeCode - Document type constants

Usage Example:

// Validate required data before API call $validationService = app(AdnicValidationService::class); $validationResult = $validationService->validateRequiredData($quote); if (!$validationResult['status']) { return $validationResult; // Contains error message } // Validate documents before upload $quoteDocuments = $documentHandler->getDocumentByType($quote, $documentTypeCodes); $validationResult = $validationService->validateUploadDocuments( $quote, $quoteDocuments, $insuredInfoDetails ); if (!$validationResult['status']) { // Missing documents, return error return $validationResult; } $isEIDFrontBackUploaded = $validationResult['isEIDFrontBackUploaded'];
Integration Points:
  • AdnicInsuranceService: Validates required data before step execution
  • AdnicApiService: Validates documents before upload/download operations
  • AdnicStepExecutor: Uses validation results to determine if steps can proceed

8. AdnicBookPolicyService Booking Process

Purpose & Responsibilities:
  • Manages final booking process and UI step locking status
  • Determines editable steps based on automation state
  • Handles step locking logic for manual intervention
  • Provides UI with information about which steps can be edited
  • Integrates with booking and Sage processes (via other services)

Key Methods:

getStepsLockingStatus($quote, bool $throughAutomation = false): array

Determines UI editability based on automation state. Returns array with policyIssuance, edit flags, message, and insurer_api_status.

Response Structure:

[ 'policyIssuance' => $policyIssuance, 'isEditPolicyDetailsDisabled' => bool, 'isEditBookingDetailsDisabled' => bool, 'message' => string, 'insurer_api_status' => string, ]

Locking Rules:

  • throughAutomation = true: All steps editable
  • No policy issuance: All steps editable
  • Failed status: Editable based on completed step
  • Processing status: Limited editability based on completed step
  • STEP_UPLOAD_DOCUMENTS completed: Policy details and booking editable
  • STEP_ISSUE_POLICY completed: Upload documents and booking editable
  • STEP_UPLOAD_POLICY_DOCS completed: Only booking editable
Dependencies:
  • LoggerService - Logging
  • GenericQueriesAllLobs - Trait for common queries
  • AdnicEnum - Step constants
  • PolicyIssuanceEnum - Status constants

Usage Example:

// Get steps locking status for UI $bookPolicyService = app(AdnicBookPolicyService::class); $lockingStatus = $bookPolicyService->getStepsLockingStatus($quote, false); if ($lockingStatus['isEditPolicyDetailsDisabled']) { // Disable policy details editing in UI } if ($lockingStatus['isEditBookingDetailsDisabled']) { // Disable booking details editing in UI } // Show message to user $message = $lockingStatus['message']; // e.g., "All steps are editable" or "Booking Details is editable"
Integration Points:
  • AdnicInsuranceService: Delegates getStepsLockingStatus() to this service
  • UI Controllers: Uses locking status to enable/disable form fields
  • PolicyIssuance Model: Reads completed_step and status for locking logic

9. AdnicQuoteUpdaterService Data Updater

Purpose & Responsibilities:
  • Updates quote data from API responses
  • Updates payment and commission information
  • Maintains data consistency between systems
  • Updates policy numbers, dates, and amounts
  • Handles quote status transitions
  • Filters null values to avoid overwriting existing data

Key Methods:

updateQuoteFromIssuePolicyResponse($quote, $issuePolicyResult): void

Updates quote with policy details from API response. Sets policy_number, policy_start_date, policy_expiry_date, quote_status_id, policy_issuance_status_id.

updatePaymentFromIssuePolicyResponse(string $quoteCode, $issuePolicyResult): void

Updates payment with commission details. Currently commented out, reserved for future use.

Quote Updates:

// Fields updated from issue policy response $data = [ 'policy_number' => $issuePolicyResult->PolicyInfo->PolicyNo, 'policy_start_date' => $issuePolicyResult->PolicyInfo->PolicyStartDate, 'policy_expiry_date' => $issuePolicyResult->PolicyInfo->PolicyEndDate, 'quote_status_id' => QuoteStatusEnum::PolicyIssued, 'policy_issuance_status_id' => PolicyIssuanceStatusEnum::PolicyIssued, 'quote_status_date' => now(), ];
Dependencies:
  • QuoteStatusEnum - Quote status constants
  • PolicyIssuanceStatusEnum - Policy issuance status constants
  • Payment - Payment model (for future payment updates)

Usage Example:

// Update quote after successful policy issuance $quoteUpdater = app(AdnicQuoteUpdaterService::class); $issuePolicyResult = $apiResponse['data']->data; $quoteUpdater->updateQuoteFromIssuePolicyResponse($quote, $issuePolicyResult); // Quote is now updated with: // - policy_number // - policy_start_date // - policy_expiry_date // - quote_status_id = PolicyIssued // - policy_issuance_status_id = PolicyIssued // Refresh quote to get updated data $quote->refresh();
Integration Points:
  • AdnicApiService: Calls updater after successful policy issuance API call
  • PersonalQuote Model: Updates quote record in database
  • Payment Model: Reserved for future payment updates

10. AdnicDocumentHandler Document Management

Purpose & Responsibilities:
  • Fetches documents from Azure storage
  • Validates document types and formats (MIME type checking)
  • Uploads documents to insurer and IMCRM
  • Maps document types between systems (IMCRM codes ↔ Insurer codes)
  • Handles base64 encoding/decoding
  • Manages document type mappings for health insurance

Key Methods:

fetchDocumentContent(string $relativePath): array

Retrieves document from Azure storage. Validates MIME type (PDF, JPEG, PNG), returns content or error.

uploadAndAttachToQuoteDocuments($quote, $documentContent, string $documentCode, ?string $originalName = null): mixed

Uploads base64 document to IMCRM and attaches to quote. Uses QuoteDocumentService for upload.

getDocumentByType($quote, array $documentTypeCodes): Collection|null

Finds documents by type from quote documents collection. Returns collection or null if not found.

getInsurerDocCodeForHealth(string $documentType): ?string

Maps IMCRM document type codes to ADNIC insurer document codes.

getDocTypeCodeForIMCRM($quote): array

Maps insurer document keys to IMCRM document type codes for policy documents.

getQuoteDocumentMappingForInsurerDocuments($documentType): ?string

Maps insurer document keys (PolicyDocument, CommisionNote, TaxInvoice) to IMCRM document codes.

getQuoteDocumentTypeCodessToUpload(): Collection

Returns collection of document types that need to be uploaded with their insurer codes and names.

Document Type Mappings:

// IMCRM → ADNIC Insurer Codes HEA_EID → '3' (Emirates ID) HEA_VISA → '6' (Visa) HEA_PAS → '1' (Passport) HEA_EID_FRONT → '4' (Emirates ID Front) HEA_EID_BACK → '5' (Emirates ID Back) HEA_BIRTH_CERTIFICATE → '11' (Birth Certificate) HEA_MEDICAL_APPLICATION_FORM → '18' (Medical Application Form) HEA_CUSTOMER_DUE_DILIGENCE → '17' (Customer Due Diligence) // ADNIC Insurer → IMCRM Codes PolicyDocument → POLC (Policy Schedule) CommisionNote → TIRBB (Debit Note) TaxInvoice → TI (Tax Invoice)

Allowed MIME Types:

private const ALLOWED_DOCUMENT_MIME_TYPES = [ 'application/pdf', 'image/jpeg', 'image/png' ];
Dependencies:
  • QuoteDocumentService - Document upload to IMCRM
  • DocumentTypeCode - Document type constants
  • AdnicEnum - Insurer document key constants
  • LoggerService - Error logging

Usage Example:

// Fetch document from Azure $documentHandler = app(AdnicDocumentHandler::class); $documentResponse = $documentHandler->fetchDocumentContent($quoteDocument->doc_url); if ($documentResponse['status']) { $fileContent = $documentResponse['content']; $base64Content = base64_encode($fileContent); // Get insurer document code $insurerDocCode = $documentHandler->getInsurerDocCodeForHealth( $quoteDocument->document_type_code ); // Upload to insurer (via AdnicApiService) // ... } // Upload policy document to IMCRM $documentContent = $downloadResponse['data']->documentContent; $docCode = $documentHandler->getQuoteDocumentMappingForInsurerDocuments( 'PolicyDocument' ); $quoteDocument = $documentHandler->uploadAndAttachToQuoteDocuments( $quote, $documentContent, $docCode, $documentName ); // Get documents by type $documentTypeCodes = [DocumentTypeCode::HEA_EID, DocumentTypeCode::HEA_PAS]; $documents = $documentHandler->getDocumentByType($quote, $documentTypeCodes);

  • AdnicApiService: Uses handler for all document operations
  • QuoteDocumentService: Uploads documents to IMCRM storage
  • Azure Storage: Fetches document content via file_get_contents()
  • Quote Documents: Reads and writes document attachments

✅ Service Usage Best Practices

1. Always Use Dependency Injection

// ✅ Good: Constructor injection public function __construct( private AdnicApiService $apiService, private AdnicValidationService $validationService, ) {} // ❌ Bad: Direct instantiation $apiService = new AdnicApiService();

2. Validate Before API Calls

// ✅ Good: Pre-validation $validationResult = $this->validationService->validateRequiredData($quote); if (!$validationResult['status']) { return $validationResult; } // Proceed with API call // ❌ Bad: No validation $response = $this->apiService->issuePolicy($quote, $process);

3. Handle Response Structure Consistently

// ✅ Good: Check status and handle errors $response = $this->apiService->issuePolicy($quote, $process, $requestResponse); if (!$response['status']) { LoggerService::error('API call failed', extra: [ 'error' => $response['error'], ]); return $response; } // Process successful response // ❌ Bad: Assume success $policyNumber = $response['data']->PolicyInfo->PolicyNo;

4. Log Comprehensive Context

// ✅ Good: Detailed logging LoggerService::info('Starting policy issuance', extra: [ 'step' => AdnicEnum::STEP_ISSUE_POLICY, 'process_id' => $process->id, 'plan_id' => $quote->plan_id, 'quote_code' => $quote->code, ]); // ❌ Bad: Minimal logging LoggerService::info('Policy issuance started');

5. Use Service Facades Appropriately

// ✅ Good: Use facade for HTTP client use App\Facades\AdnicHttpFacade; $response = AdnicHttpFacade::post($endPoint, $payload); // ✅ Also Good: Direct service injection for business logic public function __construct( private AdnicApiService $apiService, ) {}
