🔌 Liva Car Insurance - API Integration

Complete API endpoints documentation with request/response formats

🔐 Authentication

All Liva API endpoints require OAuth 2.0 authentication using Client Credentials flow. The access token must be included in the Authentication header.

OAuth Token Endpoint

Endpoint: POST {LIVA_API_BASE_URL}/auth-token
Method: POST
Purpose: OAuth 2.0 Client Credentials flow authentication Headers: Content-Type: application/x-www-form-urlencoded Request Body: client_id={LIVA_CLIENT_ID} &client_secret={LIVA_CLIENT_SECRET} &grant_type=client_credentials &scope={LIVA_SCOPE} Response: { "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...", "token_type": "Bearer", "expires_in": 3599, "scope": "{LIVA_SCOPE}" }
Token Caching: Tokens are cached in Redis with key RSA_POLICY_ISSUANCE_API_ACCESS_TOKEN and expiration time based on expires_in value (typically 3599 seconds / ~60 minutes).

API Request Headers

All API endpoints require the following headers:

Header Value Description
Content-Type application/json Request content type
Authorization Basic {LIVA_BASIC_AUTH} Basic authentication token
PartnerId {LIVA_PARENT_ID} Partner identifier
location {LIVA_LOCATION} Location code
Authentication Bearer {access_token} OAuth bearer token
SubscriptionKey {LIVA_SUBSCRIPTION_KEY} API subscription key

📄 API Endpoint 1: Upload Documents v2

Upload Required Documents

Purpose: Upload customer documents (Driving License, Emirates ID, Registration Card) to Liva before policy issuance.

Endpoint: POST {LIVA_API_BASE_URL}/motor/documents/upload/v2 Request Payload: { "UploadDocumentsRequest": { "TransactionType": "5" | "6", // "5" = New (default), "6" = Renewal (based on $quote->source) "TransactionNumber": "{insurer_quote_no}", "Attachments": [ { "DocumentType": "4" | "16" | "5", "Content": "{base64_encoded_file_content}", "Extension": "pdf" | "jpg" | "png" } ] } } Document Type Codes: - "4" = Driving License (DL) - "16" = Emirates ID (CEID) - "5" = Registration Card / Mulkiya (CAR_MULKIY) Response: { "UploadDocumentsResponse": { "Status": true, "Attachments": [ { "DocumentType": "4", "UploadStatus": true, "Message": "Document uploaded successfully" } ] } }
Document Encoding: Documents are read from Azure storage, then encoded to base64 before sending to Liva API.
Validation: System validates that all required documents exist before making API call. If any document is missing, the request fails with appropriate error message.

📋 API Endpoint 2: Create Policy v2

Issue Insurance Policy

Purpose: Create the insurance policy with Liva using quote and payment information.

⚠ Payment Status: Payment is PRE-CAPTURED before automation starts. Full transaction details are sent in the request to indicate payment was already processed.
Endpoint: POST {LIVA_API_BASE_URL}/motor/policy/create/v2 Request Payload: { "PolicyRequest": { "QuotationNo": "{insurer_quote_no}", "PremiumPayable": {total_amount}, "IsPaymentProcessed": "Success", "PartnerTrnReferenceNumber": "{quote_uuid}", "PaymtMode": 7, // 7 = Credit Card "PaymtTransactionDate": "{Y-m-d H:i:s}", // From $payment->authorized_at "PaymtTransactionNumber": "{payment_receipt_id}", // From $splitPayment->payment_receipt_id "Amount": {price_vat_applicable}, // From $payment->price_vat_applicable "AuthCode": "{payment_auth_code}", // From $splitPayment->payment_auth_code "Documents": { "DocsInResponse": false, "DocsDetails": { "PolicySchedule": false, "HirePurchaseLetter": false, "ProposalForm": false, "LetterToBank": false, "MotorArabicCertificate": false, "Receipt": false, "BreakDownRecovery": false, "UPRInvoice": false } }, "PolicyConfirmationSMS": false, "PolicyConfirmationEmail": false } } Response: { "PolicyResponse": { "Status": true, "PolicyNumber": "{policy_number}", "ConcatPolNumberWithRenCnt": "{policy_number_with_renewal}", "PolicyCreationDate": "{Y-m-d H:i:s}", "PolicyEffectiveDate": "{Y-m-d}", "PolicyExpiryDate": "{Y-m-d}", "PremiumWithoutVAT": {amount}, "VatAmount": {vat_amount}, "PaidAmount": {total_with_vat}, "Commission": {commission_amount}, "Commissionincldvat": {commission_with_vat}, "VatonCommission": {commission_vat}, "CommissionPercentage": {percentage}, "InsurerCommissionTaxInvoice": "{invoice_number}", "InsurerPremiumTaxInvoice": "{tax_invoice_number}", "InsurerInvoicedate": "{Y-m-d}" } }
✓ On Success:
  • Policy number extracted from PolicyResponse->PolicyNumber (not ConcatPolNumberWithRenCnt)
  • System updates quote with policy number, dates, premium amounts, and commission details
  • Payment record is also updated with commission information

📥 API Endpoint 3: Retrieve Documents v2

Retrieve Policy Documents

Purpose: Retrieve policy documents (Policy Schedule, Policy Certificate, Tax Invoice, etc.) from Liva after policy issuance.

⚠ CRITICAL: Documents are retrieved ONE AT A TIME. Each document type must be toggled individually in the payload before making the API call.
Endpoint: POST {LIVA_API_BASE_URL}/motor/transactions/retrieve/v2 Request Payload: { "RetrieveRequest": { "RetrieveType": "6", "TransactionNumber": "{policy_number}", "PartnerTrnReferenceNumber": "{quote_uuid}", "Documents": { "DocsInResponse": true, "DocsDetails": { "DebitNote": true, // Tax Invoice "CreditNote": false, // Tax Invoice Raised By Buyer "PolicySchedule": true, // Policy Schedule "MotorArabicCertificate": true, // Policy Certificate (Arabic) "HirePurchaseLetter": false, "ProposalForm": false, "LetterToBank": false, "Receipt": false } }, "ProposalForm": false } } Response: { "RetrieveResponse": { "Status": true, "Policies": [ { "PolicyResponse": { "Documents": { "PolicyReportsPdf": [ "{double_base64_encoded_content}" ] } } } ] } }
⚠ CRITICAL: Double Base64 Decoding (Liva-Specific)

Liva API returns documents with double base64 encoding. This is unique to Liva only. The system must decode twice to get the actual PDF content:
// Extract document content $documentContent = $response->RetrieveResponse->Policies[0]->PolicyResponse->Documents->PolicyReportsPdf[0]; // Apply DOUBLE base64 decoding (CRITICAL - Liva requirement) $fileContents = base64_decode(base64_decode($documentContent)); // Fallback if decoding fails if ($fileContents === false) { $fileContents = $documentContent; }

Note: This double encoding/decoding is specific to Liva API and does not apply to other providers (GIG, ADNIC, Qatar).

Document Type Mapping

Liva Document Type IMCRM Document Code Document Name
DebitNote TI Tax Invoice
CreditNote CTIRBB Tax Invoice Raised By Buyer
PolicySchedule POLICY_SCHEDULE Policy Schedule
MotorArabicCertificate POLICY_CERTIFICATE Policy Certificate (Arabic)
Document Processing: After retrieval, documents are:
  • Double base64 decoded
  • Stored in Azure storage
  • Attached to quote as QuoteDocument
  • Dispatched for watermarking

⚙️ Error Handling

All API endpoints return standardized error responses. The system handles errors gracefully with comprehensive logging.

Error Response Format

{ "UploadDocumentsResponse": { "Status": false, "errors": [ { "code": "ERROR_CODE", "message": "Error description" } ] } }

HTTP Status Codes

Status Code Description Handling
200 Success Process response normally
201 Created Process response normally
404 Not Found Log error, mark as failed
401 Unauthorized Refresh token, retry request
500 Server Error Log error, mark as failed

Error Detection Logic

// Check for errors in response if (isset($responseObject->$keyAPI->errors) || (isset($responseObject->$keyAPI->Status) && $responseObject->$keyAPI->Status == false)) { // Extract error message $errorMessage = extractErrorMessage($responseObject, $keyAPI); // Mark as failed $response['status'] = false; $response['error'] = $errorMessage; }

⏱️ Timeout Configuration

API calls use configurable timeout settings to prevent hanging requests.

// Timeout configuration (ApplicationStorage) LIVA_AUTOMATION_API_TIMEOUT // Usage in HTTP calls Http::timeout($this->apiTimeout) ->withHeaders($this->headers) ->post($url, $payload);
Timeout Handling:
  • Configurable per environment via ApplicationStorage
  • Applied to all API calls
  • Timeout exceptions are caught and logged
  • System can retry on timeout if enabled

📊 Response Parsing

All API responses are parsed and validated before processing. The system extracts relevant data and updates models accordingly.

Response Structure

// Standard response structure { "status": true | false, "error": null | "error message", "message": "success message" | "error message", "data": {response_object}, "completed_step": "step_name" | null }

Data Extraction
