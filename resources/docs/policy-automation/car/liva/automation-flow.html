🔄 Liva Car Insurance - Automation Flow

Detailed step-by-step workflow documentation

💳 Pre-Automation Payment Capture

🔑 Critical Prerequisite Step

Auto-capture is a mandatory prerequisite that executes BEFORE the automation workflow begins. Payment must be successfully captured before automation can proceed.

Payment Flow

  1. Customer pays online → Payment authorized
  2. Background job processes → CcPaymentProcess handles split payment approval
  3. Auto-capture executes → SplitPaymentService->processSplitPaymentApprove() calls CRUDService->capturePayment()
  4. Marshall API call → Creates PaymentAction record with action_type: 'CAPTURE' and amount
  5. Success path: If capture succeeds → Automation workflow scheduled via createPolicyIssuanceAutomation()
  6. Failure path: If capture fails → handleAutomationError() sets insurer_api_status_id to AUTO_CAPTURE_FAILED_STATUS_ID and allocates to team

Implementation Details

  • Code Location: SplitPaymentService.php lines 770-792, 1475-1487
  • Retry Logic: Up to 3 attempts with 1-second delay between retries
  • Provider Support: Currently implemented for GIG (AXA) and potentially other providers
  • Failure Handling: If capture fails, automation is prevented from starting and quote is allocated for manual handling

⚠️ Important: This explains why documentation refers to "pre-captured" payments - the payment is already captured before any automation steps execute.

📋 Overview

The Liva Car Insurance Automation follows a sequential 4-step workflow. Each step must complete successfully before proceeding to the next. The system maintains state through the PolicyIssuance model, allowing resume from the last completed step on retry.

Complete Automation Flow

Auto-Capture Payment → OAuth Token → Step 1: Upload Documents → Step 2: Issue Policy → Step 3: Upload Policy Documents → Step 4: Book Policy → Complete

🔐 Pre-requisites: OAuth Authentication

Before executing any step, the system retrieves an OAuth 2.0 access token. The token is cached in Redis to minimize API calls.

🔑 OAuth Token Retrieval

  • Check Redis cache for existing token
  • If token exists and valid, use cached token
  • If token missing/expired, request new token from Liva API
  • Cache token in Redis with expiration time
  • Set authentication headers for subsequent API calls
Token Endpoint: POST {LIVA_API_BASE_URL}/auth-token
Grant Type: client_credentials
Cache Duration: Based on expires_in from API response (default: 3599 seconds)
Cache Key: RSA_POLICY_ISSUANCE_API_ACCESS_TOKEN

Step 1: Upload Documents

1 Upload Documents to Liva API

Purpose

Upload required customer documents (Driving License, Emirates ID, Registration Card) to Liva API before policy issuance.

Process Flow

  • Validate that required documents exist in quote
  • Retrieve documents from Azure storage
  • Encode each document to base64
  • Map document types to Liva document codes:
    • Driving License (DL) → Code: '4'
    • Emirates ID (CEID) → Code: '16'
    • Registration Card (CAR_MULKIY) → Code: '5'
  • Determine transaction type based on $quote->source:
    • '5' = New policy (default)
    • '6' = Renewal (when $quote->source == RENEWAL_UPLOAD)
  • Build payload with transaction type and attachments
  • Call Liva API: motor/documents/upload/v2
  • Validate upload status for each document
  • Update process completed_step if all successful

API Endpoint

POST {LIVA_API_BASE_URL}/motor/documents/upload/v2 Headers: { "Content-Type": "application/json", "Authorization": "Basic {LIVA_BASIC_AUTH}", "PartnerId": "{LIVA_PARENT_ID}", "location": "{LIVA_LOCATION}", "Authentication": "Bearer {access_token}", "SubscriptionKey": "{LIVA_SUBSCRIPTION_KEY}" } Payload: { "UploadDocumentsRequest": { "TransactionType": "5" | "6", // 5 = New, 6 = Renewal "TransactionNumber": "{insurer_quote_no}", "Attachments": [ { "DocumentType": "4" | "16" | "5", "Content": "{base64_encoded_content}", "Extension": "pdf" | "jpg" | "png" } ] } }

Success Criteria

✓ All documents uploaded successfully
All attachments in response have UploadStatus: true

Failure Handling

⚠ On Failure:
  • Update policy issuance status to FAILED
  • Log error details
  • Stop workflow execution
  • Allow manual retry from this step

Step 2: Issue Policy

2 Create Policy with Liva API

Purpose

Create the insurance policy with Liva using quote and payment information.

Process Flow

  • Payment is PRE-CAPTURED - Payment already captured via auto-capture process before automation starts (see Pre-Automation Payment Capture section above)
  • Retrieve main payment and credit card split payment
  • Build policy request payload with:
    • Quotation number
    • Premium amount
    • Payment transaction details (from pre-captured payment):
      • PaymtTransactionNumber: $splitPayment?->payment_receipt_id
      • PaymtTransactionDate: $payment?->authorized_at (Y-m-d H:i:s format)
      • AuthCode: $splitPayment?->payment_auth_code
      • Amount: $payment?->price_vat_applicable
    • IsPaymentProcessed: 'Success' (payment already processed)
    • Payment mode (7 = Credit Card)
  • Call Liva API: motor/policy/create/v2
  • Parse policy response
  • Extract policy number from PolicyResponse->PolicyNumber
  • Update quote with policy information:
    • Policy number (from PolicyNumber field)
    • Policy issuance date
    • Policy start/expiry dates
    • Premium amounts (with/without VAT)
    • VAT amount
  • Update payment with commission details
  • Update quote status to PolicyIssued
  • Update process completed_step

API Endpoint

POST {LIVA_API_BASE_URL}/motor/policy/create/v2 Payload: { "PolicyRequest": { "QuotationNo": "{insurer_quote_no}", "PremiumPayable": {total_amount}, "IsPaymentProcessed": "Success", "PartnerTrnReferenceNumber": "{quote_uuid}", "PaymtMode": 7, "PaymtTransactionDate": "{Y-m-d H:i:s}", "PaymtTransactionNumber": "{payment_receipt_id}", "Amount": {price_vat_applicable}, "AuthCode": "{payment_auth_code}", "Documents": { "DocsInResponse": false, "DocsDetails": { "PolicySchedule": false, "HirePurchaseLetter": false, "ProposalForm": false, "LetterToBank": false, "MotorArabicCertificate": false, "Receipt": false, "BreakDownRecovery": false, "UPRInvoice": false } }, "PolicyConfirmationSMS": false, "PolicyConfirmationEmail": false } }

Success Criteria

✓ Policy created successfully
Response contains PolicyResponse with policy number and dates

Failure Handling

⚠ On Failure:
  • Update policy issuance status to FAILED
  • Log error details
  • Stop workflow execution
  • Policy number stored for retry

Step 3: Upload Policy Documents to IMCRM

3 Retrieve Policy Documents and Upload to IMCRM

Purpose

Retrieve policy documents (Policy Schedule, Policy Certificate, Tax Invoice, etc.) from Liva API and store them in IMCRM Azure storage.

Process Flow

  • Documents retrieved ONE AT A TIME - Each document type fetched individually
  • For each document type (DebitNote, CreditNote, PolicySchedule, MotorArabicCertificate):
    • Set document flag to true in payload (toggle flag)
    • Set all other document flags to false
    • Call Liva API: motor/transactions/retrieve/v2 with RetrieveType: '6'
    • Extract document content from response
    • Apply DOUBLE base64 decoding (CRITICAL - Liva API requirement): base64_decode(base64_decode($documentContent))
    • Store document in Azure storage
    • Create quote document record
    • If Policy Certificate (MotorArabicCertificate): Update rta_upload_status to DONE
    • Dispatch watermark job
    • Reset document flag to false before next iteration
  • Validate all documents retrieved successfully
  • Update process completed_step
  • Set booking_pending flag to true

Double Base64 Encoding

⚠ Important: Liva API returns documents with double base64 encoding. The system must decode twice to get the actual file content.
// Document retrieval from Liva API $documentContent = $response->RetrieveResponse->Policies[0]->PolicyResponse->Documents->PolicyReportsPdf[0]; // Double base64 decoding (required) $fileContents = base64_decode(base64_decode($documentContent)); // Fallback if decoding fails if ($fileContents === false) { $fileContents = $documentContent; }

API Endpoint

POST {LIVA_API_BASE_URL}/motor/transactions/retrieve/v2 Payload: { "RetrieveRequest": { "RetrieveType": "6", "TransactionNumber": "{policy_number}", "PartnerTrnReferenceNumber": "{quote_uuid}", "Documents": { "DocsInResponse": true, "DocsDetails": { "DebitNote": true, // Tax Invoice "CreditNote": false, // Tax Invoice Raised By Buyer "PolicySchedule": true, // Policy Schedule "MotorArabicCertificate": true, // Policy Certificate "HirePurchaseLetter": false, "ProposalForm": false, "LetterToBank": false, "Receipt": false } }, "ProposalForm": false } }

Document Type Mapping

Liva Document Type → IMCRM Document Code: - DebitNote → TI (Tax Invoice) - CreditNote → CTIRBB (Tax Invoice Raised By Buyer) - PolicySchedule → POLICY_SCHEDULE - MotorArabicCertificate → POLICY_CERTIFICATE

Success Criteria

✓ All documents retrieved and uploaded
All required documents successfully retrieved from Liva and stored in IMCRM

Failure Handling

⚠ On Failure:
  • Log which documents failed to retrieve
  • Update policy issuance status to FAILED
  • Stop workflow execution
  • Allow retry from this step

Step 4: Book Policy

4 Finalize Booking with Sage Integration

Purpose

Complete the booking process by updating booking details and triggering Sage ERP integration.

Process Flow

  • Update booking details:
    • Invoice date
    • Insurer tax invoice number
    • Commission invoice number
    • Discount value
    • Commission details (VAT applicable/not applicable)
    • Broker invoice number
  • Validate booking prerequisites using SendBookPolicyRequest
  • Create Sage process request
  • Call Sage API: postBookPolicyToSage
  • Update process completed_step
  • Return success message

Validation

Pre-booking Validation:
  • Quote ID validation
  • Model type validation
  • Send policy type validation
  • Transaction payment status validation

Success Criteria

✓ Booking process initiated
Sage process created successfully, booking will complete asynchronously

Failure Handling

⚠ On Failure:
  • Log validation or API errors
  • Update policy issuance status to FAILED
  • Stop workflow execution
  • Allow manual retry

🔄 State Management & Resume

The system maintains state through the PolicyIssuance model, allowing the workflow to resume from the last completed step on retry.

Step Tracking

// Step sequence const STEPS = [ 'UploadDocuments', 'IssuePolicy', 'UploadPolicyDocumentsToIMCRM', 'BookPolicy' ]; // Get next step based on completed step function getNextStep($completedStep) { if (!$completedStep) { return STEPS[0]; // Start from beginning } $index = array_search($completedStep, STEPS); if ($index === false || $index === count(STEPS) - 1) { return null; // All steps completed } return STEPS[$index + 1]; // Return next step }

Resume Capability

Resume Logic:
  • On retry, system checks completed_step
  • Executes only steps after the last completed step
  • Prevents duplicate API calls
  • Maintains data consistency

Timeout Detection

Timeout Detection Logic:

  • Detects failed logs with null messages
  • Updates policy issuance status to TIMEOUT
  • Enables retry if configured
