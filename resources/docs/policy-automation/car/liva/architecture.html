🏗️ Liva Car Insurance - System Architecture

Comprehensive technical documentation of the automation system architecture

📋 Overview

The Liva Car Insurance Automation system follows a service-oriented architecture pattern, implementing the PolicyIssuanceInterface to provide a standardized approach to policy issuance automation. The system is built using Laravel's dependency injection container and follows SOLID principles.

Key Architecture Principles:
  • Strategy Pattern: Provider-specific implementation via PolicyIssuanceInterface
  • Dependency Injection: All dependencies injected through constructor
  • Single Responsibility: Each service handles a specific concern
  • Interface Segregation: Clean interface contracts
  • Open/Closed: Extensible without modification

🔧 Core Service: LivaInsuranceService

The LivaInsuranceService is the main service class that orchestrates the entire policy issuance automation workflow. It implements the PolicyIssuanceInterface and handles all interactions with the Liva API.

Class Structure

namespace App\Services\PolicyIssuanceAutomation\Car; class LivaInsuranceService implements PolicyIssuanceInterface { use GenericQueriesAllLobs; private $className = 'livaInsuranceService'; private readonly string $baseUrl; public const INSURER_CODE = InsuranceProvidersEnum::RSA; public const TYPE = quoteTypeCode::Car; public const TYPE_ID = QuoteTypeId::Car; // Step Constants public const UPLOAD_DOCUMENTS = 'UploadDocuments'; public const ISSUE_POLICY = 'IssuePolicy'; public const UPLOAD_POLICY_DOCUMENTS_TO_IMCRM = 'UploadPolicyDocumentsToIMCRM'; public const BOOK_POLICY = 'BookPolicy'; private $appEnv; private $apiTimeout; }

Key Methods

  • executeSteps($process)

    Main entry point for executing the automation workflow. Handles OAuth token retrieval, step sequencing, and error handling.

  • executeStepSequence($quote, $process, $nextStepToBeExecuted)

    Orchestrates the sequential execution of all 4 steps, handling step transitions and error propagation.

  • getAccessToken()

    Manages OAuth 2.0 authentication with Redis token caching. Retrieves cached token or requests new one from Liva API.

  • httpCall($endPoint, $payload, $keyAPI)

    Centralized HTTP client method that handles all API calls with timeout configuration, error handling, and response parsing.

  • getNextStep($completedStep)

    Determines the next step in the workflow based on the last completed step, enabling resume functionality.

🔄 Step Execution Methods

1. Upload Documents Step

  • executeUploadDocumentsStep($quote, $process)

    Executes document upload step, validates response, and updates process state.

  • uploadDocuments($quote)

    Uploads required documents (Driving License, Emirates ID, Registration Card) to Liva API using base64 encoding.

2. Issue Policy Step

  • executeIssuePolicyStep($quote, $process)

    Executes policy issuance step, updates quote status, and handles policy creation response.

  • issuePolicy($quote, $process)

    Creates policy with Liva API using quote and pre-captured payment transaction details. Extracts policy number from PolicyResponse->PolicyNumber and updates quote with policy information.

3. Upload Policy Documents Step

  • executeUploadPolicyDocumentsStep($quote, $process, $issuePolicyResponsePolicyNumber)

    Executes policy document retrieval and upload step.

  • uploadPolicyDocumentsToIMCRM($quote, $process, $issuePolicyResponsePolicyNumber)

    Retrieves policy documents from Liva API one at a time (with toggle flags). Each document type is fetched individually with RetrieveType: '6'. Documents are double base64 decoded before storage.

  • uploadAndAttachToQuoteDocuments($quote, $documentContent, $documentCode, $originalName)

    Handles double base64 decoding (CRITICAL - Liva requirement) using base64_decode(base64_decode($documentContent)). Stores documents in Azure storage, attaches to quote. Updates rta_upload_status to DONE when Policy Certificate is uploaded.

4. Book Policy Step

  • executeBookPolicyStep($quote, $process)

    Executes final booking step with Sage integration.

  • bookPolicy($quote)

    Validates booking prerequisites, updates booking details, and triggers Sage API integration.

  • updateBookingDetails($quote)

    Updates payment and booking information before final booking.

  • validateBookPolicy($quote)

    Validates all prerequisites before booking policy.

🔐 Authentication Architecture

The system uses OAuth 2.0 Client Credentials flow for authentication with Liva API. Tokens are cached in Redis to minimize API calls.

OAuth Flow

OAuth 2.0 Client Credentials Flow

1. Check Redis Cache → 2. If expired/missing → 3. Request Token → 4. Cache Token → 5. Use Token

Token Management

// Token Endpoint POST {LIVA_API_BASE_URL}/auth-token // Token Cache Key const POLICY_ISSUANCE_API_ACCESS_TOKEN_KEY = 'RSA_POLICY_ISSUANCE_API_ACCESS_TOKEN'; // Token Request Headers Content-Type: application/x-www-form-urlencoded // Token Request Payload { 'client_id': config('constants.LIVA_CLIENT_ID'), 'client_secret': config('constants.LIVA_CLIENT_SECRET'), 'grant_type': 'client_credentials', 'scope': config('constants.LIVA_SCOPE') } // API Request Headers (after token retrieval) { 'Content-Type': 'application/json', 'Authorization': 'Basic {LIVA_BASIC_AUTH}', 'PartnerId': '{LIVA_PARENT_ID}', 'location': '{LIVA_LOCATION}', 'Authentication': 'Bearer {access_token}', 'SubscriptionKey': '{LIVA_SUBSCRIPTION_KEY}' }

🔄 State Management

The system maintains state through the PolicyIssuance model, tracking completed steps and allowing resume from failures.

Step Sequence

private function getAPISteps(): array { return [ self::UPLOAD_DOCUMENTS, // Step 1 self::ISSUE_POLICY, // Step 2 self::UPLOAD_POLICY_DOCUMENTS_TO_IMCRM, // Step 3 self::BOOK_POLICY, // Step 4 ]; }

State Tracking

  • completed_step

    Stores the last successfully completed step

  • status

    Tracks overall process status (PROCESSING, SUCCESS, FAILED, TIMEOUT)

  • Resume Capability

    System can resume from last completed step on retry

📊 Error Handling & Logging

Comprehensive error handling and logging is implemented at every step of the automation process.

Error Handling Strategy

  • Pre-validation

    Validates prerequisites before API calls to prevent unnecessary failures

  • Try-Catch Blocks

    All API calls wrapped in exception handling

  • Status Updates

    Updates policy issuance status on failures

  • Timeout Detection

    Method: livaPortalTimeoutResponse() detects timeout scenarios by checking for null status responses ('"status": false, "message": null') and failed logs count < 2. Updates status to TIMEOUT_STATUS if detected.

Logging

  • LoggerService Integration

    Comprehensive logging at every step with context

  • Policy Issuance Logs

    Stores request/response for each API call

  • Error Tracking

    Logs errors with full context for debugging
