🔐 OAuth 2.0 Authentication

All GIG API requests require OAuth 2.0 authentication using client credentials flow. The access token is cached in Redis to minimize API calls and improve performance.

Authentication Method OAuth 2.0 Client Credentials flow with Bearer token authentication

OAuth Token Endpoint

POST {GIG_API_AUTH_BASE_URL}/oauth/token

Request Headers

Content-Type: application/x-www-form-urlencoded

Request Payload

client_id={GIG_API_AUTH_CLIENT_ID}
&client_secret={GIG_API_AUTH_CLIENT_SECRET}
&grant_type=client_credentials
&audience=integration-platform

Response Structure

{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires_in": 3600,
  "token_type": "Bearer"
}

Token Caching

  • Cache Key: AXA_POLICY_ISSUANCE_API_ACCESS_TOKEN
  • Cache Store: Redis
  • TTL: Set from expires_in value (seconds)
  • Refresh: Automatic refresh when token expires or missing

Required Headers for Authenticated Requests

Header Name Description Example
Authorization Bearer token from OAuth endpoint Bearer {access_token}
opCo Operating company code GULF
sourceApplication Source application identifier OLS
Content-Type Request content type application/json

🌐 API Base URL & Configuration

Base URL Structure

{GIG_API_BASE_URL}/apis/gulf-motor-v3-vs/motor
Environment Variable GIG_API_BASE_URL - Base URL for GIG API (e.g., https://api.gig.ae)

API Timeout Configuration

  • Default Timeout: 30 seconds
  • Retry Attempts: 5 retries (GET, PATCH, AUTH), 1 retry (POST)
  • Retry Delay: 10 seconds between retries

📡 API Endpoints

The GIG Car Insurance API provides three main endpoints for policy issuance automation:

POST /v1/insurance-documents

Purpose

Uploads customer documents (Car Registration Card, Emirates ID, Driving License) to GIG's document management system.

Request Headers

Authorization: Bearer {access_token}
opCo: GULF
sourceApplication: OLS
Content-Type: application/json

Request Payload Structure

{
  "referenceType": "quotation",
  "referenceValue": "QUOTE123456",
  "documentType": {
    "code": "DT01",
    "value": "Car Registration Document"
  },
  "documentContent": "base64_encoded_document_content",
  "documentName": "unique_id_car_registration.pdf",
  "mimeType": "application/pdf"
}

Request Payload Fields

Field Type Required Description
referenceType string Yes Always "quotation"
referenceValue string Yes Quote's insurer quote number
documentType.code string Yes Document type code (DT01, DT02, DT03)
documentType.value string Yes Document type name
documentContent string Yes Base64 encoded document content
documentName string Yes Unique document name
mimeType string Yes Document MIME type (application/pdf, image/jpeg, image/png)

Document Type Codes

Code Document Type IMCRM Code Notes
DT01 Car Registration Document (Mulkiya) CAR_REGISTRATION_CARD Required
DT02 Driving License DRIVING_LICENSE Required
DT03 National ID (Emirates ID) CAR_EMIRATE_ID Required; supports multiple documents (front/back)
📋 Document Upload Requirements
  • Supports multiple documents per type (e.g., Emirates ID front/back)
  • All documents of a type must succeed for that type to be marked as uploaded
  • Documents are base64 encoded before upload

Response Structure

{
  "status": "success",
  "message": "Document uploaded successfully"
}
POST /v3/policies
💳 Pre-Captured Payment

Payment is already captured BEFORE this API call. Auto-capture executes during split payment approval process via SplitPaymentService->processSplitPaymentApprove(). If capture fails, automation is prevented from starting and quote is marked with AUTO_CAPTURE_FAILED status. Only payment amount and mode are sent in this request - no transaction_id is used.

Purpose

Creates a car insurance policy with GIG using quote ID and payment information.

Request Headers

Authorization: Bearer {access_token}
opCo: GULF
sourceApplication: OLS
Content-Type: application/json

Request Payload Structure

{
  "quoteId": "QUOTE123456",
  "isActive": "true",
  "payment": {
    "paymentMode": {
      "code": "CT068",
      "value": "Upfront Commission Partner Payment"
    },
    "paymentAmount": {
      "amount": 1500.00,
      "currencyCode": "AED"
    }
  }
}

Request Payload Fields

Field Type Required Description
quoteId string Yes Quote's insurer quote number
isActive string Yes Always "true"
payment.paymentMode.code string Yes Payment mode code (CT068)
payment.paymentMode.value string Yes Payment mode description
payment.paymentAmount.amount number Yes Payment amount
payment.paymentAmount.currencyCode string Yes Currency code (AED)

Response Structure

{
  "data": {
    "policyId": "POL123456789",
    "documents": [
      {
        "docId": "DOC001",
        "name": "Tax invoice"
      },
      {
        "docId": "DOC002",
        "name": "Tax invoice by buyer"
      },
      {
        "docId": "DOC003",
        "name": "Receipt with reference"
      },
      {
        "docId": "DOC004",
        "name": "Motor Insurance Policy Schedule"
      },
      {
        "docId": "DOC005",
        "name": "Certificate of Insurance"
      }
    ]
  }
}
GET /v1/insurance-documents/document

Purpose

Downloads policy documents from GIG using document ID, reference type, and reference value.

Request Headers

Authorization: Bearer {access_token}
opCo: UAE
documentType: {document_id}
referenceType: policy
referenceValue: {policy_id}
Accept: application/json

Query Parameters

This endpoint uses headers instead of query parameters:

Header Description Example
opCo Operating company UAE
documentType Document ID from policy issuance response DOC001
referenceType Reference type (always "policy") policy
referenceValue Policy ID from policy issuance POL123456789

Response Structure

{
  "document": {
    "name": "Tax invoice",
    "content": "base64_encoded_document_content"
  }
}
⚠️ Rate Limiting A 10-second delay is implemented between document downloads to respect API rate limits.

⚠️ Error Handling

Error Response Structure

{
  "message": "Error description",
  "description": "Detailed error message"
}

Common Error Scenarios

HTTP Status Error Scenario Handling
401 Unauthorized - Invalid or expired token Refresh OAuth token and retry
400 Bad Request - Invalid payload Validate payload structure and required fields
404 Not Found - Document or quote not found Verify quote/policy ID and document IDs
500 Internal Server Error Retry with exponential backoff
Timeout Request timeout Retry up to configured max retries
