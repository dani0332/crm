1. Environment Configuration

All GIG API credentials and base URLs are configured through environment variables and accessed via config/constants.php.

1.1 Environment Variables (.env)

Add the following variables to your .env file:

# GIG API Configuration GIG_API_BASE_URL=https://api.gig.ae GIG_API_AUTH_BASE_URL=https://auth.gig.ae GIG_API_AUTH_CLIENT_ID=your_client_id GIG_API_AUTH_CLIENT_SECRET=your_client_secret # Azure Storage (for document management) AZURE_IM_STORAGE_URL=https://yourstorage.blob.core.windows.net AZURE_IM_STORAGE_CONTAINER=your_container_name # Redis (for OAuth token caching) REDIS_HOST=127.0.0.1 REDIS_PASSWORD=null REDIS_PORT=6379

1.2 Constants Configuration (config/constants.php)

The following GIG constants are defined in config/constants.php:

Constant Key Environment Variable Purpose Required
GIG_API_BASE_URL GIG_API_BASE_URL Base URL for GIG API endpoints ✅ Yes
GIG_API_AUTH_BASE_URL GIG_API_AUTH_BASE_URL Base URL for OAuth authentication endpoint ✅ Yes
GIG_API_AUTH_CLIENT_ID GIG_API_AUTH_CLIENT_ID OAuth client ID for authentication ✅ Yes
GIG_API_AUTH_CLIENT_SECRET GIG_API_AUTH_CLIENT_SECRET OAuth client secret for authentication ✅ Yes
// config/constants.php return [ // ... other constants // GIG Policy Issuance API Credentials 'GIG_API_BASE_URL' => env('GIG_API_BASE_URL'), 'GIG_API_AUTH_BASE_URL' => env('GIG_API_AUTH_BASE_URL'), 'GIG_API_AUTH_CLIENT_ID' => env('GIG_API_AUTH_CLIENT_ID'), 'GIG_API_AUTH_CLIENT_SECRET' => env('GIG_API_AUTH_CLIENT_SECRET'), ];

💡 Accessing Configuration

Use Laravel's config() helper to access these values:

$baseUrl = config('constants.GIG_API_BASE_URL'); $authUrl = config('constants.GIG_API_AUTH_BASE_URL'); $clientId = config('constants.GIG_API_AUTH_CLIENT_ID');

2. OAuth 2.0 Configuration

GIG uses OAuth 2.0 client credentials flow for API authentication. The access token is cached in Redis to minimize API calls.

2.1 OAuth Endpoint Configuration

// OAuth Token Endpoint private readonly string $authUrl; // Constructed in __construct() $this->authUrl = config('constants.GIG_API_AUTH_BASE_URL') . '/oauth/token';

2.2 OAuth Request Payload

// OAuth Token Request Payload $payload = [ 'client_id' => $this->clientId, 'client_secret' => $this->clientSecret, 'grant_type' => 'client_credentials', 'audience' => 'integration-platform', ];

2.3 Redis Token Caching

Configuration Value Description
Cache Key AXA_POLICY_ISSUANCE_API_ACCESS_TOKEN Redis key for storing access token
Cache Store redis Laravel cache store name
TTL From expires_in response Token expiration time in seconds
Refresh Strategy Automatic Token refreshed when expired or missing
// Token Caching Implementation $accessToken = $data->access_token; $expiresIn = (int) $data->expires_in; Cache::store('redis')->put( self::POLICY_ISSUANCE_API_ACCESS_TOKEN_KEY, $accessToken, $expiresIn );

3. Runtime Configuration via ApplicationStorage

Runtime configuration allows you to enable/disable features and adjust settings without code deployment. All runtime settings are stored in the application_storage table and accessed via ApplicationStorageService.

3.1 Feature Toggles

Storage Key Enum Constant Purpose Type Default
ENABLE_GIG_CAR_POLICY_ISSUANCE ApplicationStorageEnums::ENABLE_GIG_CAR_POLICY_ISSUANCE Master switch to enable/disable automation boolean false
ENABLE_RETRY_TIMEOUT_GIG_CAR_POLICY_ISSUANCE ApplicationStorageEnums::ENABLE_RETRY_TIMEOUT_GIG_CAR_POLICY_ISSUANCE Enable retry mechanism for timeout failures boolean false

3.2 Accessing Runtime Configuration

use App\Services\ApplicationStorageService; use App\Enums\ApplicationStorageEnums; // Check if automation is enabled public function isPolicyIssuanceAutomationEnabled(): bool { return (bool) app(ApplicationStorageService::class) ->getValueByKey(ApplicationStorageEnums::ENABLE_GIG_CAR_POLICY_ISSUANCE); } // Check retry enabled public function isPolicyIssuanceAutomationRetryEnabledForTimeout(): bool { return (bool) app(ApplicationStorageService::class) ->getValueByKey(ApplicationStorageEnums::ENABLE_RETRY_TIMEOUT_GIG_CAR_POLICY_ISSUANCE); }

💡 Runtime Configuration Benefits

  • Enable/disable automation without code deployment
  • Control retry mechanisms for troubleshooting
  • A/B testing capabilities
  • Emergency shutdown capability
  • Per-quote automation control

7. Configuration Best Practices

✅ DO:

  • Store sensitive credentials in environment variables, never in code
  • Use Redis for OAuth token caching to improve performance
  • Enable feature toggles via ApplicationStorage for runtime control
  • Configure appropriate retry counts and delays for each HTTP method
  • Monitor token expiration and refresh proactively
  • Use separate OAuth credentials for each environment (dev, staging, production)
  • Document all configuration changes in deployment notes

❌ DON'T:

  • ❌ Hardcode API credentials or tokens in source code
  • ❌ Share OAuth credentials across environments
  • ❌ Set retry counts too high (may cause API rate limiting)
  • ❌ Disable feature toggles without understanding impact
  • ❌ Ignore token expiration errors
  • ❌ Use production credentials in development environments
  • ❌ Skip Redis configuration (will cause performance issues)
