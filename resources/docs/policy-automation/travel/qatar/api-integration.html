🔌 Qatar Travel API Integration

Complete API Documentation for Qatar Travel Insurance Policy Issuance

🔐 Authentication & Authorization

All Qatar API requests require authentication using payload-based credentials. The API uses agency ID and agency code for authentication.

Authentication Method Payload-based authentication with agency_id and agency_code included in every request body

Authentication Parameters

Every API request includes authentication parameters in the payload:

Parameter Description Source
agency_id Qatar agency identifier ALLIANCE_AGENCY_ID config
agency_code Qatar agency code ALLIANCE_AGENCY_CODE config

Request Headers

Header Name Description Value
Content-Type Request content type application/json

Configuration

Authentication credentials are configured via environment variables:

Agency ID ALLIANCE_AGENCY_ID

Qatar agency identifier

Agency Code ALLIANCE_AGENCY_CODE

Qatar agency code

🌐 API Base URL & Configuration

Base URL Structure

{ALLIANCE_API_BASE_URL}/api
Environment Variable ALLIANCE_API_BASE_URL - Base URL for Alliance API (e.g., https://api.alliance.ae)

API Timeout Configuration

API timeout is set to 20 seconds for all requests:

Timeout 20 seconds

Fixed timeout for all HTTP requests

HTTP Client Implementation

private function qatarHttpCall($endPoint, $param) { $headers = ['Content-Type' => 'application/json']; $payload = array_merge($this->authParam, $param); $url = $this->baseUrl . $endPoint; return Http::timeout(20)->withHeaders($headers)->post($url, $payload); }

📡 API Endpoints

The Qatar Travel Insurance API provides four main endpoints for policy issuance automation:

POST /v1/quote/{travelType}/finalise

Purpose

Finalizes a travel insurance policy with Qatar using quote information, customer details, and traveller information.

Travel Type

The {travelType} parameter is determined by the quote's direction_code:

  • inbound - Default value (TravelQuoteEnum::QATAR_IN_BOUND)
  • outbound - When direction_code === TRAVEL_UAE_OUTBOUND (TravelQuoteEnum::QATAR_OUT_BOUND)

Request Payload Structure

{
  "agency_id": "AGENCY_ID",
  "agency_code": "AGENCY_CODE",
  "quote_id": "QUOTE_ID",
  "scheme_id": "SCHEME_ID",
  "title_customer": "Mr",
  "first_name_customer": "John",
  "last_name_customer": "Doe",
  "title_traveller": ["Mr", "Ms"],
  "first_name_traveller": ["John", "Jane"],
  "last_name_traveller": ["Doe", "Smith"],
  "dob": ["1990-01-01", "1992-05-15"],
  "passport_number": ["A12345678", "B98765432"],
  "nationality_traveller": [1, 2],
  "email": "happiness@support.insurancemarket.ae",
  "mobile": "971502245943",
  "agency_reference": "asc"
}

Response Structure

{
  "result": {
    "policy_id": "POL123456",
    "premium": 1500.00
  },
  "errors": null
}

Response Fields

Field Type Description
result.policy_id string Generated policy identifier
result.premium float Policy premium amount (including VAT)
errors array|null Array of error messages if request failed

HTTP Status Codes

  • 200 OK - Policy finalized successfully
  • 400/500 - Error occurred (check errors array)
POST /v1/quote/{travelType}/purchase

Purpose

Purchases a finalized policy and generates the policy number and tax invoice number.

Request Payload Structure

{
  "agency_id": "AGENCY_ID",
  "agency_code": "AGENCY_CODE",
  "policy_id": "POL123456",
  "agency_reference": "TXN123456789"
}
💡 Payment Pre-Capture Payment is PRE-CAPTURED before automation starts. The agency_reference parameter uses the transaction ID from $payment->paymentSplits->first()?->paymentCharges?->transaction_id as a reference only.

Response Structure

{
  "result": {
    "policy_number": "POL-2026-001234",
    "tax_invoice_number": "INV-2026-001234"
  },
  "errors": null
}

Response Fields

Field Type Description
result.policy_number string Generated policy number
result.tax_invoice_number string Generated tax invoice number
POST /v1/policy/{travelType}/documents

Purpose

Retrieves policy documents (Tax Invoice, Certificate of Insurance) for a purchased policy. This endpoint may return a "still generating" error that requires retry.

Request Payload Structure

{
  "agency_id": "AGENCY_ID",
  "agency_code": "AGENCY_CODE",
  "policy_id": "POL123456"
}

Response Structure (Success)

{
  "result": {
    "policy_documents": [
      {
        "name": "Policy Tax Invoice",
        "url": "https://cdn.alliance.ae/documents/invoice.pdf"
      },
      {
        "name": "Certificate of Insurance",
        "url": "https://cdn.alliance.ae/documents/certificate.pdf"
      }
    ]
  },
  "errors": null
}

Response Structure (Still Generating)

{
  "result": null,
  "errors": [
    "Policy documents are still generating. Please try again later."
  ]
}
⚠️ Retry Mechanism If the API returns "Policy documents are still generating", the system automatically retries up to 5 times with a 10-second delay between attempts. The retry only occurs for "still generating" errors; other errors fail immediately.

Response Fields

Field Type Description
result.policy_documents array Array of policy document objects
policy_documents[].name string Document name (e.g., "Policy Tax Invoice", "Certificate of Insurance")
policy_documents[].url string URL to download the document
POST /v1/agency/buyer-tax-invoices

Purpose

Retrieves buyer tax invoice details including commission information, VAT details, and invoice URL.

Request Payload Structure

{
  "agency_id": "AGENCY_ID",
  "agency_code": "AGENCY_CODE",
  "policy_id": "POL123456",
  "policy_number": "POL-2026-001234"
}

Response Structure

{
  "result": {
    "buyer_tax_invoices": [
      {
        "tax_invoice_number": "INV-2026-001234",
        "tax_invoice_date": "06-Feb-26",
        "premium": 1500.00,
        "tax_rate": 5.0,
        "agency_commission": 150.00,
        "agency_commission_tax": 7.50,
        "agency_commission_inc_tax": 157.50,
        "url": "https://cdn.alliance.ae/invoices/invoice.pdf"
      }
    ]
  },
  "errors": null
}

Response Fields

Field Type Description
result.buyer_tax_invoices array Array of buyer tax invoice objects
buyer_tax_invoices[].tax_invoice_number string Tax invoice number
buyer_tax_invoices[].tax_invoice_date string Invoice date in "d-M-y" format
buyer_tax_invoices[].premium float Policy premium amount
buyer_tax_invoices[].tax_rate float Tax rate percentage
buyer_tax_invoices[].agency_commission float Commission amount (excluding tax)
buyer_tax_invoices[].agency_commission_tax float Commission VAT amount
buyer_tax_invoices[].agency_commission_inc_tax float Commission amount (including tax)
buyer_tax_invoices[].url string URL to download the buyer tax invoice

⚠️ Error Handling

Error Response Structure

All Qatar API endpoints return errors in a consistent format:

{
  "result": null,
  "errors": [
    "Error message 1",
    "Error message 2"
  ]
}

Common Error Scenarios

Error Message Description Handling
"Policy documents are still generating" Documents not ready yet Retry with 10-second delay (max 5 retries)
"Invalid policy_id" Policy ID not found Log error and return failure
"Invalid quote_id" Quote ID not found Log error and return failure
"Authentication failed" Invalid agency credentials Check configuration and log error

HTTP Status Codes

  • 200 OK - Request successful (check errors array for API-level errors)
  • 400 Bad Request - Invalid request payload
  • 401 Unauthorized - Authentication failed
  • 500 Internal Server Error - Server error
Note Even with HTTP 200 status, the API may return errors in the errors array. Always check the errors field in the response.

📄 Document Type Mapping

Qatar document names are automatically mapped to IMCRM document codes:

Qatar Document Name IMCRM Document Code Description
"Policy Tax Invoice" TRAVEL_TAX_INVOICE Policy tax invoice document
"Certificate of Insurance" TRAVEL_POLICY_SCHEDULE Policy schedule/certificate
Buyer Tax Invoice TRAVEL_TAX_INVOICE_RAISE_BY_BUYER Buyer tax invoice from Step 4
Automatic Mapping Documents are automatically mapped using the getTravelDocumentMapping() method. Unmapped documents are logged but do not stop the automation process.
