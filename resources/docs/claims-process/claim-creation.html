🆕 Claim Creation Process

Comprehensive guide to creating new insurance claims with internal policy search and CPAPI integration

📋 Overview

The claim creation process is the entry point for all new insurance claims in the system. It involves internal policy search and verification, customer information validation, LOB-specific field collection, and CPAPI integration for claim creation with automatic status assignment.

🔍 Policy Search Integration

🏠 Internal System Search

The policy search functionality uses internal system queries to retrieve active policies for claim creation. This is handled within the current system without external API calls.

// ClaimsService::searchActivePolicies() method - Internal System Search public function searchActivePolicies( ?string $email = null, ?string $policyNumber = null, ?int $quoteTypeId = null, int $page = 1 ): array { // Internal database query - no external API calls $policies = PersonalQuote::query() ->select([ 'personal_quotes.id', 'personal_quotes.uuid', 'personal_quotes.code as ref_id', 'personal_quotes.policy_number', // ... additional fields ]) ->whereNotNull('personal_quotes.policy_number') ->whereIn('personal_quotes.quote_status_id', [QuoteStatusEnum::PolicyBooked]) ->when($email || $policyNumber, function ($query) use ($email, $policyNumber) { // Internal search logic implementation }) ->simplePaginate($this->perPage); return $policies; }

Active Policy Filter Only policies with PolicyBooked status from internal database
LOB-Specific Data Car-specific fields (make, model, year, plate) when applicable

📝 LOB-Specific Validation Rules

Each Line of Business has unique validation requirements enforced through the ClaimStoreRequest validation class.

🚗 Motor/Car & Bike Claims

  • Plate Number: Required, regex pattern /^[A-Za-z0-9\-\s]+$/
  • Car Make: Required string, max 100 characters
  • Car Model: Required string, max 100 characters
  • Model Year: Required integer, range 1900 to current year + 1
  • Interdependency: If any vehicle field is provided, all must be provided
  • Auto-formatting: Plate number converted to uppercase
  • Shared Logic: Car and Bike use identical validation (isCarOrBikeLOB method)

🏥 Health & Group Medical Claims

  • Claim Request Type: Required (reimbursement, pending-approvals, ask-a-question)
  • Service Type: Required for pending-approvals type
  • Service Types: In-patient or Out-patient requests
  • Reference Number: Optional for tracking purposes
  • Conditional Logic: Service type validation based on request type
  • Lookup Validation: All IDs validated against lookups table
  • Group Medical: Corporate health insurance with additional validation

💼 Life Claims

  • Standard Fields: Basic claim information only
  • Simplified Validation: No LOB-specific required fields
  • Policy Information: Policy number and incident details
  • Incident Date: Required, must be before today
  • Claim Type: Selected from available life claim types
  • Processing: Direct path to claim processing

🏠 Other LOBs (Home, Travel, Pet, etc.)

  • Standard Processing: Basic claim workflow without complex validation
  • Supported LOBs: Home, Travel, Yacht, Pet, Cycle, Jetski, Business, CorpLine, Savings
  • Common Fields: Policy number, incident date, incident story
  • Document Types: LOB-specific document requirements from lookups
  • Status Flow: Standard Open → Closed workflow
  • Validation: Basic field validation without LOB-specific business rules

The prepareForValidation() method automatically:

public function createClaim(array $data): array { try { // Prepare API data for CPAPI integration (claim creation only) $apiData = [ 'firstName' => $data['first_name'] ?? null, 'lastName' => $data['last_name'] ?? null, 'email' => $data['email'] ?? null, 'mobileNo' => $data['mobile_no'] ?? null, 'incident' => $data['incident_story'] ?? null, 'incidentDate' => $data['incident_date'] ?? null, 'customerId' => $data['customer_id'] ?? null, 'policyNumber' => $data['policy_number'] ?? null, 'insuranceProviderId' => $data['insurance_provider_id'] ?? null, 'quoteTypeId' => $data['quote_type_id'] ?? null, 'source' => $data['source'] ?? config('constants.SOURCE_NAME', 'IMCRM'), 'quoteUID' => $data['selected_quote_uuid'] ?? null, 'claimTypeId' => $data['claim_type_id'] ?? null, 'carMake' => $data['car_make'] ?? null, 'carModel' => $data['car_model'] ?? null, 'modelYear' => $data['model_year'] ?? null, 'plateNumber' => $data['plate_number'] ?? null, 'claimRequestTypeId' => $data['claim_request_type_id'] ?? null, 'serviceTypeId' => $data['service_type_id'] ?? null, 'requestReferenceNumber' => $data['request_reference_number'] ?? null, ]; // Remove null values and make CPAPI request $apiData = array_filter($apiData, fn($value) => !is_null($value)); $response = CustomerPortalApiFacade::request('/api/claims/save-claim', 'post', $apiData); if ($response->data['success']) { return $response->data; } else { throw new \Exception('CPAPI claim creation failed: ' . ($response->data['message'] ?? 'Unknown error')); } } catch (\Exception $e) { // Comprehensive error logging LoggerService::error(' Error creating claim request', [ 'error' => $e->getMessage(), 'data' => $data, 'api_data' => $apiData ?? null, ]); throw $e; } }

🎯 Observer Pattern Integration

🔄 Automatic Status Assignment

Upon claim creation, the ClaimRequestObserver automatically sets the initial sub-status based on LOB:

// ClaimRequestObserver::creating() method - Current Implementation public function creating(ClaimRequest $claimRequest): void { // Set default source if not provided if (empty($claimRequest->source)) { $claimRequest->source = 'IMCRM'; } // Set default whatsapp_consent if not provided if (is_null($claimRequest->whatsapp_consent)) { $claimRequest->whatsapp_consent = false; } // Note: Status assignment happens after CPAPI creation response // The observer monitors claim_number changes for status updates }

🚗 Motor Claims Status Flow

  • Creation: Default values set (source='IMCRM', whatsapp_consent=false)
  • After CPAPI: Claim created in external system
  • Status Update: Triggered when claim_number is assigned
  • Auto-Detection: isCarOrBikeLOB() method identifies motor claims

🏥 Health Claims Status Flow

  • Creation: Default values set (source='IMCRM', whatsapp_consent=false)
  • After CPAPI: Claim created in external system
  • Status Update: Triggered when claim_number is assigned
  • Request Types: Reimbursement, pending-approvals, ask-a-question

💼 Life Claims Status Flow

  • Creation: Default values set (source='IMCRM', whatsapp_consent=false)
  • After CPAPI: Claim created in external system
  • Status Update: Triggered when claim_number is assigned
  • Simplified: Basic claim processing without complex sub-statuses

🚨 Error Handling & Recovery

⚠️ Common Error Scenarios

CPAPI Integration Failures

  • Network Timeout: Exception handling with LoggerService logging
  • Authentication Failure: Error propagation with context data
  • Invalid Response: Success/failure checking with proper error messages
  • Data Validation: Null value filtering before API calls

Validation Failures

  • LOB-Specific Rules: Car fields interdependency validation
  • Required Fields: First name, last name, email, mobile validation
  • Format Validation: Regex patterns for names, phone, plate numbers
  • Health Rules: Service type required for pending approvals
