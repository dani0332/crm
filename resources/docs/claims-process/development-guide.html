👨‍💻 Claims Development Guide

Comprehensive guide for developers working on the claims management system

🚀 Getting Started

Prerequisites

  • PHP 8.2+ with Laravel 12 compatibility
  • Node.js 18+ for Vue.js development
  • MySQL 8.0+ database
  • Composer for PHP dependencies
  • NPM/Yarn for frontend dependencies
  • Doppler for environment management

Development Environment

  • Laravel Valet or Docker setup
  • Vite for asset bundling and HMR
  • TailwindCSS for styling
  • Inertia.js for Laravel-Vue integration
  • Vue 3 with Composition API
  • TypeScript support (optional)

Key Commands

  • doppler run -- php artisan serve
  • npm run dev - Start Vite development server
  • doppler run -- php artisan migrate
  • doppler run -- php artisan db:seed
  • npm run build - Production build

Project Structure

  • Backend: app/Http/Controllers, app/Services, app/Models
  • Frontend: resources/js/inertia/Pages/Claims
  • Routes: routes/web.php (claims section)
  • Database: database/migrations, database/seeders
  • Tests: tests/Feature, tests/Unit

🏗️ Architecture Patterns

Laravel Patterns

  • Strict Typing: declare(strict_types=1) in all files
  • Dependency Injection: Constructor injection for services
  • Form Requests: Dedicated validation classes
  • Service Layer: Business logic separation
  • Observer Pattern: Automatic business logic triggers
  • Eloquent ORM: Model relationships and scopes

Vue.js Patterns

  • Composition API: <script setup> syntax
  • Component Structure: Feature-based organization
  • Permission Checks: useCan() composables
  • Event Communication: Parent-child events
  • Form Validation: Client-side validation
  • Error Handling: Toast notifications

Security Patterns

  • Permission Middleware: Route-level protection
  • UUID Routing: Secure route model binding
  • Input Validation: Form Request validation
  • CSRF Protection: Laravel CSRF tokens
  • Audit Logging: Comprehensive change tracking
  • Soft Deletes: Data integrity protection

Performance Patterns

  • Eager Loading: Specific field selection
  • Query Optimization: Eloquent scopes
  • Caching: API response caching
  • Pagination: Client-side pagination
  • Lazy Loading: Component lazy loading
  • Asset Optimization: Vite bundling

📝 Development Workflow

  • Feature Planning: Understand LOB-specific requirements and business rules
  • Database Design: Create migrations with proper relationships and constraints
  • Model Creation: Implement Eloquent models with relationships and scopes
  • Service Layer: Create service classes for business logic
  • Form Requests: Implement validation classes with LOB-specific rules
  • Controller Methods: Create controller methods with proper permissions
  • Routes Definition: Add routes with middleware and naming conventions
  • Frontend Components: Create Vue components with proper structure
  • Testing: Write feature and unit tests
  • Documentation: Update documentation and code comments

    • 🔧 LOB-Specific Development

    Car/Motor Claims

    • Required Fields: plate_number, car_make, car_model, model_year
    • Validation: Interdependent field validation
    • Status Flow: Awaiting Inspection → Repair/Total Loss/Cash Loss
    • Approval Amounts: Three types trigger automatic status updates
    • Observer Logic: Automatic status transitions

    Health Claims

    • Request Types: Reimbursement, Pending Approvals, Ask a Question
    • Service Types: In-patient, Out-patient requests
    • Conditional Validation: Service type required for pending approvals
    • Status Flow: Different flows based on request type
    • Closure States: Paid, Approved, Answered & Closed, Denied

    Life Claims

    • Simplified Flow: Basic claim processing
    • Status Management: Streamlined approval process
    • Closure States: Paid, Denied (simplified logic)
    • Processing: Direct path from registration to settlement
    • Validation: Standard claim validation

    Other LOBs

    • Standard Workflow: All other LOBs follow the same basic claim processing
    • Common Logic: Standard Open → Closed workflow with minimal sub-statuses
    • Includes: Home, Travel, Marine, Pet, Cycle, Business, CorpLine, Group Medical, Savings, and other specialty products
    • Validation: Standard claim validation without LOB-specific fields
    • Processing: Simplified workflow without complex business rules

    ✅ Best Practices

    ✅ Do's
    • Always use strict typing with declare(strict_types=1)
    • Implement comprehensive error handling with try-catch blocks
    • Use Form Request classes for validation
    • Apply permission middleware to all routes
    • Use Eloquent relationships instead of raw queries
    • Implement proper logging with LoggerService
    • Follow Laravel naming conventions
    • Use Vue 3 Composition API patterns
    • Implement proper component communication
    • Write comprehensive tests
    ⚠️ Don'ts
    • Don't bypass permission checks
    • Don't use raw SQL queries without proper validation
    • Don't ignore LOB-specific validation rules
    • Don't skip error handling and logging
    • Don't use inline event handlers in Vue components
    • Don't bypass CSRF protection
    • Don't ignore database constraints
    • Don't skip audit logging for important changes
    • Don't use deprecated Laravel features
    • Don't ignore performance optimization

    Controller Method Example

    public function store(ClaimStoreRequest $request): RedirectResponse { try { $claim = $this->claimsService->createClaim($request->validated()); LoggerService::info('Claim created successfully', [ 'claim_id' => $claim->id, 'user_id' => Auth::id(), 'quote_type_id' => $claim->quote_type_id ]); return redirect()->route('claims.show', $claim->uuid) ->with('success', 'Claim created successfully'); } catch (Exception $e) { LoggerService::error('Failed to create claim', [ 'error' => $e->getMessage(), 'user_id' => Auth::id(), 'request_data' => $request->validated() ]); return back()->withErrors(['error' => 'Failed to create claim']); } }

    Form Request Example

    class ClaimDetailsUpdateRequest extends FormRequest { public function rules(): array { $rules = [ 'claim_number' => 'required|string|max:255', 'incident_date' => 'required|date|before:today', ]; if ($this->quote_type_id == QuoteTypes::CAR->id()) { $rules = array_merge($rules, $this->getCarValidationRules()); } return $rules; } private function getCarValidationRules(): array { return [ 'plate_number' => 'required|regex:/^[A-Za-z0-9\-\s]+$/', 'car_make' => 'required|string|max:255', 'car_model' => 'required|string|max:255', 'model_year' => 'required|integer|min:1900|max:' . (date('Y') + 1), ]; } }

    Observer Example

    public function updating(ClaimRequest $claimRequest): void { $claimService = new ClaimsService; if ($claimRequest->isDirty('claim_number')) { $originalClaimNumber = $claimRequest->getOriginal('claim_number'); $newClaimNumber = $claimRequest->claim_number; if (empty($originalClaimNumber) && !empty($newClaimNumber)) { $claimService->updateClaimSubStatusToClaimRegistered($claimRequest); } } if ($claimRequest->isDirty('claim_sub_status_id')) { $newClaimSubStatusId = $claimRequest->claim_sub_status_id; $shouldCloseTheClaim = $claimService->checkSubStatusForClaimClosure( $claimRequest, $newClaimSubStatusId ); if ($shouldCloseTheClaim) { $claimService->markClaimAsClosed($claimRequest); } } }
