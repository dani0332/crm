🧾 Prepayment Receipt Creation Process

Comprehensive guide to prepayment receipt generation and posting in Sage 300

🎯 Overview

The prepayment receipt creation process handles the generation and posting of prepayment receipts in Sage 300 ERP system for both Accounts Receivable (AR) and Accounts Payable (AP).

💡 Important: Prepayment = Receipt in Sage 300

In Sage 300, a prepayment receipt IS the prepayment record - they are the same thing, not separate concepts.
When we create a "prepayment receipt", we're creating the payment record in Sage 300 that will later be applied to invoices. The term "prepayment" refers to payments made before (or separate from) invoice creation, and "receipt" is simply the Sage 300 document type that records these prepayments.

📋 What is a Prepayment Receipt?

  • Single Concept: Prepayment receipt = payment record
  • AR Prepayment Receipt: Records customer payment before/separate from invoice
  • AP Prepayment Receipt: Records vendor payment before/separate from invoice
  • Purpose: Created first, then applied to invoices later

🔄 Prepayment Receipt Lifecycle

  • Step 1: Create prepayment receipt (OPEN status)
  • Step 2: Ready to Post (validation)
  • Step 3: Post to GL (POSTED status)
  • Later: Apply to invoices (separate process)

🔧 Function Types in This Documentation

  • Sage API Service Methods: Handle actual API calls to Sage 300
  • Payload Factory Methods: Generate API request structures
  • Location: SageApiService.php & SagePayloadFactory.php

🗄️ Database Storage for Prepayment Receipt References

  • payment_splits.sage_reciept_id: Stores AR prepayment receipt document number
  • payment_splits.sage_ap_payment_receipt_id: Stores AP prepayment receipt document number
  • Purpose: Reference to the prepayment receipt (payment record) in Sage 300
  • Note: These store the actual payment record references, not separate receipts

📋 Prepayment Receipt Types in Sage 300

💳

AR Prepayment Receipt

Customer payment record created in AR module BEFORE applying to invoices. The prepayment receipt IS the payment itself - recorded in Sage as a receipt document that goes through Open → Ready to Post → Posted workflow.

🏦

AP Prepayment Receipt

Vendor payment record created in AP module BEFORE applying to invoices. The prepayment receipt IS the payment to the vendor - recorded in Sage as a payment document following the same status workflow.

💼

Commission Prepayment

Commission payment records. Can be AR prepayment receipts (receiving commission) or AP prepayment receipts (paying commission) - both are simply payment records in their respective modules.

🔄

Prepayment Receipt Lifecycle

All prepayment receipts (payment records) follow: Create (Open) → Mark Ready to Post → Post to General Ledger (Posted) → Later applied to invoices

🛠️ Core Receipt Creation Functions

📍 Function Type: These are Sage API Service Methods that orchestrate multiple receipt creation calls.

💳 createARPrepaymentPremiumReceipts() - API Service Method

Main orchestrator function in SageApiService for creating AR prepayment receipts for multiple paid payment splits. 

private function createARPrepaymentPremiumReceipts($sageRequestDataArray, $splitAmount = null)
{
    [$sageRequest, $quote, $payment, $paymentSplits] = $sageRequestDataArray;
    $prepaymentResponses = [];

    // Get all paid payment splits (PAID, PARTIALLY_PAID, CAPTURED)
    $paidPaymentSplits = $payment->paymentSplits()
        ->whereIn('payment_status_id', [PaymentStatusEnum::PAID, PaymentStatusEnum::PARTIALLY_PAID, PaymentStatusEnum::CAPTURED])
        ->get();

    foreach ($paidPaymentSplits as $paymentSplit) {
        // Skip credit approval payments
        $isPaymentMethodCA = in_array($paymentSplit->payment_method, [PaymentMethodsEnum::CreditApproval]);
        if ($isPaymentMethodCA) {
            LoggerService::info('Posting of prepayment skipped due to credit approval');
            $prepaymentResponses[] = ['status' => true, 'message' => 'Skipped due to credit approval'];
            continue;
        }

        // Create individual AR prepayment receipt
        $createPrepaymentReceiptResponse = $this->createARPrepaymentPremiumReceipt($sageRequest, $quote, $payment, $paymentSplit);
        $prepaymentResponses[] = $createPrepaymentReceiptResponse;
    }

    // Check for any failures
    foreach ($prepaymentResponses as $item) {
        if ($item['status'] === false) {
            return ['status' => false, 'message' => $item['message']];
        }
    }

    return ['status' => true, 'message' => 'AR Prepayment Receipts posted on sage.'];
}

🔧 Individual Receipt Creation Methods

📍 Function Type: These are Sage API Service Methods that handle individual receipt creation with API calls.

💳 createARPrepaymentPremiumReceipt() - API Service Method (4 Steps)

Creates individual AR prepayment receipt in SageApiService through complete Open → Ready to Post → Posted lifecycle.

1

Customer Verification

Get Sage customer number using getSageCustomerNumber()

2

Create Receipt (OPEN)

Create AR prepayment receipt batch with createPrepaymentReceiptPayload()

3

Ready to Post

Mark batch ready for posting with readyToPostReceiptArPayment()

4

Post to GL (POSTED)

Post receipt to general ledger with aRPostReceiptsPayment()

public function createARPrepaymentPremiumReceipt($sageRequest, $quote, $payment, $paymentSplit, $splitAmount = null)
{
    // Step 1: Prepare data and get customer number
    $sageRequest = SagePayloadFactory::globalSagePrepaymentReceiptPayloadData([$quote, $payment, $paymentSplit, $sageRequest, $splitAmount]);
    $sageCustomerNumberResponse = $sageApiService->getSageCustomerNumber(...);
    $sageRequest->sage_customer_number = $sageCustomerNumberResponse['sageCustomerNumber'];

    // Step 2: Create AR Prepayment Receipt (OPEN Status)
    $payLoadOptions = SagePayloadFactory::createPrepaymentReceiptPayload($sageRequest);
    $createPremiumPrepaymentResponse = $sageApiService->postToSage300($payLoadOptions['endPoint'], $payLoadOptions['payload']);
    $sageResponse = json_decode($createPremiumPrepaymentResponse, true);

    if (isset($sageResponse['ReceiptsAdjustments'][0]['DocumentNumber'])) {
        // Update payment split with receipt ID
        $documentNumberForReceipt = $sageResponse['ReceiptsAdjustments'][0]['DocumentNumber'];
        $paymentSplit->update(['sage_reciept_id' => $documentNumberForReceipt]);

        // Step 3: Ready to Post (OPEN → READY TO POST)
        $readyToPostReceiptAr = SagePayloadFactory::readyToPostReceiptArPayment($sageResponse['BatchNumber']);
        $readyToPostResponse = $sageApiService->postToSage300($readyToPostReceiptAr['endPoint'], $readyToPostReceiptAr['payload'], 'PATCH');

        // Step 4: Post to General Ledger (READY TO POST → POSTED)
        $aRPostReceipts = SagePayloadFactory::aRPostReceiptsPayment($sageResponse['BatchNumber']);
        $postedResponse = $sageApiService->postToSage300($aRPostReceipts['endPoint'], $aRPostReceipts['payload']);

        return ['status' => true, 'message' => 'Prepayment created'];
    }

    return ['status' => false, 'message' => 'Document number not generated from sage'];
}

Creates individual AP prepayment receipt in SageApiService for vendor payments through complete lifecycle.

Create AP Payment (OPEN)

6

Ready to Post

public function createAPPrepaymentPremiumReceipt($sageRequest, $quote, $payment, $paymentSplit, $splitAmount = null)
{
    // Step 5: Create AP Prepayment Payment (OPEN Status)
    $sageRequest = SagePayloadFactory::globalSagePrepaymentReceiptPayloadData([$quote, $payment, $paymentSplit, $sageRequest, $splitAmount]);
    $payLoadOptions = SagePayloadFactory::createAPPrepaymentReceiptPayload($sageRequest);
    $createAPPremiumPaymentReceipt = $this->postToSage300($payLoadOptions['endPoint'], $payLoadOptions['payload']);
    $sageResponse = json_decode($createAPPremiumPaymentReceipt, true);

    if (isset($sageResponse['PaymentsAdjustments'][0]['DocumentNumber'])) {
        // Update payment split with AP receipt ID
        $documentNumberForReceipt = $sageResponse['PaymentsAdjustments'][0]['DocumentNumber'];
        $paymentSplit->update(['sage_ap_payment_receipt_id' => $documentNumberForReceipt]);

        // Step 6: Ready to Post (OPEN → READY TO POST)
        $readyToPostReceiptAp = SagePayloadFactory::readyToPostAPPaymentReceiptPayload($sageResponse['BatchNumber']);
        $readyToPostResponse = $this->postToSage300($readyToPostReceiptAp['endPoint'], $readyToPostReceiptAp['payload'], 'PATCH');

        // Step 7: Post to General Ledger (READY TO POST → POSTED)
        $aPPostReceipts = SagePayloadFactory::postAPPaymentReceiptPayload($sageResponse['BatchNumber']);
        $postedResponse = $this->postToSage300($aPPostReceipts['endPoint'], $aPPostReceipts['payload']);

        return ['status' => true, 'message' => 'AP Prepayment created'];
    }

    return ['status' => false, 'message' => 'Document number not generated from sage'];
}

🏭 Payload Factory Methods

📍 Function Type: These are Payload Factory Methods that generate Sage 300 API request structures.

🔧 globalSagePrepaymentReceiptPayloadData() - Payload Factory Method

Static method in SagePayloadFactory that prepares and normalizes all data required for receipt creation from quote, payment, and split information. 

public static function globalSagePrepaymentReceiptPayloadData($sageRequestData)
{
    [$quote, $payment, $paymentSplit, $sageRequest, $splitAmount] = $sageRequestData;

    // Set collection amount from payment split
    $sageRequest->collection_amount = $paymentSplit->collection_amount;
    if ($splitAmount != null) {
        $sageRequest->collection_amount = $splitAmount;
    }

    // Get insurance provider details
    $insuranceProvider = getInsuranceProvider($payment, $sageRequest->quoteType, $quote);
    $sageRequest->sageVenderId = $insuranceProvider?->sage_vendor_id;
    $sageRequest->insurerName = $insuranceProvider?->text;
    $sageRequest->insurerCode = $insuranceProvider?->code;

    // Set payment method details
    $sageRequest->sage_payment_code = $paymentSplit->payment_method;
    $sageRequest->checkNumber = $paymentSplit->check_detail;

    // Set advisor and customer information
    $sageRequest->advisor_id = $quote->advisor_id;
    $sageRequest->customer_id = $quote->customer_id;

    return $sageRequest;
}

💳 createPrepaymentReceiptPayload() - Payload Factory Method

Static method in SagePayloadFactory that creates the Sage 300 AR prepayment receipt payload structure. 

public static function createPrepaymentReceiptPayload($sageRequest, $isCommissionReceipt = false)
{
    $optionalFields = self::createPrepaymentOptionalFields($sageRequest);
    $customerNumber = $sageRequest->sage_customer_number;
    $bankCode = SageEnum::BANK_CODE_INS;
    $paymentCode = SageEnum::PAYMENT_CODE_IP;
    $bankReceiptAmount = roundNumber(floatval($sageRequest->collection_amount));

    $payLoad = [
        'BatchRecordType' => 'CA',  // AR Receipt Batch
        'BankCode' => $bankCode,
        'ReceiptsAdjustments' => [
            [
                'BatchType' => 'CA',
                'CustomerNumber' => $customerNumber,
                'BankCode' => $bankCode,
                'BankReceiptAmount' => $bankReceiptAmount,
                'PaymentCode' => $paymentCode,
                'ReceiptTransactionType' => 'Prepayment',  // Key: Prepayment type
                'AppliedReceiptsAdjustments' => [
                    [
                        'BatchType' => 'CA',
                        'CustomerNumber' => $customerNumber,
                        'ReceiptTransactionType' => 'Prepayment',
                    ],
                ],
                'ReceiptAdjustmentOptionalField' => $optionalFields,
            ],
        ],
    ];

    return [
        'endPoint' => 'AR/ARReceiptAndAdjustmentBatches',
        'payload' => $payLoad,
        'sage_request_type' => SageEnum::SRT_CREATE_PP_REC,
        'entry_type' => SageEnum::SCT_STRAIGHT,
    ];
}

🏦 createAPPrepaymentReceiptPayload() - Payload Factory Method

Static method in SagePayloadFactory that creates the Sage 300 AP prepayment payment payload structure for vendor payments. 

public static function createAPPrepaymentReceiptPayload($sageRequest)
{

    $payLoad = [

                'EntryDescription' => $entryDescription,
                'PaymentTransactionType' => 'Prepayment',  // Key: Prepayment type
                'BankCode' => $bankCode,
                'TotalPrepayVendorCurrency' => $bankReceiptAmount,
                'AppliedPayments' => [
                    [
                        'BatchType' => 'PY',
                        'VendorNumber' => $vendorNumber,
                        'TransactionType' => 'PrepaymentPosted',
                    ],
                ],
                'PaymentAdjustmentOptionalField' => $optionalFields,
            ],
        ],

        'endPoint' => 'AP/APPaymentAndAdjustmentBatches',

🔧 Receipt Processing Logic

📋 Payment Split Processing

Both AR and AP receipt creation functions process payment splits based on their payment status, focusing only on splits that have been successfully paid or captured.

✅ Processed Payment Splits

  • PAID: Payment completed successfully
  • PARTIALLY_PAID: Partial payment received
  • CAPTURED: Payment captured by gateway
  • Valid Amount: collection_amount > 0

⏭️ Skipped Payment Splits

  • Credit Approval: PaymentMethodsEnum::CreditApproval
  • Pending Status: Not yet paid or captured
  • Zero Amount: No collection amount
  • Failed Payments: Payment processing failed

🔄 NRA Use Case - Non-Regular Approval Receipt Creation

📍 Special Scenario: Creating prepayment receipts when payment is approved AFTER policy/send update has already been booked on Sage.

💡 What is NRA (Non-Regular Approval)?

NRA handles the scenario where a payment split is approved AFTER the policy has already been booked on Sage.
In the normal flow, prepayment receipts are created during policy booking. However, in NRA cases, the payment approval happens later (e.g., delayed bank confirmation, manual verification), requiring separate prepayment receipt creation.

🎯 NRA Trigger Conditions

✅ When NRA Receipt Creation Occurs

  • Payment Approved: $request->is_approved is true
  • Not Already Paid: $splitPayment->payment_status_id != PAID
  • Sage Enabled: isSageEnabled() returns true
  • Post-Booking Approval: shouldCreateAndSchedulePostPrepayment() returns true
  • Not Health AUH: !$isHealthAUH (Health Abu Dhabi excluded)

🚫 When NRA Receipt Creation is Skipped

  • Already Paid: Split payment already has PAID status
  • Sage Disabled: Sage integration is disabled
  • Regular Booking: Payment approved during normal booking flow
  • Health AUH: Health Abu Dhabi quote type
  • Payment Declined: Payment is being declined instead of approved

🔧 NRA Implementation in PaymentRepository

The NRA use case is implemented in the fetchSplitPaymentApproveDecline() method in PaymentRepository. 

public function fetchSplitPaymentApproveDecline($request)
{
    LoggerService::startFeatureLogging(LoggerFeatureEnum::APPROVE_DECLINE_CHILD_PAYMENT);

    // Fetch payment split and related data
    $splitPayment = PaymentSplits::find($request->splitPaymentId);
    $masterPayment = $splitPayment->payment;
    $quote = $masterPayment?->paymentable;

    $isHealthAUH = $this->isHealthAUHLead(ucfirst($request->modelType), $quote);

    /* Handle NRA case where payment is approved after policy/send update is booked */
    $shouldCreatePrepaymentPremiumReceipt = (new SageApiService)->shouldCreateAndSchedulePostPrepayment($quote, $splitPayment);
    info(self::class.' fn:'.__FUNCTION__.' Child payment code: '.$splitPayment->code.' with serial no: '.$splitPayment->sr_no
        .' trigger creation of Premium Sage receipt: ',
        ['$shouldCreatePrepaymentPremiumReceipt' => $shouldCreatePrepaymentPremiumReceipt]
    );

    // Process Sage API call outside transaction if needed
    if ($request->is_approved
        && $splitPayment->payment_status_id != PaymentStatusEnum::PAID
        && (new SageApiService)->isSageEnabled()
        && $shouldCreatePrepaymentPremiumReceipt
        && !$isHealthAUH
    ) {
        // Build Sage request for NRA receipt creation
        $sageRequest = $request->safe();
        $sageRequest->userId = auth()->id();
        $sageRequest->quoteType = $request->modelType;
        $sageRequest->quoteTypeId = QuoteTypes::getIdFromValue($request->modelType);
        $sageRequest->advisor_id = $quote->advisor_id;
        $sageRequest->collection_amount = $request->collection_amount;
        $sageRequest->insurerReceiptNumber = $request->insurer_receipt_number;

        /* Handle NRA case where payment is approved after policy/send update is booked */
        $sageARPrepaymentResponse = (new SageApiService)->createARPrepaymentPremiumReceipt(
            $sageRequest,
            $quote,
            $masterPayment,
            $splitPayment,
            $request->collection_amount
        );

        if (!$sageARPrepaymentResponse['status']) {
            vAbort($sageARPrepaymentResponse['message']);
        }

        /* AP Prepayment creation is currently commented out
        $sageRequest->sage_customer_number = $sageARPrepaymentResponse['sageCustomerNumber'];

        $sageAPPrepaymentResponse = (new SageApiService)->createAPPrepaymentPremiumReceipt(
            $sageRequest, $quote, $masterPayment, $splitPayment, $request->collection_amount
        );

        if (!$sageAPPrepaymentResponse['status']) {
            vAbort($sageAPPrepaymentResponse['message']);
        }
        */
    }

    // Continue with database transaction for payment approval/decline
    return $this->handleWithDeadlockRetries(function () use ($request, $splitPayment, $masterPayment) {
        // Update payment split status, collection amount, etc.
        // ... (transaction logic continues)
    }, $maxRetries);
}

📋 NRA Receipt Creation Flow

1

Policy Already Booked

Policy/send update has been booked on Sage without this payment split

2

Payment Approval Request

User approves payment split via fetchSplitPaymentApproveDecline()

3

NRA Validation Check

System validates if NRA receipt creation is needed

4

Create AR Prepayment Receipt

Calls createARPrepaymentPremiumReceipt() outside transaction

5

Update Payment Status

Complete approval in database transaction

🔍 Key NRA Methods

shouldCreateAndSchedulePostPrepayment()

  • Location: SageApiService
  • Purpose: Determines if NRA receipt creation is needed
  • Checks: Quote booking status, payment split status, Sage process status
  • Returns: Boolean indicating if post-booking receipt should be created

createARPrepaymentPremiumReceipt()

  • Location: SageApiService
  • Called For: Both regular booking AND NRA scenarios
  • Parameters: sageRequest, quote, masterPayment, splitPayment, collectionAmount
  • Result: Creates AR prepayment receipt in Sage 300

⚠️ Important NRA Considerations

Transaction Isolation: NRA receipt creation happens OUTSIDE the database transaction to prevent long-running Sage API calls from blocking database operations.

AP Receipt Commented: AP prepayment receipt creation is currently commented out in NRA flow (same as regular flow).

Error Handling: If AR receipt creation fails, the entire approval process is aborted with vAbort().

Audit Trail: NRA receipt creation is logged with specific feature flag (APPROVE_DECLINE_CHILD_PAYMENT).

📊 NRA vs Regular Receipt Creation

Aspect Regular Receipt Creation NRA Receipt Creation
Timing During policy booking (BookPolicyOnSageJob) After policy booking (Payment approval)
Trigger postBookPolicyToSage() workflow fetchSplitPaymentApproveDecline() approval
All Splits Creates receipts for all paid splits at once Creates receipt for single approved split
Transaction Part of booking workflow transaction Outside payment approval transaction
Use Case Normal payment flow - pay then book Delayed approval - book then pay later
Method Called createARPrepaymentPremiumReceipts() (plural) createARPrepaymentPremiumReceipt() (singular)
