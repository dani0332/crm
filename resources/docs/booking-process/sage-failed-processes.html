🔍 Sage Failed Processes Management

Monitor, troubleshoot, and resolve failed Sage 300 integration processes

⚠️ Issue Management

❓ What Are Sage Failed Processes?

Sage Failed Processes are policy bookings or endorsements that encountered errors during integration with Sage 300 ERP system. These failures can occur at various stages of the booking workflow including customer creation, receipt generation, invoice posting, or payment application.

💡 Why Monitor Failed Processes?

Critical for Financial Accuracy: Failed Sage processes mean the policy is sold but not properly recorded in the accounting system, causing:

✓ Missing revenue records in financial reports
✓ Untracked commission payments to sales teams
✓ Incomplete accounts receivable and payable records
✓ Potential compliance and audit issues

Database Query Architecture

// Base Query Construction SageProcess::select('id', 'model_type', 'model_id', 'insurance_provider_id', 'request', 'status', 'created_at', 'updated_at') ->where('status', SageEnum::SAGE_PROCESS_FAILED_STATUS) ->whereNotIn('model_type', [PaymentSplits::class, EmbeddedTransaction::class]) ->orderBy('id', 'desc') // Eager Loading (prevents N+1 queries) ->with([ 'model' => function ($query) { $query->with([ 'sageApiLogs' => fn ($q) => $q->where('status', SageEnum::STATUS_FAIL) ->select('id', 'section_type', 'section_id', 'sage_end_point', 'response', 'status', 'created_at') ->orderBy('created_at', 'asc') ->limit(1), // Only fetch FIRST failed log 'payments' => fn ($q) => $q->select(/* payment columns */) ->with(['paymentSplits', 'paymentStatus']), ]); }, 'insuranceProvider:id,text', ]) // Model Validation (ensures quote has failed status) ->whereHas('model', function ($q) { $q->whereHas('sageApiLogs', fn ($subQuery) => $subQuery->where('status', SageEnum::STATUS_FAIL) ); // Check for POLICY_BOOKING_FAILED status if (Schema::hasColumn($modelInstance->getTable(), 'quote_status_id')) { $q->where('quote_status_id', QuoteStatusEnum::POLICY_BOOKING_FAILED); } elseif (Schema::hasColumn($modelInstance->getTable(), 'status')) { $q->where('status', SendUpdateLogStatusEnum::UPDATE_BOOKING_FAILED); } });

🔍 Filter Implementation Details

1. Insurance Provider Filter

// Multi-select filter (array of IDs) $query->when( $request->insurance_provider_id && is_array($request->insurance_provider_id) && count($request->insurance_provider_id) > 0, fn ($q) => $q->whereIn('insurance_provider_id', $request->insurance_provider_id) );

2. Quote Type Filter (Complex Logic)

// Handles both direct models and personal quotes $query->when($request->quote_type_id, function ($q) use ($request) { [$directModelClasses, $personalQuoteTypeIds] = $this->getDirectModelClassesAndPersonalQuoteTypeIds($request); $q->where(function ($subQuery) use ($directModelClasses, $personalQuoteTypeIds) { // Direct models (e.g., HealthQuote, TravelQuote) if (!empty($directModelClasses)) { $subQuery->whereIn('model_type', $directModelClasses); } // Personal quotes (Car, Bike via PersonalQuote model) if (!empty($personalQuoteTypeIds)) { $subQuery->orWhere(function ($personalQuery) use ($personalQuoteTypeIds) { $personalQuery->where('model_type', PersonalQuote::class) ->whereExists(function ($existsQuery) use ($personalQuoteTypeIds) { $existsQuery->select(DB::raw(1)) ->from('personal_quotes') ->whereColumn('personal_quotes.id', 'sage_processes.model_id') ->whereIn('personal_quotes.quote_type_id', $personalQuoteTypeIds); }); }); } }); });

3. Option Filter (Main Lead vs Send Update)

// Simple model type discrimination $query->when($request->option, function ($q) use ($request) { if ($request->option === self::OPTION_SEND_UPDATE) { // Only Send Updates $q->where('model_type', $this->sendUpdateModelClass); } elseif ($request->option === self::OPTION_MAIN_LEAD) { // Exclude Send Updates (all other models) $q->where('model_type', '!=', $this->sendUpdateModelClass); } });

4. Date Range Filter

// Inclusive date range on created_at $query->when( $request->date_from, fn ($q) => $q->where('created_at', '>=', Carbon::parse($request->date_from)->startOfDay() ) )->when( $request->date_to, fn ($q) => $q->where('created_at', '<=', Carbon::parse($request->date_to)->endOfDay() ) );

🎨 Data Enrichment Process

After fetching base data, the service enriches results with additional computed information.

1. Collected Sage Receipt IDs

📋 Receipt ID Aggregation

Purpose: Collect all sage_reciept_id values from payment_splits
Method: Flatten payment.paymentSplits and extract IDs
Format: Comma-separated string (e.g., "R001, R002, R003")
Storage: Added as virtual attribute to each process item

// Optimized collection-based aggregation foreach ($items as $item) { $sageReceiptIds = []; if ($item->model && $item->model->payments) { $sageReceiptIds = $item->model->payments ->pluck('paymentSplits') ->flatten() ->pluck('sage_reciept_id') ->filter() ->values() ->toArray(); } $item->collected_sage_receipt_ids = !empty($sageReceiptIds) ? implode(', ', $sageReceiptIds) : null; $item->collected_sage_receipt_ids_array = $sageReceiptIds; }

2. IMCRM Error Extraction

🔧 Error Message Parsing

Purpose: Extract user-friendly error from Sage API response
Source: sage_api_logs.response (JSON)
Path: error.message.value
Handling: Supports double-encoded JSON strings

// Safe error extraction with fallbacks $firstFailedLog = $item->model?->sageApiLogs?->first(); if ($firstFailedLog?->response) { try { $responseData = $this->decodeJsonResponse($firstFailedLog->response); // Safely extract nested error message $item->imcrm_error = !empty($responseData['error']['message']['value']) ? $responseData['error']['message']['value'] : null; } catch (\Exception $e) { LoggerService::warning('Could not parse sage API response', [ 'sage_api_log_id' => $firstFailedLog->id ?? null, ]); $item->imcrm_error = null; } } // Double-encoded JSON handling protected function decodeJsonResponse(string $jsonString): ?array { $decoded = json_decode($jsonString, true); // Check if double-encoded and decode again if (is_string($decoded)) { $decoded = json_decode($decoded, true); } return is_array($decoded) ? $decoded : null; }

3. Eager Loading Relationships

📊 Quote Status Loading

  • Groups models by type (class name)
  • Checks schema for quote_status_id column
  • Batch loads quoteStatus in single query per type
  • Prevents N+1 query problem

📝 Personal Quote Loading

  • Groups models by type
  • Checks for personal_quote_id column
  • Loads personalQuote with uuid, code, policy_number
  • Efficient batch loading strategy

⚠️ Common Failure Scenarios

❌ Customer Creation Failed

  • Error: Customer already exists with different details
  • Sage API: AR/ARCustomers
  • Resolution: Update customer info in Sage or map to existing

❌ Receipt Creation Failed

  • Error: Duplicate receipt ID or invalid GL account
  • Sage API: AR/ARReceiptAndAdjustmentBatches
  • Resolution: Check sage_reciept_id uniqueness and GL codes

❌ Invoice Posting Failed

  • Error: Invalid invoice number sequence or tax config
  • Sage API: AR/ARInvoices or AP/APInvoices
  • Resolution: Verify invoice numbering and tax setup

❌ Payment Application Failed

  • Error: Receipt already applied or amount mismatch
  • Sage API: AR/ARApplyReceiptsToInvoices
  • Resolution: Check receipt status and invoice balance

❌ Connection Timeout

  • Error: Sage 300 API not responding
  • Sage API: Any endpoint
  • Resolution: Check Sage server status and network connectivity

❌ Missing Required Fields

  • Error: Required Sage IDs not found
  • Check: customerId, sageVenderId, insurerGlLiaiblityAccount
  • Resolution: Complete Sage configuration for provider

⚡ Performance Optimizations

  • Read from replica database (SetReadDbConnection middleware)
  • Eager loading prevents N+1 queries
  • Batch relationship loading by model type
  • Limited to first failed API log only

🧮 Collection Methods

  • Use Laravel collections instead of loops
  • Flatten and filter in single pass
  • Pluck specific columns to reduce memory
  • Filter null values efficiently

📄 Pagination

  • Simple pagination (10 items per page)
  • Reduces memory footprint
  • Faster page load times
  • Filter params appended to pagination URLs

📤 Export Handling

  • ModernCsvExportable trait for large datasets
  • Chunked export processing
  • Streaming response to avoid memory issues
  • Empty data check before export
