# Lead Form Module

## Overview

The Lead Form module handles customer information capture for Cyber Insurance quotes. It provides a user-friendly interface for entering customer details and validates the data before submission.

## Purpose

The lead form is the entry point for creating new Cyber Insurance quotes. It captures essential customer information required to generate quotes and assign advisors.

## Key Features

- **Customer Information Capture**: First name, last name, email, mobile number
- **Personal Details**: Date of birth, nationality, emirate of registration
- **Client-side Validation**: Real-time validation using Vue.js rules
- **Server-side Validation**: Laravel Form Request validation
- **Edit Mode**: Ability to update existing quotes (blocked when status = Policy Booked)
- **Lookup Data**: Dynamic dropdowns for nationalities and emirates
- **Lead Prefix**: Leads created with prefix `CYB-xxxxxx`
- **Immutable Fields**: Email and mobile number cannot be changed after creation
- **All Fields Mandatory**: All form fields are required

## Form Fields

The form includes the following fields (all mandatory):

1. **First Name** (required, max 20 characters, letters/spaces/hyphens only)
2. **Last Name** (required, max 50 characters, letters/spaces/hyphens only)
3. **Email** (required, email format, immutable after creation)
4. **Mobile Number** (required, immutable after creation)
5. **Date of Birth** (required, date format)
6. **Nationality** (required, dropdown from database with country name and code mapping)
7. **Emirate of Registration** (required, dropdown with all emirates: Dubai, Ras al Khaimah, etc.)

**Note**:

- All fields are mandatory
- Email and mobile are disabled in edit mode (immutable)
- Nationality stores both country name and mapped country code

For detailed field definitions and validation rules, see [Form Fields](./form-fields.md).

## Form Flow

### Create Mode

1. User navigates to "Create Cyber Quote"
2. Empty form displayed with lookup data (nationalities, emirates)
3. User fills in customer details
4. Client-side validation on blur/change
5. Form submission triggers server-side validation
6. If valid, quote created and advisor assigned
7. Redirect to quote show page

### Edit Mode

1. User navigates to existing quote
2. Form pre-filled with existing data
3. Email and mobile disabled (immutable fields)
4. **Edit Restriction**: If lead status = "Policy Booked", editing is blocked
5. User updates allowed fields
6. Form submission triggers validation
7. Quote updated directly in database (not via external API)
8. Redirect to quote show page

For detailed submission flow, see [Submission Flow](./submission-flow.md).

## Validation

### Client-side Validation

- Uses Vue.js composable `useRules()`
- Rules: `isRequired`, `isEmail`, `isMobileNo`, `isValidName`
- Real-time feedback on field blur/change

### Server-side Validation

- Laravel Form Request validation
- Custom validation messages
- Database existence checks for foreign keys

## API Endpoints

- **GET** `/personal-quotes/cyber/create` - Show create form (route name: `cyber-quotes-create`)
- **POST** `/personal-quotes/cyber` - Store new quote (route name: `cyber-quotes-store`)
- **GET** `/personal-quotes/cyber/{uuid}/edit` - Show edit form (route name: `cyber-quotes-edit`)
- **PUT** `/personal-quotes/cyber/{uuid}` - Update existing quote (route name: `cyber-quotes-update`)

For detailed API documentation, see [API Endpoints](./api-endpoints.md).

## Lead Reference Format

**Format**: `CYB-xxxxxx`

**Prefix**: `CYB-` (from quote type `short_code`)

**Generation**: Automatically generated by external Capi API when lead is created

**Location**: `app/Enums/QuoteTypes.php:230`

**Example**: `CYB-123456`

## Edit Restrictions

### Policy Booked Status

**Requirement**: Once lead status = "Policy Booked", editing is blocked

**Implementation**:

- Edit button disabled
- Form fields disabled
- Same behavior as other LOBs (Car, Health, etc.)

**Location**: Frontend validation and backend checks

### Immutable Fields

**After Creation**:

- Email (disabled in edit mode)
- Mobile Number (disabled in edit mode)

**Reason**: Prevent data inconsistency and maintain data integrity
